# Hypothesis

참가자 #1에서 확인된 두 개의 차단(보리 탭 미발견, 문지르기 미발견)과 한 개의 공백(첫 하트 뒤 사건 없음)이, **UX 구조 변경 없이 발견성 보조와 생활 사건 연결만으로 해소되는지** 확인한다.

| # | 가설 | 검증 방법 |
|---|---|---|
| **H-A** | 자율 이동을 한 번 보여준 뒤 1회성 탭 힌트를 주면, 진행자 도움 없이 보리를 탭한다 | 힌트 전/후/rescue 구분 기록 |
| **H-B** | 확대 상태에서 대상과 동작을 명시한 1회성 안내를 주면, 진행자 도움 없이 실제 rub이 나온다 | 첫 입력 종류와 첫 하트까지의 시도 횟수 |
| **H-C** | 첫 하트 뒤 "요구 없음"을 유지하면서도 자율 생활 사건을 연결하면, 참가자는 공백이 아니라 **계속되는 생활**로 인식한다 | 조용한 구간 중 발화·행동, 종료 후 비유도 질문 |
| **H-D** | 목적지 이동·가변 체류·휴식이라는 최소 행동 문법만으로 보리를 "움직이는 물체"가 아니라 "생활하는 존재"로 이해한다 | 행동의 목적을 설명하는 자발적 발화 |

**중요:** 참가자 #1의 "공백" 경험은 `첫 하트 뒤 요구하지 않는다` 원칙에 대한 반증이 **아니다.** 확인 결과 참가자 주 경로에는 자동 생활 사건이 하나도 연결돼 있지 않았고, 모든 사건이 진행자 패널 뒤에 있었다. 즉 그 원칙은 **아직 한 번도 테스트되지 않았다.** 참가자 #2가 이 원칙의 첫 실측이다.

# Changes made for participant #2

## 1. 탭 발견성 — 기존 힌트의 트리거 수정

새 힌트 종류를 추가한 것이 **아니다.** `UX_FINAL.md` §8이 이미 허용한 세 번째 안내("가장 가까운 유효 상호작용 하나를 1회")의 **발동 조건만** 고쳤다.

| | 이전 | 참가자 #2 |
|---|---|---|
| 트리거 | 빈 영역 **2회 연속 탭** | **자율 이동 1회 완료 + 도착** 후에도 미탭이면 노출 |
| 보조 트리거 | — | 빈 영역 **1회** 탭 시 앞당겨 노출 |
| 지속 | 4초 후 자동 제거 | **보리를 탭할 때까지 유지** |
| 문구 | `보리를 눌러 보세요` | 동일 |

기존 트리거는 **아무것도 누르지 않는 참가자를 구조적으로 구제할 수 없었다.** 참가자 #1이 정확히 그 경우였다. 관찰만 하는 사람은 영원히 조건을 만들지 못한다.

- 보리를 버튼처럼 꾸미지 않았다. 영구 라벨도 없다.
- 부위 강조·히트 영역 노출 없음.
- 탭만 가르치고 문지르기는 언급하지 않는다.

## 2. 문지르기 발견성 — 문구 교체 + 표시 위치 분리

문구를 `손가락으로 문질러 보세요` → **`손가락으로 천천히 쓰다듬어 보세요`** 로 교체했다.

**더 중요한 수정은 위치다.** 이전에는 안내가 반응 문구와 같은 요소를 썼기 때문에, 참가자가 한 번 탭하는 순간 `눈을 깜박였어요`가 안내를 덮어썼다. **문지르기를 배우기도 전에 단서가 사라지는 구조**였다. 이제 안내는 별도 요소(`#zHint`)이며 탭 반응이 지우지 못하고, **실제 유효한 rub이 인식될 때만** 사라진다.

- 첫 확대에만 1회. 두 번째 확대부터는 없다.
- 모달 아님. 입력을 막지 않는다.
- 부위 이름·선택 버튼·하트 예고 없음.

## 3. 최소 자율 생활 루프

기존 유휴 이동은 3초마다 ±14px 흔들기였다. 목적지도 멈춤도 없는 진동이라 참가자 #1이 "움직이는 그림"으로 읽은 것은 당연하다.

새 루프는 상태 몇 개뿐이며 NPC 엔진이 아니다.

```
목적지 선택 → 이동(거리에 비례한 시간) → 도착 → 가변 체류 → 다시 선택
```

| 파라미터 | 값 | 의미 |
|---|---|---|
| 목적지 | 방 전역 **5곳** | 직전 목적지는 다시 고르지 않음 (두 점 왕복 방지) |
| 체류 | **2.6~5.2초 가변** | 일정 주기 = 기계적으로 읽힘 |
| 이동 시간 | 거리 비례 **0.7~1.6초** | 순간이동이 아니라 '건너감'으로 읽히게 |
| 휴식 | **9초** + 자세 변화 | 위치·자세·지속시간 세 가지로 표현 |

물리·충돌·pathfinding·보행 애니메이션·리깅은 없다. 캐릭터 그림도 그대로다 — **행동 구조만 바꿔야 시각 품질과 효과가 섞이지 않는다.**

## 4. 첫 하트 뒤 리듬

```
하트 → (조용한 자율 행동 1회, 아무 제안 없음) → 식사 맥락 + 밥그릇 제안 → 자율 이동 2회 → 휴식
```

- 하트 직후 질문·배치 요청·팝업 **없음**
- 식사 제안을 **무시해도** 생활은 계속되고 재촉하지 않는다
- 휴식은 **잠자리 배치를 요구하지 않는다** — "오브젝트가 없어도 결핍 없음"을 함께 확인
- 하트에 도달하지 못한 참가자도 **75초 뒤 생활 사건이 진행된다.** 그러지 않으면 참가자 #1의 공백이 그대로 재현된다

# What intentionally remains unchanged

- **쓰다듬기 판정 로직 전체.** 실제 좌표 이동 ≥ 26px만이 쓰다듬기다. 짧은 탭·반복 탭·이동 없는 길게 누르기는 하트를 만들지 않는다. 부위는 제스처가 처음 닿은 곳으로 고정된다
- 선호 부위에만 하트, 비선호는 중립 수용(패널티 없음)
- 확대 종료는 명시적 닫기
- 말풍선 비상호작용, 빈 영역 탭은 세계를 바꾸지 않음
- 캐릭터 표현·화면 스타일·회색조
- 온보딩 전 구간(로그인 → 기본 정보 → 사진 → Q1 → 생성 → 후보 → 보정 → 공간 → 이동 영역 → 첫 만남)
- QA 진입(`?qa=petting`, `?qa=candidates`)과 진행자 패널
- **`UX_FINAL.md`, `USER_FLOW.md`** — 손대지 않았다

## 이번에 넣지 않은 것

배변 → 청소 → Q5 / Q2 활동량 / 놀이·장난감 / 잠자리 배치 과제 / 추가 오브젝트 / 알림 / 경제 / 장기 시뮬레이션.

**Q2를 뺀 이유가 특히 중요하다.** Q2는 답변에 따라 이동 폭을 바꾸므로, 함께 넣으면 참가자가 느낀 생활감이 **기본 행동 개선 때문인지 자기 답변 때문인지 구분할 수 없다.** H-D가 측정 불가능해진다.

기존 경로는 그대로 남아 있고 진행자 패널로 접근 가능하다. 참가자 #2 주 경로에서만 빠진다.

# What the facilitator must NOT explain

절대 먼저 말하지 않는다.

- "보리를 눌러 보세요"
- "손가락으로 문질러 보세요" / "쓰다듬어 보세요"
- "밥그릇을 눌러 보세요"
- "지금 뭔가 해 보세요" / "화면을 만져 보세요"
- 하트가 나오는 부위, 탭과 문지르기의 차이, 다음에 무슨 일이 일어나는지

**침묵을 견딜 것.** 조용한 구간은 버그가 아니라 측정 대상이다(H-C).

참가자가 직접 도움을 요청하거나 진행이 완전히 멈춘 경우에만, **먼저 실패 시각과 그때 화면에 떠 있던 힌트를 기록한 뒤** 최소 안내를 한다. 그 이후 행동은 `자발적 발견`이 아니라 **`rescue 후 진행`** 으로 분리 기록한다.

식사 제안을 무시하거나 휴식을 관찰만 해도 재촉하지 않는다.

# What to observe

## Home 진입 ~ 첫 탭
- Home 진입 시각 / 첫 자율 이동을 봤다고 판단되는 행동·발화
- **탭 힌트 노출 시각** 과 그때까지 참가자가 한 행동
- 탭 시점: `힌트 전 자발적` / `힌트 후 자발적` / `rescue 후`
- 보리 탭 전 빈 공간 탭 횟수

## 확대 ~ 첫 하트
- 확대 직후 첫 입력: 탭 / 정지 hold / rub / 닫기
- 안내 노출부터 첫 실제 rub까지의 시간
- 몸 위에서 손가락을 **이동**시켰는가
- 첫 하트까지의 시도 횟수, rescue 여부
- 탭과 rub을 서로 다른 동작으로 이해한 정황

## 첫 하트 직후 (H-C 핵심 구간)
- 하트 직후 행동: 관찰 / 추가 쓰다듬기 / 닫기 / 다른 곳 탭 / 이탈
- **조용한 구간을 편안해하는가, 다음 행동을 찾는가**
- `끝난 건가요?` 류 발화 유무와 시각
- 보리의 다음 이동을 알아챈 행동·발화

## 식사·휴식
- 제안 문구 **전에** 식사 맥락을 알아챘는가
- 밥그릇 배치 / 무시 중 무엇을 선택했는가
- 배치했다면 다시 탭해 급식 반응까지 발견했는가
- 무시했을 때 생활이 계속되는 것을 알아챘는가
- 휴식을 `아무것도 안 함`이 아니라 **`쉬고 있음`** 으로 설명하는가

## 종료 후 비유도 질문
- "보리가 이 공간에서 무엇을 하고 있었다고 느꼈나요?"
- "앱을 더 켜 두면 어떤 일이 일어날 것 같나요?"
- "보리에게 어떤 행동을 할 수 있다고 생각했나요?"
- "어느 순간에 다음에 뭘 해야 할지 모르겠다고 느꼈나요?"
- "보리가 스스로 생활한다고 느낀 순간이 있었다면 언제였나요?"

`살아 있는 것 같았나요?`처럼 원하는 답이 들어 있는 질문은 금지.

# Success signals

- **H-A** 진행자 도움 없이 보리를 탭한다 (힌트 전이든 후든)
- **H-B** 진행자 설명 없이 실제 rub이 나오고 첫 하트에 도달한다
- **H-C** 조용한 구간에서 불안·이탈 없이 기다리고, 이어지는 사건을 스스로 알아챈다
- **H-D** 행동의 **목적**을 자발적으로 말한다 — "어디론가 갔다", "멈춰서 쉬네요", "그릇 보고 다가갔어요"
- 식사 제안을 기회로 읽는다. 의무·죄책감 발화가 없다
- 종료 질문에서 "계속 뭔가 하고 있을 것 같다"는 기대가 나온다

---

# Failure signals

- 힌트가 떴는데도 탭하지 못한다 → 문구가 아니라 **위치·시인성** 문제. 다음 참가자에서 표시 방식을 바꾼다
- 안내를 읽고도 탭만 반복한다 → 텍스트 한계. **제스처 시연** 을 다음 조건으로 검토
- 조용한 구간에서 `끝났나요?` / 이탈 → H-C 반증 가능성. 다만 **한 명으로 원칙을 폐기하지 않는다**
- 여전히 "조금씩 움직이는 그림"이라고 말한다 → 행동 문법이 아니라 **활동 밀도 또는 Home loop 가설** 을 다시 본다
- 식사 제안을 지시·과제로 받아들인다 → 제안 표현과 타이밍 재검토
- 죄책감·방치·의무 관련 자발적 발화 → **즉시 실패 신호로 기록** (제품 철학 위반)

# Decisions intentionally deferred

한 명(또는 두 명)의 결과로 확정하지 않는다.

- 탭 힌트의 최종 타이밍·문구·표시 방식, 영구 채택 여부
- 빈 공간 탭 보조 트리거의 존치
- rub 안내에 제스처 시연·애니메이션이 필요한지
- 첫 세션에서 생활 사건을 **보장** 할지, 그 간격
- 첫 세션에 식사 외 어떤 사건을 넣을지
- Q2·Q5·놀이의 첫 세션 포함 여부와 최종 타이밍
- 목적지 수·이동 거리·체류 시간·휴식 길이 등 **모든 행동 파라미터** (전부 Low-fi 임시값)
- 첫 세션과 재방문 세션의 pacing 차이
- 참가자 #1의 공백이 Home loop 자체 문제인지 사건 미연결 문제인지에 대한 최종 판정
- **`UX_FINAL.md` / `USER_FLOW.md` 반영 여부** — 반복 관찰된 문제만 승격 후보로 올린다

# 방법론 주의 — 이 실험이 스스로 만드는 편향

1. **탭 힌트가 자발적 발견을 가릴 수 있다.** 힌트가 뜨기 전 구간이 유일한 자발적 발견 측정 창이다. 힌트 전/후 구분 기록이 없으면 H-A는 측정되지 않는다.
2. **참가자 #1과 A/B 비교가 아니다.** 조건이 여러 개 동시에 바뀌었다(힌트 트리거, 안내 문구·위치, 이동 구조, 사건 연결). 어느 변경이 효과를 냈는지는 이 한 세션으로 분리되지 않는다.
3. **첫 세션 사건 간격은 압축돼 있다.** 실제 제품 리듬이 아니라 짧은 테스트 안에서 loop를 관찰하기 위한 조건이다. 참가자에게 이 속도가 제품 사양인 것처럼 설명하지 않는다.
