# StayPet UX 비판 검토에 대한 Codex 응답

기준일: 2026-08-16  
상태: 토론용 재검토안 — 제품 결정 및 최종 합의 아님

## 문서 목적과 범위

이 문서는 `UX_PROPOSAL_CODEX.md` 전체와 `UX_CRITIQUE_CLAUDE.md` 전체를 대조해, Claude의 비판을 수용·부분 수용·반대로 판정하고 Codex 제안을 다시 검증한 결과다.

판정에는 `CURRENT_STATE.md`, `PRD.md`, `USER_FLOW.md`, `DESIGN_RULES.md`, `staypet_context.md`를 함께 적용했다. 따라서 UX 논리상 타당한 제안이라도 확정된 P0 범위나 최근 제품 결정과 충돌하면 이 문서에서 임의로 확정하지 않는다.

이 문서는 다음을 하지 않는다.

- `PRD.md`, `USER_FLOW.md`, `UX_PROPOSAL_CODEX.md`의 변경
- Low-fi 제작, UI 시각 디자인, 코딩
- 미확정 정책의 확정
- Claude안과 Codex안의 최종 합의 선언

## 판정 기준

- **수용**: 문제 진단과 개선 방향이 모두 타당하다. 세부 구현은 미확정일 수 있다.
- **부분 수용**: 핵심 문제는 맞지만 근거가 과장됐거나, 제안한 해법보다 더 안전한 제3안이 있거나, 제품 문서와 조율이 필요하다.
- **반대**: 근거가 현재 제품 문서와 충돌하거나, 제안이 다른 중요한 UX 원칙을 훼손하거나, 기존 Codex 의도를 사실과 다르게 해석했다.

# 2. Claude 주장별 상세 재검토

## 2.1 Element Flow의 형식적 반복과 ‘대체 가능성’ 누락

1. **Claude의 주장 요약**  
   Codex의 53개 Element Flow가 같은 11개 항목을 형식적으로 반복했으며, uxconfirm의 12번째 축인 ‘대체 가능성’이 전부 빠졌다. 그래서 화면은 합쳐졌지만 조작 자체를 더 쉬운 방식으로 바꾼 사례가 없고 실행 취소만 추가됐다.

2. **판단: 부분 수용**

3. **UX 근거**  
   사용자가 배워야 하는 비용은 화면 수가 아니라 필수 행동 수, 서로 다른 조작 문법 수, 오류 복구에 필요한 개념 수로 결정된다. 이 기준에서 기존 문서는 이동 영역의 자유 드로잉, 지우기, 초기화, 실행 취소, 미리보기 같은 문법을 유지한 채 보조 도구를 더했다. 실질 비판은 맞다.

4. **기존 Codex 제안의 문제**  
   원래 요청의 11번 ‘존재 필요성’ 안에는 “더 직접적이고 자연스러운 상호작용으로 대체할 수 있는가?”가 포함돼 있었지만, 다수 Element에서 첫 질문인 필요성만 답하고 대체 조작 비교는 짧게 끝냈다. 특히 Brush, 문답 다음, 확대 상태의 탭, 말풍선 닫기에서 대체안을 체계적으로 비교하지 않았다.

5. **Claude 주장 자체의 문제**  
   원래 사용자 형식은 12개 독립 항목이 아니라 11개이며, 대체 가능성은 11번의 두 번째 질문이다. 따라서 “12번째 축이 형식상 전부 누락됐다”는 서술은 정확하지 않다. 또한 직접 오브젝트 터치, 별도 확대 버튼 제거, 추가 사진·동영상 분기 흡수처럼 더 직접적인 상호작용을 유지·강화한 사례가 전혀 없다는 주장도 과하다. 다만 새 조작으로 치환한 사례가 부족했다는 결론은 유효하다.

6. **수정된 UX 제안**  
   모든 핵심 Element를 다음 네 질문으로 다시 평가한다: `필수인가 → 상태 변화 없이 제거할 수 있는가 → 기존 조작에 흡수할 수 있는가 → 더 관대한 입력으로 대체할 수 있는가`. 이번 수정에서는 자유 브러시를 교정 또는 타일 토글로, 말풍선 탭 닫기를 자동 소멸로, 2~6번 단일 선택의 `다음`을 선택 즉시 진행으로, 오브젝트 드래그만을 탭 배치 병행으로 바꾼다.

7. **실제 행동 흐름의 개선**  
   사용자는 더 적은 도구 이름을 배우고, 한 번의 입력이 곧 결과로 연결되며, 잘못된 조작을 ‘실패’로 경험하는 횟수가 줄어든다. 화면을 통과하는 속도뿐 아니라 학습 비용과 복구 비용이 함께 감소한다.

## 2.2 화면 수와 조작 총량, 핵심 결정의 유예

1. **Claude의 주장 요약**  
   Codex안은 화면 병합에 집중했지만 문답 6개와 복잡한 영역 편집을 유지해 전체 조작 총량을 줄이지 못했다. 확대/이동 충돌, 후보 확대, 생성 대기, 튜토리얼 트리거처럼 중요한 문제를 ‘검증 필요’로 남겼다.

2. **판단: 부분 수용**

3. **UX 근거**  
   Low-fi 직전에는 모든 정책을 확정할 필요가 없지만, 무엇을 비교할지와 기준안은 있어야 한다. 그렇지 않으면 시제품이 임의 해석으로 만들어져 핵심 가설을 검증하지 못한다. 특히 이동 영역과 첫 교감은 성공 여부를 좌우하므로 기본 상호작용안이 필요하다.

4. **기존 Codex 제안의 문제**  
   “사용자 결정 필요”라는 안전한 표시가 과도해져, 이동 영역 조작과 첫 Home 힌트 같은 핵심 지점에서도 테스트 가능한 기준안을 제시하지 못했다. 조작 총량을 별도 지표로 계산하지도 않았다.

5. **Claude 주장 자체의 문제**  
   미확정 사항을 임의 확정하지 말라는 저장소 지침 때문에 일부 유예는 필수였다. 유예 자체를 설계 실패로 보면 제품 정책을 대신 결정하는 오류가 생긴다. 문제는 유예가 아니라 ‘비교할 후보와 판정 기준 없이 유예한 것’이다.

6. **수정된 UX 제안**  
   각 미결 사안에 `추천 기준안`, `비교안`, `판정 지표`, `제품 결정이 필요한 이유`를 붙인다. 예를 들어 이동 영역 기준안은 자동 제안 후 큰 단위 교정, 기술적으로 불가능하면 타일 토글이며, 자유 브러시는 대조안으로만 둔다.

7. **실제 행동 흐름의 개선**  
   Low-fi 참여자는 완성되지 않은 임의 조작을 시험하지 않게 되고, 팀은 “어느 화면을 좋아했는가”가 아니라 완료 시간·첫 시도 성공률·복구 횟수로 안을 비교할 수 있다.

## 2.3 종·이름·성별 통합과 성별 필수 여부

1. **Claude의 주장 요약**  
   세 입력을 하나의 맥락으로 통합하는 데 동의하되, 성별이 외형·행동·호칭에 어떤 영향을 주는지 정의되지 않았으므로 P0 필수에서 내려야 한다. 종 선택이 이후 질문을 바꾸는 의존성도 반영해야 한다.

2. **판단: 통합·종 의존성은 수용, 성별 하향은 반대**

3. **UX 근거**  
   종·이름·성별은 사용자가 ‘어떤 아이를 만들고 있는지’를 세우는 하나의 과업이므로 통합이 자연스럽다. 종 변경 시 문답 4가 짖음/울음으로 바뀌므로 즉시 종속 상태를 갱신해야 한다. 반면 필수 입력은 설명 가능한 목적이 있어야 한다는 Claude의 원칙도 타당하다.

4. **기존 Codex 제안의 문제**  
   통합만 제시하고 성별이 무엇에 쓰이는지, 종 변경이 이미 입력한 종별 문답에 어떤 영향을 주는지 충분히 적지 않았다. 이후 단계에서 종을 바꾸면 어떤 답만 무효화되는지도 더 명확해야 했다.

5. **Claude 주장 자체의 문제**  
   `PRD.md`는 성별을 P0 기본 정보로 명시한다. 이 문서가 필수에서 내리면 UX 개선이 아니라 제품 범위를 변경하는 것이다. 사용자도 제품 정책을 임의로 새로 확정하지 말라고 했다.

6. **수정된 UX 제안**  
   기본 정보는 한 단계로 유지한다. 성별은 현재 P0 상태를 유지하되, 사용자 결정 항목으로 ‘생성·호칭·행동 중 실제 영향’을 명시한다. 종을 바꾸면 문답 4의 레이블과 종 전용 예시만 즉시 바꾸고, 영향을 받는 기존 답이 있을 때만 재확인을 요청한다.

7. **실제 행동 흐름의 개선**  
   사용자는 관련 정보 사이를 오가지 않고 한 번에 입력한다. 종 변경 때문에 전체 등록을 다시 할 필요가 없고, 현재 정책이 유지되는 동안에도 “왜 묻는지 모르는 입력” 문제를 제품 결정 목록에 가시화할 수 있다.

## 2.4 사진·동영상 병합, 생성 시작과 병렬 처리

1. **Claude의 주장 요약**  
   사진과 선택 동영상을 같은 단계로 묶는 것은 맞지만, 사진 선택 직후 생성을 시작해 문답과 병렬 처리하는 안은 단순 기술 문제가 아니다. 상위 입력 수정 시 작업 무효화, 사진을 고른 직후의 감정적 순간, 실제 생성 시간이 불명확한 대기 UX를 다뤄야 한다.

2. **판단: 수용**

3. **UX 근거**  
   비동기 처리는 사용자의 상태 모델에 영향을 준다. 무엇으로 생성 중인지, 수정하면 다시 시작되는지, 답변이 현재 생성에 반영되는지를 모르면 진행이 빠르더라도 통제감을 잃는다. 업로드 선택과 확정도 다른 사건이다.

4. **기존 Codex 제안의 문제**  
   사진이 유효하면 “가능한 한 일찍 생성”한다고만 적고, 시작 커밋 지점과 작업 버전을 정의하지 않았다. 문답 도중 사진·종을 수정했을 때 기존 작업을 취소할지, 후보를 폐기할지, 답변이 다음 생성에만 반영되는지 빠졌다.

5. **Claude 주장 자체의 문제**  
   병렬화를 하지 말아야 한다는 결론까지는 근거가 없다. 실제 생성 시간이 문답보다 길다면 사용자의 대기 시간을 유용하게 바꿀 수 있다. 필요한 것은 병렬화 금지가 아니라 정직하고 예측 가능한 작업 규칙이다.

6. **수정된 UX 제안**  
   사진 선택 후 적합성 확인과 사용자의 `이 사진으로 계속` 확정이 끝난 때 생성 버전 1을 시작한다. 종·주 사진·피사체 선택을 바꾸면 진행 중 작업을 조용히 버리지 않고 “새 입력으로 다시 준비됨”을 알리며 버전 2를 시작한다. 완료된 이전 후보는 새 후보가 성공할 때까지 보존한다. 실제 진행률을 모르면 퍼센트나 ETA를 만들지 않고 `사진 확인 → 특징 준비 → 후보 생성`처럼 사실인 상태만 보여준다.

7. **실제 행동 흐름의 개선**  
   사용자는 생성이 언제 시작됐고 수정이 어떤 영향을 주는지 이해한다. 대기 중 문답을 답해도 다시 처음부터 해야 한다는 불안을 줄이고, 새 생성 실패 시 기존 결과로 돌아갈 수 있다.

## 2.5 여섯 문답의 위저드 구조와 탭 수

1. **Claude의 주장 요약**  
   Codex가 “매번 같은 CTA는 설문처럼 느껴진다”고 진단한 뒤에도 숫자 진행률과 공통 이전/다음을 채택해 해법이 진단과 어긋났다. 모든 문항에서 선택 후 `다음`을 누르면 최소 12탭이며, 단일 선택인 2~6은 선택 즉시 진행할 수 있다.

2. **판단: 수용**

3. **UX 근거**  
   1번은 복수 선택 가능성이 있어 확정 행동이 필요하지만 2~6은 단일 선택이다. 모든 질문에 같은 CTA를 쓰면 질문 의미보다 위저드 통과가 전면에 온다. 단일 선택 뒤 별도 확인은 실수 방지 이득보다 반복 비용이 클 수 있다.

4. **기존 Codex 제안의 문제**  
   일관성을 단순함과 혼동했다. 문항 유형 차이를 상호작용에 반영하지 않았고, 진행률도 “3/6”을 표시할지보다 사용자가 왜 답하는지를 설명하는 데 덜 집중했다. 필수 탭 수를 세지 않은 것도 누락이다.

5. **Claude 주장 자체의 문제**  
   단일 선택 즉시 자동 진행은 선택을 잠깐 탐색하거나 손가락이 빗나간 사용자에게 화면이 사라지는 느낌을 줄 수 있다. 모든 사용자에게 무조건 더 낫다고 확정할 근거는 아직 없다. 접근성 보조 기술에서도 충분한 선택 확인이 필요할 수 있다.

6. **수정된 UX 제안**  
   문답 1은 복수 선택 후 명시적 확인을 사용한다. 문답 2~6은 선택 즉시 값이 반영되고 짧은 전환 뒤 다음 질문으로 이동하는 안을 기준으로 시험하되, 항상 `이전`으로 돌아와 답을 바꿀 수 있어야 한다. 자동 진행과 명시적 다음을 Low-fi에서 비교하고, 오선택·되돌림·완료 시간을 측정한다. 진행 정보는 남은 부담을 숨기지 않되, “아이의 생활 반응에 반영됨”이라는 목적과 함께 전달한다.

7. **실제 행동 흐름의 개선**  
   선행 문답을 모두 답는 경우 최소 행동이 12회에서 7회 수준으로 줄어든다. 이전 이동이 보장되므로 속도를 얻으면서도 실수 복구 가능성을 유지한다.

## 2.6 문답 1만 선행하는 안, 점진적 문답, 문답 3·5의 정서적 안전성

1. **Claude의 주장 요약**  
   첫 개인화 확인에 직접 필요한 문답 1만 첫 만남 전에 받고, 문답 2~6은 첫 쓰다듬기 뒤로 옮기면 첫 만남 전 단계가 7~8로 줄어든다. 식사·배변 주기는 투병이나 말년의 기억을 자극할 수 있으므로 중립 선택지도 필요하다.

2. **판단: 부분 수용**

3. **UX 근거**  
   문답 1은 첫 쓰다듬기 하트라는 즉시 보상과 연결되지만, 2~6은 보상 회수 시점이 늦다. 그래서 모든 문답을 첫 만남의 관문으로 두는 것은 약하다. 다만 활동·발성·수면 정보가 없는 첫 등장 행동이 획일적이면 “우리 아이다”라는 가치 A가 약해질 수 있다. 전부 선행과 전부 후행 사이의 선택만 있을 필요는 없다.

4. **기존 Codex 제안의 문제**  
   생성 대기와 문답을 겹치는 것만 검토하고 문답이 첫 만남을 차단해야 하는지 자체를 재검토하지 않았다. 이는 TTFV의 가장 큰 덩어리를 그대로 둔 핵심 누락이다. 문답 3·5를 데이터 입력으로만 보고 감정적 회상 부담을 고려하지 않은 것도 잘못이다.

5. **Claude 주장 자체의 문제**  
   2~6을 모두 첫 쓰다듬기 뒤로 고정하면 생성 대기라는 자연스러운 여백을 사용하지 못하고, 첫 만남 직후 감정 보상을 또 설문으로 끊을 수 있다. ‘중립 선택지’를 바로 추가하면 빈도 데이터의 의미와 행동 기본값이라는 제품 정책까지 새로 결정하게 된다.

6. **수정된 UX 제안**  
   `점진적 생활 보정`을 제3안으로 제안한다. 문답 1만 첫 교감 전 필수로 둔다. 문답 2~6은 실제 생성 대기가 존재할 때 “기다리는 동안 더 알려주기”로 답할 수 있지만 후보 준비를 막지 않는다. 후보가 먼저 준비되면 즉시 후보로 이동하고 미응답 문항은 첫 쓰다듬기 후 Home의 비강제 보정 흐름으로 남긴다. 문답 3·5에는 `지금 답하기 어렵다` 또는 `잘 모르겠다` 같은 유예가 필요한지 사용자 검증 후 제품 결정한다. 유예 때문에 벌점·결핍·나쁜 행동은 생기지 않는다.

7. **실제 행동 흐름의 개선**  
   사용자는 반드시 거쳐야 할 질문을 하나로 줄이고, 기다리는 시간이 있을 때만 추가 정보를 제공한다. 기억하기 힘든 식사·배변 질문을 억지로 고르지 않아도 되며, 답하지 않아도 아이를 만나는 길이 막히지 않는다. 동시에 답한 정보는 첫 생활 장면부터 반영할 수 있다.

## 2.7 캐릭터 후보 비교, 복구 경로, 반복 재생성

1. **Claude의 주장 요약**  
   원인별 복구와 기존 후보 보존은 좋지만, 다시 만들기·사진 추가·이전 입력 수정·보정을 대등하게 보여주면 사용자가 실패 원인을 진단해야 한다. 원본 사진 참조, 후보 확대, 반복 재생성의 방향과 안전한 퇴로도 빠졌다.

2. **판단: 수용**

3. **UX 근거**  
   후보가 마음에 들지 않는 순간은 분석 과제가 아니라 감정적으로 민감한 판단 순간이다. 사용자가 생성 시스템의 실패 원인을 구분하게 하면 부담이 커진다. 기존 결과를 보존하고 한 가지 명확한 다음 행동을 주되, 정밀한 수정은 필요할 때만 열어야 한다.

4. **기존 Codex 제안의 문제**  
   네 복구 경로의 의미는 분리했지만 정보 구조를 정하지 않아 사실상 동등한 선택처럼 읽혔다. `다시 만들기`를 반복하면 더 나아진다는 기대를 어떻게 다룰지, 결과를 더 보기 싫을 때 어떻게 빠져나갈지도 누락했다. 보정은 ‘가까운 후보를 조금 고치는’ 경로인데 불만족 복구와 같은 레벨에 놓였다.

5. **Claude 주장 자체의 문제**  
   원본 사진을 항상 후보 옆에 병치하면 닮음의 차이를 더 날카롭게 만들고 정서적으로 불편할 수 있다. “방향 힌트”도 시스템이 보장하지 못하는 속성을 약속하면 또 다른 실패 기대를 만든다.

6. **수정된 UX 제안**  
   후보 화면의 주 과업은 `후보 선택 → 이 모습으로 계속`이다. 만족할 후보가 없을 때 주 복구는 `다시 준비하기` 하나로 두고, 열면 `사진을 더하거나 바꾸기`, `기본 정보 확인`, `같은 입력으로 새 후보 받기`를 설명과 함께 제시한다. 보정은 선택한 후보가 “가깝지만 조금 다른” 경우에만 진입한다. 원본은 요청 시 확인하거나 한 후보를 집중 비교하는 방식으로 시험한다. 반복 재생성 뒤에는 추가 사진 안내와 `지금은 나가기/나중에 계속`을 제공하며 기존 후보와 입력을 보존한다.

7. **실제 행동 흐름의 개선**  
   사용자는 먼저 실패 원인을 진단하지 않고도 안전하게 한 단계 진행할 수 있다. 가까운 결과는 보정하고, 근본적으로 다른 결과는 입력을 개선하며, 정서적으로 불편하면 평가 없이 떠날 수 있다. 무의미한 반복과 데이터 재입력이 줄어든다.

## 2.8 이동 가능 영역: 자유 브러시, 교정, 타일, 확대, 미리보기

1. **Claude의 주장 요약**  
   자유 브러시를 유지하고 지우기·초기화·실행 취소·미리보기 등을 추가한 것은 어려운 과업을 미니 이미지 편집기로 만든 것이다. 시스템 바닥 추정 후 교정, 블록 토글, 확대·이동 제거, 편집 중 상시 이동 표시가 더 단순하다.

2. **판단: 핵심 진단은 수용, 세부 해법은 부분 수용**

3. **UX 근거**  
   사용자의 목표는 마스크를 잘 그리는 것이 아니라 “아이가 어디까지 다닐 수 있는지” 정하는 것이다. 빈 캔버스 자유 드로잉은 시작점과 필요한 정밀도를 알기 어렵다. 생성보다 교정이 빠르고, 큰 단위 선택은 정밀 연속 제스처보다 접근성이 높다.

4. **기존 Codex 제안의 문제**  
   PRD의 ‘직접 표시’를 자유 브러시 유지로 좁게 해석했다. 오류 복구는 늘렸지만 최초 성공을 쉽게 만들지 못했다. 별도 미리보기를 두어 편집과 결과 예측을 분리했고, 확대·이동 충돌의 기준안도 없었다.

5. **Claude 주장 자체의 문제**  
   임의의 실제 공간 사진에서 바닥 추정이 충분히 안정적이라는 보장이 없다. 잘못된 자동 제안은 사용자가 시스템 오판을 찾아내게 만들 수 있다. 확대를 완전히 금지하면 작은 화면이나 복잡한 공간에서 오히려 접근성이 나빠진다. 캐릭터를 편집 중 계속 움직이는 방식은 선택 대상과 겹치고 주의를 산만하게 할 수 있다.

6. **수정된 UX 제안**  
   우선순위는 다음과 같다. 1안은 시스템이 넓은 후보 영역을 제안하고 사용자가 큰 타일 단위로 추가·제외하는 `제안 후 교정`이다. 2안은 자동 추정 없이 큰 타일을 탭하거나 쓸어 직접 켜고 끄는 방식이다. 같은 타일 재탭은 지우기이므로 별도 지우개가 필요 없다. 전체 초기화와 한 단계 실행 취소만 유지한다. 별도 미리보기 모드는 제거하고 선택 영역 안에 정적 발자국·도달 예시 또는 간단한 경로 샘플을 상시 표시한다. 확대가 필요하면 명시적 확대 상태에서만 제공하고 한 손가락 영역 선택과 충돌시키지 않는다. 자유 브러시는 비교 대조안으로만 둔다.

7. **실제 행동 흐름의 개선**  
   사용자는 어디서 시작할지 고민하지 않고 제안 영역을 고치거나 큰 칸을 선택한다. 지우개 모드를 기억하지 않아도 같은 조작으로 추가·제외할 수 있으며, 완료 전에 이동 결과를 계속 예측한다. 첫 시도 완료율과 수정 횟수가 개선될 가능성이 높다.

## 2.9 첫 만남 전후의 오브젝트 배치

1. **Claude의 주장 요약**  
   오브젝트 배치를 첫 만남 뒤로 옮기는 데 동의하지만, Codex가 제시한 자동 배치 확인 단계도 새로운 관문이므로 없애야 한다. 기본 오브젝트는 조용히 자동 배치하고 첫 만남을 먼저 보여줘야 한다.

2. **판단: 부분 수용**

3. **UX 근거**  
   후보와 공간을 준비한 직후의 감정적 기대를 밥그릇·잠자리·장난감 배치 과제가 끊어서는 안 된다. 확인만 하는 단계도 여전히 첫 만남을 지연한다. 다만 실제 집 사진 위의 가상 오브젝트 위치는 공간의 자연스러움에 직접 영향을 준다.

4. **기존 Codex 제안의 문제**  
   첫 만남 뒤 수동 배치를 추천하면서도 Low-fi 범위에서는 이동한 오브젝트 배치를 필수처럼 적어 내부 우선순위가 흔들렸다. ‘기술적으로 오브젝트가 필요하면 자동 배치 확인’이라는 안전안도 확인을 관문으로 남겼다.

5. **Claude 주장 자체의 문제**  
   조용한 자동 배치가 항상 안전하지 않다. 실제 사진의 벽·가구·통로 위에 그릇이 놓이면 “우리 집”이라는 핵심 가치가 깨진다. 또한 PRD는 기본 오브젝트 배치를 P0로 명시하므로 사용자 통제를 완전히 제거하는 것은 제품 범위 재해석이다.

6. **수정된 UX 제안**  
   기술적으로 가능하면 첫 만남에는 가상 생활 오브젝트를 요구하지 않는다. 첫 쓰다듬기 후 Home 맥락에서 밥그릇 하나를 탭 배치로 안내하고, 잠자리·장난감은 이후 필요 맥락에서 배치한다. 기술상 첫 장면에 오브젝트가 반드시 필요하면 시스템이 임시 위치를 정하되 첫 만남 전 확인을 요구하지 않고, Home에서 첫 교감 뒤 수정 기회를 준다. 이 두 안은 제품·기술 결정이 필요하다.

7. **실제 행동 흐름의 개선**  
   사용자는 설정을 끝내기 위해 집을 꾸미는 대신 먼저 아이를 만난다. 감정적 보상 뒤에 한 가지 실제 행동으로 밥그릇 조작까지 자연스럽게 배우며, 한 번에 세 개를 배치하는 부담도 줄어든다.

## 2.10 TTFV 정량화와 이탈 위험 우선순위

1. **Claude의 주장 요약**  
   Codex는 첫 만남까지 길다고 말했지만 단계 수를 측정하지 않았다. 현행 15~18, Codex 12~13이며 문답 1만 선행하면 7~8로 줄어든다. 이동 영역은 Codex가 매긴 3순위보다 더 위험하고, 빈도와 심각도를 분리해야 한다.

2. **판단: 수용**

3. **UX 근거**  
   “빠르다”는 인상만으로 안을 비교할 수 없다. 첫 가치까지 걸리는 실제 시간, 필수 결정 수, 입력 수, 오류 복구 횟수를 함께 봐야 한다. 이 제품은 `우리 아이가 우리 집에 있다`와 `내 답이 반응에 반영됐다`라는 두 가치 순간이 다르므로 둘을 별도로 측정해야 한다.

4. **기존 Codex 제안의 문제**  
   TTFV를 정성적으로만 다뤘고 질문 6개가 전체 경로에서 차지하는 비중을 계산하지 않았다. 이탈 위험을 단일 순위로 제시해 발생 가능성과 실패 심각도를 섞었다. 이동 영역이 감정 보상 직전이라는 위치적 위험도 충분히 반영하지 않았다.

5. **Claude 주장 자체의 문제**  
   15~18, 12~13, 7~8은 화면·분기·자동 상태를 무엇으로 세는지 명확하지 않아 실제 TTFV 수치는 아니다. 이동 영역이 1~2순위라는 주장도 사용자 데이터가 아니라 합리적 가설이다. 단계 수가 같아도 사진 선택 1회와 자유 브러시 1회는 시간이 크게 다르다.

6. **수정된 UX 제안**  
   `TTFV-A = 앱 실행부터 실제 공간 속 캐릭터 첫 노출`, `TTFV-B = 앱 실행부터 선호 쓰다듬기 개인화 반응`으로 분리한다. 각 지표에 초 단위 시간, 차단 단계 수, 필수 선택·제스처 수, 되돌림 수를 기록한다. 이탈 위험은 `발생 가능성`과 `발생 시 손실`을 각각 평가한다. 4장에서 동일 단위로 경로를 다시 계산한다.

7. **실제 행동 흐름의 개선**  
   팀은 화면을 두 개 줄였다는 이유만으로 개선을 확정하지 않고, 사용자가 실제로 더 빨리 가치 A와 B에 도달하는지 확인할 수 있다. 가장 느리고 회복하기 어려운 구간부터 개선하게 된다.

## 2.11 Home 발견성, 망설임, 빈 배경 탭, 첫 급식

1. **Claude의 주장 요약**  
   Codex의 ‘사용자가 망설이면 안내’는 트리거가 없고, 빈 배경 탭의 반응도 정의하지 않았다. 빈 탭에 캐릭터가 시선을 보내고, 첫 밥그릇 탭은 배고프지 않아도 반드시 알아차리는 반응을 해야 한다.

2. **판단: 문제 진단과 첫 급식은 수용, 빈 탭 해법은 부분 수용**

3. **UX 근거**  
   버튼이 없는 직접 상호작용에서는 잘못된 곳을 누르는 행동도 정상적인 탐색이다. 첫 두세 번의 입력이 무반응이면 화면 전체를 비상호작용으로 오해할 수 있다. 첫 유효 상호작용은 상태 조건과 무관하게 조작이 인식됐음을 보여줘야 한다.

4. **기존 Codex 제안의 문제**  
   ‘망설임’을 시간·행동으로 정의하지 않았고 유효하지 않은 입력을 Element로 다루지 않았다. 첫 급식에서 배고픔 상태를 자율성보다 앞세워, 사용자의 첫 조작이 무반응일 수 있게 했다.

5. **Claude 주장 자체의 문제**  
   캐릭터가 모든 빈 탭 지점을 바라보면 사용자는 바닥 탭으로 이동이나 주의를 지시할 수 있다고 학습할 수 있다. 이는 자율 NPC 원칙과 충돌하고 반복 탭을 부추긴다. 유효하지 않은 탭마다 세계가 반응할 필요도 없다.

6. **수정된 UX 제안**  
   첫 Home에서 첫 만남 직후 캐릭터가 가까운 상태를 잠시 유지해 유효 타깃을 쉽게 만든다. `5초 동안 유효 상호작용 없음` 또는 `빈 영역 2회 탭`을 초기 테스트용 힌트 트리거로 둔다. 빈 탭 자체는 오류나 이동 명령으로 처리하지 않고 Home을 유지하며, 두 번 연속이면 가장 가까운 유효 대상에 상황형 힌트를 한 번 제공한다. 밥그릇 첫 탭은 그릇 상태 변화와 캐릭터의 시선·귀·짧은 몸짓 중 하나로 항상 인지시키되, 배고프지 않으면 강제로 먹이지 않는다.

7. **실제 행동 흐름의 개선**  
   첫 탐색 실패가 곧 “안 눌린다”는 결론으로 이어지지 않는다. 동시에 사용자는 빈 바닥을 명령 입력으로 오해하지 않는다. 밥을 주면 최소한 전달됐다는 확신을 얻으면서도 캐릭터의 자율성은 유지된다.

## 2.12 캐릭터 확대, 탭·쓰다듬기, 종료, 말풍선 충돌

1. **Claude의 주장 요약**  
   탭으로 확대에 진입했는데 확대 상태에서는 문지르기만 인정하면 모드가 불일치한다. 탭을 짧은 쓰다듬기로 수용하고, 명시적 닫기를 1차 종료 수단으로 삼으며, 말풍선은 탭 대상에서 제거해 캐릭터로 터치를 통과시켜야 한다.

2. **판단: 종료·말풍선은 수용, 탭을 완전한 쓰다듬기로 보는 것은 부분 수용**

3. **UX 근거**  
   같은 대상에 같은 탭을 했는데 상태에 따라 무반응이면 오류처럼 느껴진다. 그러나 제품의 핵심 입력은 사용자가 몸의 부위를 ‘문지르는’ 행위이며, 선호 부위 개인화도 위치와 지속 입력이 있어야 의도가 분명해진다. 탭을 전부 동일한 성공으로 처리하면 이 차별점이 약해질 수 있다.

4. **기존 Codex 제안의 문제**  
   확대 중 단순 탭을 실패처럼 보고 안내를 반복한 것은 부자연스럽다. 종료 수단 세 개를 대등하게 나열해 기본 정신 모델을 정하지 않았고, 말풍선 탭 닫기가 캐릭터 히트 타깃을 가리는 문제를 놓쳤다.

5. **Claude 주장 자체의 문제**  
   탭 하나만으로 선호 부위 하트까지 동일하게 발생시키면 사용자는 문지르기를 발견하지 못하고, 우연한 탭에도 강한 개인화 반응이 나와 “내가 답한 것이 반영됐다”는 인과가 약해질 수 있다.

6. **수정된 UX 제안**  
   확대 상태에서 탭은 실패가 아니라 짧은 접촉으로 받아 캐릭터의 미세한 인지 반응을 준다. 문지르기, 짧게 누르기 또는 접근성용 반복 탭이 쓰다듬기 상태를 만들며, 선호 부위에서는 그때 하트와 더 분명한 긍정 반응이 나온다. 종료는 명시적 닫기를 1차, 시스템 뒤로가기를 2차로 보장한다. 안전한 빈 여백 탭은 보조 수단일 뿐 유일한 방법이 아니다. 말풍선은 탭을 가로채지 않고 자동 소멸하며, 말풍선 위 터치는 가능한 경우 캐릭터로 전달한다.

7. **실제 행동 흐름의 개선**  
   탭이 무시되지 않으면서도 문지르기의 감정적 의미가 유지된다. 사용자는 종료 방법을 찾기 위해 여러 영역을 시험하지 않고 명시적으로 돌아갈 수 있고, 말풍선 때문에 캐릭터 접촉이 실패하지 않는다.

## 2.13 최소 튜토리얼과 첫 세션의 발견 개수

1. **Claude의 주장 요약**  
   Codex의 상황형 1회 안내가 PRD의 P0 ‘첫 사용 튜토리얼’을 조용히 재정의했다. 기능 발견을 여러 방문에 나누면 재방문해야만 재방문 동기를 발견하는 순환이 생긴다. 첫 세션에 최소 두 상호작용을 경험하게 해야 한다.

2. **판단: 부분 수용**

3. **UX 근거**  
   첫 세션에 모든 기능을 설명하면 몰입이 깨지지만, 캐릭터만 보고 아무것도 못 한 채 나가면 재방문 이유도 약해진다. 최소한 개인화된 쓰다듬기와 생활 오브젝트 한 가지의 직접성을 발견할 기회가 필요하다. P0 튜토리얼은 반드시 별도 투어나 체크리스트를 뜻하지 않는다.

4. **기존 Codex 제안의 문제**  
   ‘상황형 힌트의 합이 튜토리얼’이라는 해석을 명시적으로 제품 결정 항목에 올리지 않았다. 첫 세션에서 어느 정도까지 도달시키는지 성공 기준도 없었다.

5. **Claude 주장 자체의 문제**  
   “최소 두 개를 반드시 완료”로 바꾸면 새로운 강제 과제가 된다. 사용자가 첫 만남만 조용히 보고 나가고 싶은 선택도 존중해야 한다. 발견 기회와 완료 의무는 다르다.

6. **수정된 UX 제안**  
   첫 만남 직후 캐릭터 접촉 기회를 가장 먼저 만들고, 첫 쓰다듬기 후에만 밥그릇 한 가지를 맥락 속에서 소개한다. 사용자가 반응하지 않으면 진행을 막거나 완료 체크를 요구하지 않는다. Low-fi에서는 첫 세션에 네 핵심 대상 중 몇 개를 자발적으로 발견했는지, 첫 개인화 반응까지 도달했는지를 측정한다. `P0 튜토리얼 = 상황형 안내의 합`인지 여부는 사용자 결정으로 남긴다.

7. **실제 행동 흐름의 개선**  
   사용자는 설명 화면을 통과하지 않고도 핵심 교감과 생활 상호작용을 실제 맥락에서 배운다. 조용히 머물거나 나갈 자유는 유지되며, 재방문 전에 제품이 ‘보기만 하는 장면’이 아니라는 점을 알 가능성이 높아진다.

## 2.14 재방문에서 ‘앱 밖에서도 생활했다’는 이해

1. **Claude의 주장 요약**  
   Codex가 연속성 설명을 두 번째 방문의 백업으로 미뤄, 재방문하지 않은 사용자에게 핵심 가설이 전달되지 않는다. 첫 재진입 장면에서 변화가 보여야 하고 캐릭터도 즉시 보이거나 찾을 수 있어야 한다.

2. **판단: 부분 수용**

3. **UX 근거**  
   보고서나 보상 팝업 없이도 현재 위치·행동·생활 흔적이 전과 다르면 자율적 생활을 추론할 수 있다. 다만 첫 프레임에 캐릭터가 없고 변화도 미세하면 사용자는 로딩 실패로 오해한다. 최초 재방문은 연속성 가설을 검증하는 중요한 순간이다.

4. **기존 Codex 제안의 문제**  
   현재 장면을 1차 전달 수단으로 두었지만, 캐릭터가 시야 밖이거나 가려진 경우와 변화가 약한 경우를 충분히 정의하지 않았다. 보조 문구를 언제 한 번 보여줄지 트리거도 불명확했다.

5. **Claude 주장 자체의 문제**  
   Codex는 핵심 가설 자체를 두 번째 방문 이후로 미룬 것이 아니다. 기존 3.14와 7.6의 1차 원칙은 첫 재방문부터 달라진 현재 장면을 직접 보여주는 것이고, 설명 문구만 두 번째 방문의 백업으로 제한했다. 따라서 “재방문하지 않은 사람에게 영원히 도달하지 않는다”는 비판은 현재 장면이라는 1차 전달 수단을 누락한 해석이다. 또한 재방문을 하지 않은 사용자에게 ‘앱을 꺼둔 동안 생활했다’를 실제로 증명하는 것은 논리적으로 불가능하다.

6. **수정된 UX 제안**  
   첫 재방문 첫 프레임에서 캐릭터가 보이거나 한 번의 명확한 단서로 즉시 찾을 수 있어야 한다. 이전 종료 장면과 다른 현재 행동 또는 생활 흔적 하나를 비모달로 보여준다. 이해가 확인되지 않으면 최초 재방문에 한해 “쉬는 동안에도 자기 시간을 보냈어요”처럼 죄책감 없는 원리 설명을 짧게 보조할 수 있지만 활동 보고서·보상 요약은 만들지 않는다. 실제 문구는 후속 카피 검토 대상이다.

7. **실제 행동 흐름의 개선**  
   사용자는 앱을 열자마자 현재의 아이를 찾고, 지난번 장면을 복구한 것이 아니라 시간이 이어졌다고 이해할 단서를 얻는다. 보고서를 닫는 과제 없이 바로 Home 생활로 들어간다.

## 2.15 사진 적합성의 조기 확인과 적합한 사진이 없는 사용자

1. **Claude의 주장 요약**  
   가장 치명적인 실패는 업로드 오류가 아니라 “사용 가능한 파일이지만 닮은 결과가 나오기 어려운 사진”이다. 얼굴이 너무 작거나 피사체가 여럿인 문제를 후보 단계에서 처음 알리면 늦다. 적합한 사진이 아예 없는 사용자 경로도 필요하다.

2. **판단: 수용**

3. **UX 근거**  
   실패를 원인 가까이에서 발견하면 수정 비용과 감정적 기대 손실이 작다. 사진을 고른 직후의 안내는 후보 2~3개가 모두 어색하게 나온 뒤 원인을 설명하는 것보다 안전하다. 이 제품에서는 품질 실패가 정서적 불편으로 확대될 수 있다.

4. **기존 Codex 제안의 문제**  
   파일 형식·권한·손상·네트워크 같은 기술 오류만 상세히 다루고, 피사체 크기·가림·다중 피사체·흐림 같은 의미적 적합성을 누락했다. 적합한 자료가 없는 사용자를 후보까지 밀어 넣거나 막는 두 극단 사이의 경로도 없었다.

5. **Claude 주장 자체의 문제**  
   얼굴 인식 성공을 곧 “이 사진으로 계속할 수 있음”으로 표현하면 생성 품질을 과도하게 약속할 수 있다. 크롭과 피사체 선택을 당연한 해법으로 넣는 것도 새로운 기능·모델 능력을 가정한다. 오래된 사진의 품질을 평가하는 표현이 사용자의 기억을 평가하는 것처럼 들려서도 안 된다.

6. **수정된 UX 제안**  
   업로드 직후 품질 점수 대신 최소 적합성 점검을 한다: 반려동물 감지 여부, 너무 작은 피사체, 여러 피사체, 심한 가림처럼 확인 가능한 조건만 알린다. 사용 가능한 경우 생성 가능성을 보장하지 않고 “이 사진을 참고할 수 있어요” 정도로 처리한다. 문제가 있으면 `다른 사진 추가`, `이 사진 교체`, `나중에 계속`을 제공하고 입력을 보존한다. 크롭·피사체 지정은 기술 가능성과 사용자 이해를 별도 검증한 뒤 결정한다. 완전히 사용할 수 없는 경우만 진행을 막고 이유와 복구를 같은 자리에서 제공한다.

7. **실제 행동 흐름의 개선**  
   사용자는 질문과 대기를 끝낸 뒤 실패를 발견하지 않고, 가장 수정하기 쉬운 순간에 자료를 보완한다. 좋은 사진이 없어도 비난받거나 모든 기억을 다시 찾도록 강요받지 않으며, 안전하게 중단하고 돌아올 수 있다.

## 2.16 접근성: 브러시·드래그·문지르기의 대체 입력

1. **Claude의 주장 요약**  
   핵심 상호작용이 정밀한 연속 제스처에 집중돼 손 떨림, 운동 제약, 낮은 기기 숙련도를 가진 사용자가 완료하기 어렵다. 블록 토글과 탭 쓰다듬기 같은 대체가 필요하다.

2. **판단: 수용**

3. **UX 근거**  
   접근성 대안은 별도 모드보다 같은 결과에 도달하는 관대한 입력으로 제공할 때 학습 비용이 낮다. 실제 사용자층의 연령을 단정할 필요 없이, 핵심 가치가 한 종류의 정밀 제스처에만 의존하지 않아야 한다.

4. **기존 Codex 제안의 문제**  
   이동 영역의 Brush, 오브젝트 배치의 드래그, 쓰다듬기의 문지르기를 각각 유일한 정상 조작처럼 기술했다. 터치 판정 범위는 언급했지만 대체 입력과 시간 제한 없음, 중간 성공 인정 같은 관대한 규칙이 빠졌다.

5. **Claude 주장 자체의 문제**  
   대상 사용자가 모바일 게임 사용자보다 연령·숙련도 분포가 넓다는 서술은 확인되지 않은 가정이다. 그러나 이 가정이 사실이어야만 접근성 개선이 필요한 것은 아니다. 또한 탭 하나를 문지르기와 완전히 동일시하는 것은 개인화 인과를 약하게 만들 수 있다.

6. **수정된 UX 제안**  
   이동 영역은 큰 타일 탭/쓸기, 오브젝트는 드래그와 위치 탭 선택을 모두 허용한다. 쓰다듬기는 문지르기 외에 짧게 누르기 또는 같은 부위 반복 탭으로도 충분한 접촉을 인식한다. 모든 핵심 조작은 넓은 판정 범위, 시간 압박 없음, 중간 상태 보존을 기본으로 한다.

7. **실제 행동 흐름의 개선**  
   사용자는 손가락 정밀도에 따라 자신에게 쉬운 조작을 선택하고, 한 번의 흔들림이나 손을 뗀 행동 때문에 전체 과업을 다시 하지 않는다. 접근성 개선이 곧 일반 사용자의 오류 허용성도 높인다.

## 2.17 정서적으로 불편한 생성 결과와 안전한 퇴로

1. **Claude의 주장 요약**  
   후보 불만족은 닮음이나 품질 문제만이 아니라, 애도 중인 사용자에게 보기 힘든 결과일 수 있다. 첫 결과의 기대치 설정과 평가하지 않고 나가는 경로가 필요하다.

2. **판단: 수용**

3. **UX 근거**  
   생성 결과는 시스템 산출물이지만 사용자는 실제 반려동물의 기억과 비교한다. 불편한 결과를 계속 보면서 원인을 선택하거나 평가하게 하면 회복보다 회피와 이탈이 커질 수 있다. 결과 보존보다 숨김과 중단이 우선인 경우도 있다.

4. **기존 Codex 제안의 문제**  
   불만족을 유사도·세부 외형·입력 부족으로만 분류했다. 결과를 즉시 치우기, 등록을 저장하고 나가기, 이후 다시 시작하기, 피드백을 강요하지 않기 같은 정서적 안전 흐름이 없었다.

5. **Claude 주장 자체의 문제**  
   기대치를 낮추는 설명을 과하게 앞세우면 첫 결과를 보기 전부터 실패를 예고하고 감정적 기대를 꺾을 수 있다. “정서적으로 불편한 결과”를 사용자에게 직접 판별·명명하게 할 필요도 없다.

6. **수정된 UX 제안**  
   후보는 확정 전 제안 상태임을 짧게 알리고, 결과 화면에서 `지금은 그만 보기`를 즉시 사용할 수 있게 한다. 이 행동은 후보를 숨기고 입력을 저장한 채 이전 안전 지점 또는 앱 밖으로 나가며, 이유·별점·불쾌함 평가를 요구하지 않는다. 다시 들어오면 기존 결과를 자동으로 크게 노출하지 않고 계속 보기 여부를 선택하게 한다.

7. **실제 행동 흐름의 개선**  
   사용자는 시스템 실패를 견뎌야 다음 단계로 갈 수 있다는 압박을 받지 않는다. 감정이 준비됐을 때 이어갈 수 있고, 반복 재생성으로 불편함이 누적되는 것을 막는다.

## 2.18 첫 만남 인터럽트와 다시보기

1. **Claude의 주장 요약**  
   Codex는 첫 만남이 중단되면 다시 보여줘야 한다고 하면서 수동 다시보기는 범위에 추가하지 않아 모순된다. 전화·알림·백그라운드 전환 같은 정상 인터럽트 복구가 필요하다.

2. **판단: 부분 수용**

3. **UX 근거**  
   첫 만남은 5~10초의 감정적 정점이므로 앱이 foreground가 아닌 동안 완료 처리되면 안 된다. 사용자가 장면을 보지 못한 상태와, 장면을 본 뒤 다시 보고 싶은 상태는 서로 다른 UX 요구다.

4. **기존 Codex 제안의 문제**  
   ‘안전하게 이어가기’, ‘다시 보여주는 정책’, ‘수동 다시보기 미추가’를 가까이 적어 두 개의 상태를 구분하지 못했다. 완료 판정 시점과 외부 인터럽트 상태도 오류·복구 표에 명시하지 않았다.

5. **Claude 주장 자체의 문제**  
   미완료 장면의 자동 복구와 완료한 장면의 수동 다시보기는 모순 관계가 아니다. 전자는 실패 복구이고 후자는 별도 기능이다. Claude가 둘을 같은 ‘다시보기’로 묶은 것은 과하다. 수동 다시보기는 현재 PRD P0에 없으므로 자동으로 추가할 수 없다.

6. **수정된 UX 제안**  
   첫 만남 완료 플래그는 앱이 foreground인 상태에서 핵심 등장과 시스템 문구가 표시되고 Home 전환이 끝난 뒤에만 기록한다. 그 전에 백그라운드로 가면 완료하지 않고, 복귀 시 장면 시작 전이면 다시 시작하고 진행 중이면 자연스러운 지점에서 재개한다. 완료 뒤에는 자동 반복하지 않는다. 사용자가 다시 보고 싶을 때의 수동 재생은 별도 사용자 결정으로 남긴다.

7. **실제 행동 흐름의 개선**  
   전화나 알림 때문에 핵심 순간을 영구히 놓치지 않는다. 반대로 이미 본 사용자는 재접속 때마다 장면이 반복되는 불편을 겪지 않는다.

## 2.19 Low-fi 범위·매체, 보정 속성, 재개 단위, P1 분석

1. **Claude의 주장 요약**  
   Codex의 Low-fi 범위는 앞뒤가 모순되고, 정적 화면으로 제스처·자율성·재방문을 검증하려 한다. 보정 6속성과 세밀한 저장 지점은 1차에 과하며, 정책이 없는 상점·알림 Element Flow도 일찍 작성됐다.

2. **판단: 부분 수용**

3. **UX 근거**  
   검증 매체는 가설이 요구하는 행동을 재현해야 한다. 화면 순서는 정적 연결로 볼 수 있지만 Brush·타일·드래그·문지르기·종료는 인터랙션 가능한 상태가 필요하다. 장기 재방문은 한 세션 시뮬레이션만으로 실제 재방문 동기를 증명할 수 없다. 1차 보정은 모든 속성보다 ‘선택 후보를 부분 수정하는 정신 모델’을 먼저 확인하는 편이 효율적이다.

4. **기존 Codex 제안의 문제**  
   8.1에서는 오브젝트 배치 후행 흐름을 필수처럼 적고 13.8에서는 전후 배치 비교를 사용자 결정으로 남겨 모순됐다. Low-fi의 상호작용 수준을 구분하지 않았고, 문답별·파일별 저장 단위를 구현 사양에 가깝게 세분화했다.

5. **Claude 주장 자체의 문제**  
   Low-fi는 반드시 정적이지 않으며 낮은 충실도의 인터랙티브 시제품도 가능하다. 따라서 문제는 ‘Low-fi라서 검증 불가’가 아니라 필요한 동작을 구현하지 않은 매체로 검증하려는 것이다. 또한 상점·앨범·사진·알림 Element 분석은 원래 사용자가 명시적으로 요청했고, Codex는 이를 1차 제외로 판정했다. 분석했다는 사실 자체를 일관성 문제로 볼 수 없다. 보정의 여섯 속성도 PRD P0이므로 제거 확정은 불가하다.

6. **수정된 UX 제안**  
   1차는 세 묶음으로 나눈다. A는 화면 흐름과 TTFV용 연결형 Low-fi, B는 이동 영역·후보 복구·쓰다듬기·종료용 저충실도 인터랙션 시제품, C는 첫 재방문 상태 변화 이해용 분리 시나리오다. 실제 장기 재방문성은 후속 종단 검증으로 남긴다. 보정은 대표적인 형태·색/무늬 조정만으로 정신 모델을 먼저 보고 여섯 속성 전체는 후속 검증한다. 저장은 사진 확정, 후보 확정, 공간 확정 같은 마일스톤만 UX 수준에서 정의한다. P1 기능은 현재 문서상 흐름만 보존하고 1차 시제품에는 넣지 않는다.

7. **실제 행동 흐름의 개선**  
   참가자는 정적 그림을 보고 제스처를 이해했다고 말하는 대신 실제로 조작한다. 팀은 한 시제품에 모든 기능을 넣지 않고 핵심 실패를 분리해 찾으며, 제품 범위를 지키면서도 1차 검증 시간을 줄인다.

## 2.20 다중 반려동물, 비애도 사용자, 로그인 후행

1. **Claude의 주장 요약**  
   단일 반려동물 전제가 암묵적이므로 스코프를 명시해야 한다. 살아 있는 반려동물이나 호기심 사용자의 톤도 검증해야 한다. 첫 가치 우선 원칙을 로그인에는 적용하지 않아 후행 인증 검토가 빠졌다.

2. **판단: 다중 반려동물은 부분 수용, 비애도 대상 확대와 로그인 후행은 반대**

3. **UX 근거**  
   다중 반려동물 지원 여부는 계정·Home·공간·생성 재사용 흐름을 크게 바꾸므로 암묵적으로 두면 안 된다. 반면 핵심 대상과 로그인 위치는 정보 구조보다 상위 제품 결정이며, 이번 UX 토론에서 임의로 확장하면 검증 대상이 흐려진다.

4. **기존 Codex 제안의 문제**  
   계정당 한 마리라는 가정을 명시하지 않아 이후 추가 등록과 Home 전환 가능성을 독자가 판단할 수 없었다. ‘첫 가치 전 관문 최소화’ 원칙의 예외가 로그인이라는 점도 설명하지 않았다.

5. **Claude 주장 자체의 문제**

6. **수정된 UX 제안**  
   이번 신규 Flow는 단일 반려동물 등록을 기준으로 유지하되 계정당 등록 수와 추가 등록 시점을 사용자 결정 목록에 올린다. 비애도 사용자는 이번 Low-fi 표본과 카피 기준에 포함하지 않는다. 로그인 첫 화면은 유지하고, 세 방식의 실패·취소·재시도만 검증한다. 제품 결정이 바뀔 때만 게스트 체험이나 후행 인증을 별도 재검토한다.

7. **실제 행동 흐름의 개선**  
   현재 핵심 사용자의 민감한 맥락과 확정된 진입 구조를 흔들지 않으면서, 향후 구조를 크게 바꿀 다중 반려동물 문제만 명시적으로 남긴다. 이번 검증 결과가 서로 다른 타깃의 반응으로 희석되지 않는다.

## 2.21 위험 등급과 Claude의 P0/P1/P2 분류

1. **Claude의 주장 요약**  
   이동 영역, 사진 적합성, 첫 만남 인터럽트, 빈 탭, 확대 탭 거부를 P0 위험으로 두고, 문답·후보·급식·발견성·병렬화·Low-fi 매체를 P1, 나머지를 P2로 분류했다.

2. **판단: 부분 수용**

3. **UX 근거**  
   이동 영역 실패, 늦은 사진 실패, 첫 만남 유실은 실제로 첫 가치 도달을 막거나 큰 정서적 손실을 만들 수 있어 가장 먼저 검증해야 한다. 확대 입력과 Home 발견성도 가치 B 도달에 직접 영향을 준다.

4. **기존 Codex 제안의 문제**  
   위험을 순위만 매겨 빈도와 심각도, 복구 가능성을 분리하지 않았다. 사진 적합성과 외부 인터럽트를 위험 목록에 넣지 않았고, Home 첫 무효 입력을 관찰 항목으로 만들지 않았다.

5. **Claude 주장 자체의 문제**  
   제품 우선순위 P0/P1/P2와 UX 위험 등급 P0/P1/P2를 같은 표기로 사용하면 PRD 우선순위와 혼동된다. 빈 탭 한 번의 무반응이 항상 전체 발견 설계를 무너뜨린다고 단정하기도 어렵다. 아직 사용자 관찰 없이 위험 순위를 확정할 수 없다.

6. **수정된 UX 제안**  
   UX 위험은 `차단 여부`, `정서적 손실`, `발생 가능성`, `복구 비용` 네 축으로 기록한다. 1차 최우선 검증은 사진 적합성, 후보 불만족 복구, 이동 영역 첫 시도, 첫 만남 인터럽트, 첫 개인화 쓰다듬기다. Home 빈 탭과 급식 반응은 같은 인터랙션 시제품 안에서 함께 관찰한다.

7. **실제 행동 흐름의 개선**  
   팀은 PRD 기능 우선순위와 사용 실패 위험을 혼동하지 않고, 사용자에게 회복 불가능한 손실을 주는 지점부터 고친다. 실제 관찰 후 완화 순서를 바꿀 수 있다.

# 4. TTFV 재측정

## 4.1 측정 단위

Claude의 단계 수 문제 제기는 맞지만, 앞으로는 다음을 분리한다.

| 지표 | 정의 |
|---|---|
| TTFV-A | 앱 실행부터 실제 공간 속 캐릭터를 처음 보는 시점까지의 실제 시간 |
| TTFV-B | 앱 실행부터 선호 쓰다듬기 부위의 개인화 반응을 처음 확인할 때까지의 실제 시간 |
| 필수 전이 단계 | 최단 경로에서 사용자가 선택·확정·조작해야 하거나 가치 도착점으로 통과하는 상태. 첫 만남은 도착 상태로 포함 |
| 필수 입력 | 탭·선택·입력·제스처의 최소 횟수 |
| 재작업 | 뒤로가기, 수정, 실패 후 재시도의 횟수와 시간 |

앱 실행과 자동 로딩은 상태지만 사용자 결정은 아니다. 생성 대기는 초 단위 TTFV에는 포함하되 필수 전이 단계 수에는 넣지 않는다. 선택적 동영상·추가 사진·보정은 최단 경로에는 넣지 않고 분기 비용으로 별도 기록한다.

## 4.2 같은 단위로 센 필수 전이 단계

아래 수치는 구현 결과가 아니라 문서 흐름을 동일 기준으로 다시 센 설계 가설이다. 로그인하지 않은 신규 사용자의 최단 경로를 기준으로 한다.

| 현재 USER_FLOW | 로그인 → 종 → 이름·성별 → 사진 → 영상 진행/건너뜀 → Q1 → Q2 → Q3 → Q4 → Q5 → Q6 → 후보 확정 → 공간 사진 → 이동 영역 → 기본 오브젝트 → 첫 만남 | **16** | 추가 사진·동영상 업로드·보정 분기 시 17~19 이상 |
| 기존 Codex안 | 로그인 → 통합 기본 정보 → 통합 자료 → Q1~Q6 → 후보 확정 → 공간 사진 → 이동 영역 → 첫 만남 | **13** | Q를 각 한 단계로 셈. 생성 대기는 실제 시간에만 포함 |
| Claude안 | 로그인 → 통합 기본 정보 → 통합 자료 → Q1 → 후보 확정 → 공간 사진 → 이동 영역 → 첫 만남 | **8** | Q2~6 전부 첫 쓰다듬기 뒤 |
| 수정 Codex안 | 로그인 → 통합 기본 정보 → 사진 적합성·확정 → Q1 → 후보 확정 → 공간 사진 → 이동 영역 → 첫 만남 | **8** | Q2~6은 실제 생성 대기 중 선택 가능하나 다음 단계 전이를 막지 않음 |

Claude의 `15~18 → 12~13 → 7~8`은 방향상 타당하다. 다만 위처럼 포함 단위를 고정하면 최단 필수 전이 경로는 `16 → 13 → 8`로 재현된다. 이는 실제 초 단위 성과가 아니다.

## 4.3 가치 B까지 추가되는 행동

첫 만남 뒤 Home에 들어온 것만으로 개인화가 확인되지는 않는다. 가치 B까지는 최소한 다음이 더 필요하다.

1. 캐릭터를 유효하게 탭해 확대한다.
2. 선호 부위를 문지르거나 접근성 대체 입력으로 접촉한다.
3. 하트와 차별화된 긍정 반응을 확인한다.

따라서 Low-fi는 TTFV-A에서 멈추지 않고 TTFV-B까지 측정해야 한다. 첫 만남의 마지막 자세가 캐릭터 접촉을 쉽게 만드는지, 안내 없이 첫 입력을 시작하는지, 단순 탭 뒤 문지르기로 이어지는지를 관찰한다.

| 구간 | 발생 가능성 가설 | 발생 시 손실 | 복구 비용 | 1차 검증 우선도 |
|---|---|---|---|---|
| 사진 적합성 실패 | 중~높음 | 높음 | 높음 | 최우선 |

| 첫 만남 인터럽트 | 낮음~중간 | 매우 높음 | 매우 높음 | 최우선 시나리오 |

# 6. 수정된 오류·복구·뒤로가기 원칙

## 6.1 기술 실패와 품질 실패를 분리한다

- 기술 실패: 권한, 네트워크, 파일 손상, 생성 요청 실패, 저장 실패.
- 품질 위험: 피사체가 너무 작음, 여러 피사체, 심한 가림, 생성 결과 불만족.
- 정서적 중단: 후보를 더 보고 싶지 않음, 식사·배변 질문을 지금 답하기 어려움, 첫 만남을 조용히 보고 종료하고 싶음.

세 범주는 서로 다른 복구가 필요하다. 기술 실패는 실패 범위만 재시도하고, 품질 위험은 원인 가까이서 자료를 보완하며, 정서적 중단은 이유를 묻지 않고 저장 후 나갈 수 있어야 한다.

## 6.2 수정이 진행 중 생성에 미치는 영향

| 수정 대상 | 영향 | 복구 원칙 |
|---|---|---|
| 종 | 문답 4와 종 종속 생성 입력 | 영향받는 항목만 재확인, 새 생성 성공 전 기존 결과 보존 |
| 이름 | 표시 문구 | 생성 외형을 다시 만들 필요가 없으면 즉시 반영 |
| 성별 | 영향 정책 미확정 | 실제 생성 입력 여부가 정해질 때까지 전체 무효화를 가정하지 않음 |
| 주 사진·피사체 | 외형 생성 핵심 입력 | 새 작업 버전 시작, 이전 후보 보존 |
| 추가 사진·동영상 | 생성 보조 입력 | 새 결과가 필요한지 먼저 알리고 사용자 확정 뒤 시작 |
| Q1 | 첫 쓰다듬기 반응 | 아직 첫 교감 전이면 즉시 반영, 이후에도 수정 가능 |
| Q2~6 | 생활 행동 | 후보 외형을 무효화하지 않고 행동 설정만 갱신하는 방향 우선 |

## 6.3 첫 만남 복구

- 핵심 장면과 시스템 문구가 foreground에서 모두 보이기 전에는 완료 처리하지 않는다.
- 중단 복귀는 자동 반복 재생 기능이 아니라 미완료 상태 복구다.
- 완료 후 수동 다시보기는 별도 기능이며 현재 미확정이다.
- 렌더링 실패 시 빈 Home으로 보내지 않고, 안전한 재시도 또는 이전 확정 상태로 돌아간다.

## 6.4 Home의 실패 아닌 상태

- 빈 공간 탭은 오류가 아니다.
- 배고프지 않아 먹지 않는 것도 오류가 아니다. 다만 첫 급식 조작의 인지는 보장한다.
- 말풍선이나 배변 흔적이 없는 상태는 정상이다.
- 비선호 부위 접촉도 실패가 아니다. 하트 대신 편안한 시선·미세한 몸짓처럼 수용 반응을 주되 벌점과 거부 반응은 만들지 않는다.

# 7. Low-fi 1차 검증 범위 재조정

## 7.1 흐름 검증용 Low-fi

반드시 포함할 차단 흐름은 다음과 같다.

1. 로그인 3방식의 진입·취소·실패·재시도
2. 종·이름·성별 통합 입력과 종 변경 영향
3. 사진 추가, 최소 적합성 신호, 교체·추가·보류
4. Q1 선행과 Q2~6 비차단 제안
5. 생성의 사실 기반 상태와 입력 수정 시 작업 갱신
6. 후보 선택·확정·불만족·정서적 나가기
7. 공간 사진과 이동 영역
8. 첫 만남과 Home 전환
9. 첫 쓰다듬기 개인화 반응
10. 첫 생활 오브젝트 한 가지의 발견

## 7.2 인터랙션 검증용 저충실도 시제품

정적 화면만으로 판정하지 않을 항목은 다음과 같다.

- 자동 제안 후 타일 교정 대 직접 타일 토글
- 같은 타일 재탭으로 제외하는 방식의 이해
- 후보 카드 선택, 요청 시 원본 참조, 불만족 복구
- 캐릭터 탭, 확대, 접촉, 문지르기·누르기·반복 탭
- 명시적 닫기와 시스템 뒤로가기
- 빈 배경 탭, 말풍선 터치 통과
- 밥그릇 첫 탭의 인지 반응
- 드래그와 위치 탭을 통한 첫 오브젝트 배치

## 7.3 분리 시나리오

- 첫 만남 도중 전화·알림·백그라운드 전환 후 복구
- 첫 재방문에서 현재 장면 변화와 캐릭터 찾기
- 문답 3·5를 답하기 어려워하는 상황
- 적합한 사진이 없는 상황
- 후보가 닮지 않거나 더 보기 불편한 상황

재방문 시뮬레이션은 “상태가 달라졌음을 이해하는가”만 검증한다. 실제로 다시 방문하고 싶어지는지는 후속 종단 테스트가 필요하다.

## 7.4 이번 1차에서 제외할 것

- 상점, 결제, 재화
- 함께한 날의 정보 구조
- 앨범 전체 구조
- 추억 사진의 저장·공유 확장
- 알림 옵트인 시점과 빈도
- 꾸미기 전체 편집기
- 다중 반려동물 추가·전환
- 완료 후 첫 만남 수동 다시보기
- 보정 여섯 속성 전체의 세부 조작

P1 기능은 존재 위치와 핵심 기능 무료 원칙만 문서 수준에서 유지하고, 이번 1차 TTFV·핵심 교감 검증에 넣지 않는다.

# 8. Claude가 잘못 이해했거나 제품 문서와 충돌한 지점

## 8.1 ‘12번째 축이 전부 누락’이라는 형식적 주장

사용자가 요청한 형식은 11개 항목이며, 11번 안에 존재 필요성과 대체 가능성이 함께 있었다. Claude의 번호 체계는 uxconfirm 기준을 새로 적용한 것이다. 그러나 Codex가 두 번째 질문을 충분히 답하지 못했다는 실질 비판은 수용한다.

## 8.2 성별 필수 해제

성별은 현재 `PRD.md` P0 기본 정보다. 영향이 불명확한 것은 제품 결정 문제지만, 이 응답에서 임의로 선택 입력으로 바꿀 수 없다.

## 8.3 재방문 이해를 두 번째 방문으로 미뤘다는 해석

기존 Codex안의 1차 수단은 첫 재방문부터 달라진 현재 장면을 보여주는 것이었다. 두 번째 방문 이후로 미룬 것은 설명 문구라는 백업뿐이다. Claude는 이 1차 수단을 충분히 반영하지 않았다. 다만 첫 프레임 가시성 규칙이 부족했다는 비판은 수용한다.

## 8.4 첫 만남 복구와 수동 다시보기의 동일시

중단돼 완료하지 못한 장면을 복구하는 것과 완료한 장면을 사용자가 다시 재생하는 것은 다른 상태다. 전자는 P0 복구 규칙으로 필요하지만 후자는 제품 범위 결정이다.

## 8.5 비애도 사용자를 확장 대상으로 보는 주장

현재 PRD는 반려동물과 이별한 보호자를 핵심 대상으로 명시한다. 장기 철학이 ‘추모 화면’보다 ‘다시 함께하는 일상’을 지향한다는 사실이 곧 타깃 확장을 의미하지 않는다.

## 8.6 로그인 후행

로그인 첫 화면과 별도 소개 화면 없음은 `CURRENT_STATE.md`의 최신 확정 결정이다. 첫 가치 우선이라는 원칙에도 상위 제품 결정이라는 명시적 예외가 있다. 인증 위치를 바꾸는 안은 이번 UX 토론에서 채택하지 않는다.

## 8.7 P1 Element를 분석한 것이 불필요했다는 주장

사용자가 상점·앨범·추억 사진·알림을 개별 검토하고 1차 범위를 나누라고 명시했기 때문에 최소 Element 분석은 필요했다. 다만 정책이 없는 세부 흐름을 11개 슬롯으로 길게 전개한 것은 과했으며, 이번 응답에서는 1차 제외 판단까지만 유지한다.

# 9. 아직 사용자 결정이 필요한 쟁점

이 문서는 아래 항목을 확정하지 않는다.

## 9.1 문답의 위치와 입력 정책

- 기존처럼 Q1~Q6 전부 첫 만남 전에 둘지
- Claude안처럼 Q1만 선행하고 Q2~Q6을 전부 첫 교감 뒤에 둘지
- Codex 수정안처럼 Q1만 차단하고 Q2~Q6은 실제 생성 대기 중 선택적으로 받되 미응답만 첫 교감 뒤로 넘길지
- Q2~Q6 단일 선택 후 자동 진행을 기본으로 할지
- 문답 3·5에 `잘 모르겠다`, `지금 답하기 어렵다`, `나중에 답하기` 중 어떤 정책을 둘지
- Q2~Q6이 외형 후보 생성에도 필요한지, 아니면 생활 행동 설정에만 쓰이는지

## 9.2 이동 영역의 근본 조작

- 시스템 바닥 추정의 실제 신뢰도가 충분한지
- 제안 후 큰 타일 교정을 기준안으로 할지
- 자동 추정 없이 큰 타일 직접 토글을 기준안으로 할지
- 작은 공간 확인을 위한 제한적 확대가 필요한지
- 유효 영역의 제품·기술 기준이 무엇인지

## 9.3 오브젝트와 첫 만남

- 오브젝트 없이 첫 만남을 렌더링할 수 있는지
- 불가능하다면 임시 자동 배치를 허용할지
- 첫 쓰다듬기 뒤 밥그릇 한 개부터 배치하는 흐름을 P0 오브젝트 배치 충족으로 볼지
- 나머지 잠자리·장난감을 언제 배치할지

## 9.4 생성·후보·보정

- 실제 생성 시간대와 병렬 문답이 유용해지는 기준
- 원본 사진을 요청 시만 보여줄지, 집중 비교 상태를 둘지
- 같은 입력 재생성 전에 방향 선택을 받을지
- 보정 여섯 속성 중 1차 검증에 사용할 대표 속성
- 후보를 숨긴 뒤 재진입할 때의 안전한 기본 상태

## 9.5 첫 만남과 Home

- 첫 만남 완료 후 수동 다시보기 기능을 둘지
- P0 첫 사용 튜토리얼을 상황형 안내의 합으로 정의할지
- 첫 Home 힌트 트리거의 시간·무효 탭 기준
- 접근성용 쓰다듬기를 짧게 누르기, 반복 탭 중 무엇으로 제공할지
- 첫 재방문에 원리 설명 문구를 한 번 보조할지

## 9.6 제품 스코프

- 성별이 외형·행동·호칭 중 어디에 실제로 쓰이는지
- 계정당 반려동물 수와 추가 등록 시점
- 이동 영역 자동 추정, 크롭, 다중 피사체 선택의 기술 범위
- Low-fi 1차를 연결형 흐름과 인터랙션 시제품으로 분리할지

# Claude 의견 중 수용하는 것

- 화면 병합만으로는 충분하지 않으며 필수 행동 수와 조작 문법 수를 줄여야 한다.
- 기존 Element Flow가 대체 조작을 충분히 검토하지 못했다.
- 문답 6개 전체를 첫 만남의 필수 관문으로 둔 것은 가장 큰 병목이다.
- Q1과 Q2~6의 입력 특성을 구분하고 불필요한 `다음` 탭을 줄여야 한다.
- 문답 3·5의 정서적 안전성과 답변 유예를 검토해야 한다.
- 후보 복구를 네 개의 대등한 선택으로 보여주지 말고 주 경로와 보조 경로로 계층화해야 한다.
- 원본 참조, 반복 재생성의 퇴로, 정서적으로 불편한 후보를 그만 보는 흐름이 필요하다.
- 자유 브러시와 다수 편집 도구를 기본안으로 삼은 것은 과도했다.
- 별도 미리보기 모드보다 편집 중 결과 예측이 계속 가능해야 한다.
- 오브젝트 배치는 첫 만남 전 관문에서 빼야 한다.
- TTFV를 가치 A와 B로 나누고 실제 시간·차단 단계·필수 입력을 측정해야 한다.
- Home의 망설임 트리거, 빈 탭, 첫 급식 반응을 명시해야 한다.
- 말풍선은 캐릭터 접촉을 방해하는 탭 대상이 되어서는 안 된다.
- 확대 종료는 명시적 방법을 1차로 보장해야 한다.
- 첫 재방문 첫 프레임에서 캐릭터가 보이거나 즉시 찾을 수 있어야 한다.
- 업로드 직후 사진 적합성을 확인하고, 적합한 사진이 없는 경로를 제공해야 한다.
- 정밀 연속 제스처 외의 접근성 대안을 제공해야 한다.
- 첫 만남 중 외부 인터럽트를 별도 복구 시나리오로 정의해야 한다.
- Low-fi 1차는 흐름 검증과 실제 제스처 검증을 가설별로 분리해야 한다.
- 보정 6속성 전체와 세밀한 저장 단위는 1차 검증에 과하다.

# Claude 의견 중 반대하는 것

- ‘12번째 축이 53개 Element에서 전부 빠졌다’는 형식적 판정에는 반대한다. 원 요청은 11개 항목이고 대체 가능성은 11번의 하위 질문이었다. 다만 실질 검토 부족은 수용한다.
- 성별을 이 문서에서 P0 필수에서 내리는 데 반대한다. 현재 PRD 범위를 바꾸는 결정이다.
- Q2~6을 전부 첫 쓰다듬기 뒤로 고정하는 것에는 반대한다. 실제 생성 대기 중 비차단 선택을 허용하는 제3안이 대기 활용과 첫 행동 개인화를 함께 지킨다.
- 이동 영역에서 확대를 무조건 제거하는 데 반대한다. 제스처 충돌은 없애야 하지만 작은 화면과 접근성을 검증한 뒤 제한적 확대 필요성을 판단해야 한다.
- 첫 만남 전 오브젝트를 조용히 자동 배치하는 것을 기본안으로 확정하는 데 반대한다. 실제 공간에서 부자연스러운 배치는 핵심 가치를 훼손할 수 있다.
- 모든 빈 배경 탭에 캐릭터가 탭 위치를 바라보게 하는 데 반대한다. 자율적 생활 대신 바닥 탭 명령이라는 잘못된 규칙을 학습시킬 수 있다.
- 확대 상태의 단일 탭을 문지르기와 완전히 같은 개인화 성공으로 처리하는 데 반대한다. 탭은 접촉으로 인정하되 본 쓰다듬기의 입력 의미는 유지한다.
- Codex가 재접속 연속성 이해를 두 번째 방문으로 미뤘다는 해석에 반대한다. 기존 1차 수단은 첫 재방문의 달라진 현재 장면이었다.
- 미완료 첫 만남 복구와 완료 후 수동 다시보기가 모순이라는 해석에 반대한다. 두 상태는 분리해야 한다.
- 비애도 사용자를 이번 핵심 타깃으로 확장하는 데 반대한다. 현재 PRD와 충돌한다.
- 로그인 후행을 이번 수정안에 포함하는 데 반대한다. 로그인 첫 화면은 최신 확정 결정이다.
- P1 Element를 분석했다는 사실 자체가 불필요했다는 주장에 반대한다. 사용자가 명시적으로 검토를 요청했으며, 문제는 분석의 세부 정도였다.

# Codex가 수정해서 제안하는 UX 구조

아래는 최종 합의안이 아니라 Claude 비판을 반영해 다시 세운 우선 제안 구조다.

1. **앱 실행 → 로그인**  
   최신 확정안대로 로그인 버튼 3개를 유지한다. 실패·취소·재시도에서 입력과 등록 상태를 잃지 않는다.

2. **통합 기본 정보**  
   강아지/고양이, 이름, 성별을 한 단계에서 입력한다. 종 변경은 종별 질문과 예시에만 즉시 반영한다. 성별의 실제 용도는 제품 결정으로 남긴다.

3. **사진 추가 → 즉시 적합성 확인 → 사용자 확정**  
   사진·추가 사진·P1 동영상은 같은 자료 단계 안에 둔다. 파일 성공과 생성 적합성을 구분하고, 문제가 있으면 생성 전에 추가·교체·보류할 수 있다. 사용자가 사진을 확정한 뒤에만 생성 작업을 시작한다.

4. **Q1 선행, Q2~Q6 비차단 점진 보정**  
   첫 개인화 쓰다듬기에 필요한 Q1만 첫 만남 전 필수로 받는다. Q2~Q6은 실제 생성 대기가 있을 때 선택적으로 제안하지만 후보 준비와 첫 만남을 막지 않는다. 미응답은 첫 교감 뒤에 이어서 답할 수 있다. Q3·Q5는 답하기 어려운 사용자가 벌점 없이 유예할 수 있어야 한다.

5. **후보 준비 → 선택 → 원인별 안전한 복구**  
   후보 선택과 확정을 주 과업으로 둔다. 불만족이면 `다시 준비하기` 하나에서 사진 보완·기본 정보 확인·새 후보를 보조 경로로 연다. 선택 후보가 가까울 때만 보정에 들어간다. 기존 결과는 새 결과가 성공할 때까지 보존하고, 불편하면 이유를 묻지 않고 숨기고 나갈 수 있다.

6. **실제 공간 사진 → 이동 영역의 쉬운 지정**  
   자유 브러시는 기본안에서 내린다. 시스템 제안 후 큰 타일 교정을 우선 시험하고, 신뢰도가 부족하면 큰 타일 직접 토글을 사용한다. 별도 지우개와 미리보기 모드는 제거하고, 같은 타일 재탭으로 제외하며 결과 예측 단서를 편집 중 계속 보여준다.

7. **첫 만남 → Home**  
   첫 만남 전 오브젝트 배치 관문을 없앤다. 핵심 장면은 foreground에서 실제로 보여준 뒤에만 완료한다. 중단되면 미완료 상태를 복구하고, 완료 뒤 수동 다시보기는 별도 결정으로 남긴다.

8. **첫 개인화 교감 보장**  
   첫 만남 뒤 캐릭터를 쉽게 탭할 수 있는 상태를 만든다. 탭은 접촉 반응, 문지르기·짧게 누르기·반복 탭은 쓰다듬기로 인정한다. 선호 부위에만 하트와 더 분명한 긍정 반응을 주고, 비선호 부위도 편안하게 수용한다. 명시적 닫기로 기본 시점에 복귀한다.

9. **첫 생활 오브젝트를 맥락 속에서 발견**  
   첫 교감 뒤 밥그릇 하나부터 배치하거나 상호작용하게 한다. 첫 급식은 배고픔과 무관하게 조작 인지 반응을 보장하되 강제로 먹이지 않는다. 잠자리·장난감은 이후 맥락에서 점진적으로 배치한다.

10. **Home의 최소 발견성과 자율성 유지**  
    말풍선은 비상호작용 정보로 자동 소멸한다. 빈 탭은 오류도 이동 명령도 아니며, 반복 무효 입력이나 일정 시간 무입력 때만 유효 대상을 한 번 안내한다. 강제 투어 없이 첫 세션에 캐릭터와 오브젝트 한 가지를 발견할 기회를 만든다.

11. **재방문은 보고서가 아니라 달라진 현재 장면**  
    첫 재방문부터 캐릭터가 보이거나 즉시 찾을 수 있고, 이전과 다른 행동·위치·흔적 중 하나가 자연스럽게 드러난다. 이해가 약할 때만 최초 한 번의 비모달 원리 설명을 검토하며, 활동 보고서·죄책감·보상 압박은 만들지 않는다.

12. **Low-fi 1차는 핵심 가치 A와 B까지만 깊게 검증**  
    연결형 흐름에서는 로그인부터 첫 만남까지의 TTFV-A를, 인터랙션 시제품에서는 이동 영역과 첫 개인화 반응의 TTFV-B를 검증한다. 상점, 함께한 날, 앨범, 추억 사진, 알림, 꾸미기 전체, 다중 반려동물은 1차에서 제외한다.

이 수정 구조의 핵심은 화면을 더 적게 만드는 것만이 아니다. 첫 만남을 막는 필수 질문을 줄이고, 정밀 제스처를 관대한 입력으로 바꾸며, 실패를 더 일찍 발견하고, 사용자가 감정적으로 멈춰도 안전하게 돌아올 수 있게 하는 것이다. 다만 문답 위치, 이동 영역 방식, 첫 오브젝트 처리, 튜토리얼 정의는 아직 사용자 결정과 Low-fi 비교 검증이 필요하다.
