# 1. StayPet UX 핵심 원칙

1. **다시 만나는 것이 아니라 다시 함께 지내는 일상.** 추모 서비스가 아니다. 캐릭터가 실제 사망한 반려동물 본인인 것처럼 말하지 않는다.
2. **아무것도 요구하지 않는 시간을 지킨다.** 관찰은 유휴 상태가 아니라 핵심 경험이다. 감정 정점(첫 만남·첫 하트) 직후에는 어떤 과제도 자동으로 시작하지 않는다.
3. **첫 만남을 막는 필수 관문을 최소화한다.** 첫 만남 전에는 외형 생성과 실제 공간에 필요한 정보만 받는다.
4. **조작 총량을 줄인다.** 화면 수가 아니라 사용자가 배워야 할 조작 문법 수와 필수 행동 수로 평가한다.
5. **정밀 제스처를 요구하지 않는다.** 모든 핵심 조작에 관대한 대체 입력, 넓은 판정 범위, 시간 압박 없음, 중간 상태 보존을 기본으로 한다.
6. **실패는 원인 가까이에서 발견시킨다.** 늦고 비싼 실패를 이르고 값싼 수정으로 바꾼다.
7. **기술 실패 · 품질 위험 · 정서적 중단을 구분해 복구한다.**
8. **새 결과가 성공하기 전에 기존 결과를 지우지 않는다.** 뒤로가기는 삭제가 아니다.
9. **의무가 아니라 교감.** 미접속·급식·청소에 해로운 패널티가 없다. 연속 출석 압박, 질병·죽음, 죄책감 유발 표현을 만들지 않는다.
10. **숫자 상태 UI를 만들지 않는다.** 행동, 짧은 말풍선, 생활 흔적으로 표현한다.
11. **기본 교감과 기본 생활 오브젝트는 무료다.**
12. **기능은 상황 속에서 발견한다.** 기능 목록을 설명하는 투어를 만들지 않고, 관련 상황이 실제로 발생할 때 한 번씩 알린다.

# 2. 최종 신규 사용자 전체 Flow

사용자가 실제로 경험하는 순서다. `[시스템]`은 사용자 조작이 없는 단계다.

```
[시스템] 앱 실행 · 세션 분기
   ↓
로그인            일반 / Kakao / Google
   ↓
반려동물 기본 정보  종 · 이름 · 성별  (한 단계)
   ↓
사진 자료          필수 사진 + 추가 사진 + 선택 동영상
                  업로드 직후 최소 적합성 확인
                  → `이 사진으로 계속` 확정
   ↓
[시스템] 생성 시작  (사진 확정 시점)
   ↓
생활 문답 Q1       쓰다듬기 선호 부위 — 첫 만남 전 유일한 문답
   ↓
[대기 있을 때만] 생성 대기   과제 없음 · 떠날 수 있음
   ↓
캐릭터 후보 2~3개   선택 → `이 모습으로 계속`
                  └ (선택) 간단 보정
   ↓
실제 공간 사진
   ↓
이동 가능 영역      타일 토글
   ↓
첫 만남            5~10초 · 가상 오브젝트 없음
                  `{이름}가 우리 집으로 찾아왔어요.`
   ↓
Home 도착          관찰 · 완료 페이지 없음
   ↓
첫 교감            캐릭터 탭 → 확대 → 쓰다듬기 → 선호 부위 하트
   ↓
Home 관찰 복귀      ★ 여기서 어떤 과제도 자동으로 시작하지 않는다
   ↓
이후 상황형 발견     한 세션에 새 제안 최대 1개 · 답할 때까지 사라지지 않음
                  식사 상황  → 밥그릇 배치 → (다음 기회) Q3 식사 주기
                  수면 상황  → 잠자리 배치 → (다음 기회) Q6 수면양
                  놀이 상황  → 장난감 배치
                  이동 장면  → Q2 활동량
                  배변 상황  → 흔적 치우기 안내
                  Q4만 상황형에서 제외 · Q5는 배변 청소 직후 제안
```

**필수 전이 단계: 8** (로그인 → 기본 정보 → 사진 → Q1 → 후보 확정 → 공간 사진 → 이동 영역 → 첫 만남)
현행 `USER_FLOW.md` 기준 16단계에서 줄어든 값이다. 단, 이는 **설계 가설이며 실측 TTFV가 아니다**(§5 참조).

**제거된 단계** — 다시 넣지 않는다.
`추가 사진이 있나요?` 확인 화면 / 동영상 전용 독립 단계와 `건너뛰기` / 종·이름·성별 각각의 독립 화면 / 문답 완료 후 재검토 화면 / 보정의 이중 확정 / 첫 만남 전 오브젝트 배치 / 첫 만남 뒤 완료 페이지 / 전체 기능 투어 / 재방문 활동 보고서

# 3. 화면별 최종 UX

## 3.0 앱 실행 · 세션 분기 `[시스템]`

사용자 조작이 없다. 미로그인 → 로그인, 인증됐으나 등록 미완료 → 마지막 저장 지점, 설정 완료 → 경과시간 처리 후 Home. 세션 확인 실패를 신규 사용자로 오판하지 않고 재시도한다. 별도 설명 화면을 만들지 않는다.

## 3.1 로그인

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 편한 방식으로 인증하고 다음으로 간다 |
| 진입 이유 | 로그인된 세션이 없다 |
| 최초 인지 정보 | 세 가지 로그인 선택지가 있다는 것 |
| 주요 행동 | 세 방식 중 하나 선택 후 인증 완료 |
| CTA | `로그인하기` / `Kakao로 시작하기` / `Google로 시작하기` — 기본 선택 없음 |
| 즉각적 피드백 | 탭 접수, 외부 인증 전환, 앱 복귀 후 처리 상태 |
| 성공 상태 | 계정 인증 완료 및 사용자 상태 분기 |
| 다음 단계 | 신규 → 기본 정보 / 중단 → 마지막 저장 지점 / 기존 → Home |
| 뒤로가기 · 수정 | 외부 인증 취소 시 로그인 선택으로 복귀, 다른 방식 선택 가능 |
| 실패 · 복구 | 네트워크·취소·동의 거부·공급자 오류를 구분해 같은 위치에서 재시도. 기존 계정·설정 데이터를 삭제하지 않는다 |

별도 서비스 소개 슬라이드를 만들지 않는다(`CURRENT_STATE.md` 확정).

## 3.2 반려동물 기본 정보

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 만들 반려동물이 누구인지 최소 정보로 정한다 |
| 진입 이유 | 신규 인증이 끝났다 |
| 최초 인지 정보 | 강아지/고양이, 이름, 성별을 정하는 짧은 단계라는 것 |
| 주요 행동 | 종 선택 → 이름 입력 → 성별 선택 |
| CTA | 다음 단계로 가는 확정 CTA 하나 |
| 즉각적 피드백 | 각 값의 선택·입력 상태와 누락·형식 문제를 해당 항목에서 즉시 표시 |
| 성공 상태 | 세 값이 초안에 저장되고 진행 조건을 충족 |
| 다음 단계 | 사진 자료 |
| 뒤로가기 · 수정 | 이후 단계에서 돌아와 수정 가능. 종 변경 시 문답 4의 레이블·종별 예시를 즉시 갱신하고, 영향받는 기존 답이 있을 때만 재확인 요청 |
| 실패 · 복구 | 빈 이름·미선택·저장 실패를 각각 처리하고 다른 정상 입력은 보존 |

**종은 이 화면의 선행 결정이다.** 이후 문답 4(짖음/울음), 종별 대표 행동, 생성 분기의 기준이 되므로 이름·성별보다 먼저 확정되어야 한다.

## 3.3 사진 자료

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 닮은 캐릭터가 나올 자료를 제공한다 |
| 진입 이유 | 기본 정보가 준비됐고 외형 생성에 사진이 필요하다 |
| 최초 인지 정보 | 사진 추가가 이 단계의 필수 행동이라는 것 |
| 주요 행동 | 최소 1장 추가 → 적합성 확인 결과 확인 → 필요 시 추가·교체 → `이 사진으로 계속` |
| CTA | 사진 추가(보조) / `이 사진으로 계속`(주) |
| 즉각적 피드백 | 사진 단위 미리보기, 업로드 상태, 성공 시 `업로드 완료`, 적합성 점검 결과 |
| 성공 상태 | 유효 사진이 확정되고 생성 작업이 시작됨 |
| 다음 단계 | 생활 문답 Q1 |
| 뒤로가기 · 수정 | 기본 정보로 돌아가도 성공한 업로드는 보존. 각 사진을 삭제·교체 가능 |
| 실패 · 복구 | **기술 실패**(권한·형식·손상·네트워크)는 파일 단위로 재시도. **품질 위험**(반려동물 미감지·피사체 너무 작음·여러 피사체·심한 가림)은 `다른 사진 추가` / `이 사진 교체` / `나중에 계속`을 같은 자리에서 제공. 완전히 사용할 수 없는 경우만 진행 차단 |

**금지:** 품질 점수·별점 표시, 생성 품질 보장 표현, 사진이나 사용자의 기억을 평가하는 것처럼 읽히는 표현, `사진 1장만으로도 시작할 수 있어요`(`DESIGN_RULES.md` 명시 금지).
선택 동영상은 이 단계 안의 보조 행동이며, 독립 화면이나 `건너뛰기` 버튼을 만들지 않는다.

## 3.4 생활 문답 Q1

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 좋아했던 쓰다듬기 부위를 알려 반응을 개인화한다 |
| 진입 이유 | 사진이 확정됐고, 첫 교감 반응에 이 정보가 필요하다 |
| 최초 인지 정보 | 지금 묻는 질문 하나. **Q2~Q6은 여기 없다** |
| 주요 행동 | 머리 / 배 / 엉덩이 / 등 중 선택(복수 선택) 후 확인 |
| CTA | 명시적 확인 CTA 하나 |
| 즉각적 피드백 | 각 부위의 선택 상태 즉시 반영 |
| 성공 상태 | 선호 부위가 저장되어 첫 쓰다듬기 반응 조건에 연결됨 |
| 다음 단계 | 생성이 진행 중이면 대기, 이미 준비됐으면 후보 |
| 뒤로가기 · 수정 | 사진 단계로 돌아가도 답 보존. 첫 교감 전이면 언제든 수정 가능 |
| 실패 · 복구 | 저장 실패 시 화면 선택을 유지하고 재시도. 미선택 시 이 질문 안에서 안내 |

정답이 없다는 것과 어떤 답도 패널티를 만들지 않는다는 원칙은 매 질문마다 반복 설명하지 않는다.

## 3.5 생성 대기 `대기가 있을 때만`

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 입력을 잃지 않고 결과가 준비되기를 기다린다 |
| 진입 이유 | 생성 요청이 접수됐고 아직 결과가 없다 |
| 최초 인지 정보 | 요청이 정상 접수됐다는 것, **그리고 여기 머무르지 않아도 된다는 것** |
| 주요 행동 | 없음. 머무르거나 떠나는 것 모두 정상 |
| CTA | 정상 처리 중에는 없음. 실패 시 `다시 시도` |
| 즉각적 피드백 | 사실로 확인 가능한 상태만 순차 표시 (예: 사진 확인 → 특징 준비 → 후보 생성) |
| 성공 상태 | 후보 2~3개를 비교할 수 있는 상태 |
| 다음 단계 | 후보 선택 |
| 뒤로가기 · 수정 | 안전하게 나갈 수 있고, 자발적으로 돌아오면 작업 상태를 조회해 `완료` / `진행 중` / `실패` 중 해당 상태로 복원 |
| 실패 · 복구 | 생성 요청만 재시도하고 사진·문답을 유지. 반복 실패 시 사진 수정 경로 안내 |

**절대 금지**
- 가짜 진행률(%)과 근거 없는 ETA
- **대기를 과제로 채우는 것.** Q2~Q6을 여기에 넣지 않는다
- 앱 밖으로 완료를 푸시하는 것(외부 알림은 P1 옵트인이므로 이 Flow의 전제가 될 수 없다)
- 작업을 조용히 취소하고 처음부터 다시 입력하게 하는 것

요청 지속성이 기술적으로 불가능하다면 **최소한 입력을 보존하고 재시작이 필요함을 정직하게 알린다**(§13 기술 검증).

## 3.6 캐릭터 후보 선택

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 기억하는 모습과 가장 가까운 후보를 고른다 |
| 진입 이유 | 후보가 준비됐다 |
| 최초 인지 정보 | 후보를 비교할 수 있고, 고른 뒤 확정하거나 다듬을 수 있다는 것 |
| 주요 행동 | 후보 하나 선택 → `이 모습으로 계속` |
| CTA | 주: `이 모습으로 계속`. 보조: 간단 보정, `다시 준비하기`, `지금은 그만 보기` |
| 즉각적 피드백 | 현재 선택 후보를 즉시 구분 |
| 성공 상태 | 외형이 확정되어 공간 설정으로 진행 |
| 다음 단계 | 공간 사진 (보정을 선택하면 보정 상태) |
| 뒤로가기 · 수정 | 다른 카드로 자유롭게 변경. 뒤로가도 생성 결과를 파괴하지 않음 |
| 실패 · 복구 | 일부 후보 로드 실패 시 정상 후보 유지하고 실패분만 재시도. 전체 실패는 생성 재시도 |

**불만족 복구는 계층 구조다.** 네 경로를 대등하게 늘어놓지 않는다.
- 주 경로: `다시 준비하기` 하나. 열면 `사진을 더하거나 바꾸기` / `기본 정보 확인` / `같은 입력으로 새 후보 받기`를 설명과 함께 제시
- 보정: 선택한 후보가 "가깝지만 조금 다를" 때만 진입
- 원본 사진: **상시 병치하지 않고 사용자가 요청할 때만** 참조
- 반복 재생성 뒤에는 추가 사진 안내와 `나중에 계속`을 제공하며 기존 후보와 입력을 보존

**정서적 퇴로:** `지금은 그만 보기`를 결과 화면에서 즉시 사용할 수 있다. 후보를 숨기고 입력을 저장한 채 안전 지점 또는 앱 밖으로 나가며, **이유·별점·불쾌함 평가를 요구하지 않는다.** 재진입 시 기존 결과를 자동으로 크게 노출하지 않고 계속 볼지 선택하게 한다.

## 3.7 캐릭터 간단 보정 `선택 상태`

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 전반적으로 닮은 후보의 일부만 조정한다 |
| 진입 이유 | 후보는 괜찮은데 특정 특징이 다르다 |
| 최초 인지 정보 | 기준 후보와 수정 가능한 범위 |
| 주요 행동 | 속성 선택 → 값 변경 → 비교 → 확정 |
| CTA | 보정 확정 하나. **후보 화면으로 돌아가 다시 확정하는 이중 확인은 없다** |
| 즉각적 피드백 | 항목 단위로 반영 중·완료·실패 표시 |
| 성공 상태 | 보정 외형이 최종 저장 |
| 다음 단계 | 공간 사진 |
| 뒤로가기 · 수정 | 원본 복원과 직전 변경 취소를 구분. 초안 폐기 시에만 확인 |
| 실패 · 복구 | 실패한 변경만 이전값으로 복구하고 다른 성공 변경은 보존 |

모든 속성을 수정하도록 강제하지 않는다. **Low-fi 1차에서는 대표 속성 2종(형태 1, 색/무늬 1)만** 검증한다.

## 3.8 실제 공간 사진

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 캐릭터가 생활할 실제 공간 한 곳을 정한다 |
| 진입 이유 | 외형이 확정됐고 Home 배경이 필요하다 |
| 최초 인지 정보 | 공간 사진 한 장을 고르는 단계라는 것 |
| 주요 행동 | 사진 선택·업로드 후 결과 확인 |
| CTA | 업로드 → 이동 영역으로 가는 CTA |
| 즉각적 피드백 | 미리보기, 업로드 상태, 성공 시 `업로드 완료` |
| 성공 상태 | 공간 사진 저장 |
| 다음 단계 | 이동 가능 영역 |
| 뒤로가기 · 수정 | 후보로 돌아가도 공간 사진 초안 보존. **교체 전 기존 이동 영역이 무효화됨을 먼저 알린다** |
| 실패 · 복구 | 권한·형식·손상·해상도·네트워크를 구분. 확정된 캐릭터 결과는 보존 |

공간 종류를 분류시키지 않고 여러 방을 요구하지 않는다.

## 3.9 이동 가능 영역

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 캐릭터가 다닐 범위를 정한다 |
| 진입 이유 | 사진만으로는 시스템이 사용자 의도를 알 수 없다 |
| 최초 인지 정보 | "캐릭터가 다녀도 되는 바닥을 고른다"는 하나의 과업. 최초 1회 짧은 안내 |
| 주요 행동 | 타일을 탭하거나 쓸어서 켜고, 같은 타일을 다시 탭해 끈다 |
| CTA | `완료` |
| 즉각적 피드백 | 손가락을 따라 타일 상태가 지연 없이 바뀜. **선택 영역 안에 도달 예시(정적 발자국·간단한 경로 샘플)를 상시 표시** |
| 성공 상태 | 캐릭터가 움직일 수 있는 유효 면적 확보 |
| 다음 단계 | 첫 만남 |
| 뒤로가기 · 수정 | 같은 타일 재탭, 한 단계 실행 취소, 전체 초기화. 사진 단계로 돌아가도 초안 보존 |
| 실패 · 복구 | 빈 영역·너무 작은 영역은 완료 시점 전에 이유와 수정 방법을 함께 안내하고 편집 상태에 남긴다 |

**확정된 조작 규칙**
- 기준 조작은 **큰 타일 토글**이다. 자유 곡선 드로잉은 기본안에서 폐기됐다
- 같은 타일 재탭이 제외이므로 **별도 지우개 도구가 없다**
- 남는 도구는 `실행 취소(1단계)` · `전체 초기화` · `완료` 뿐이다
- **별도 미리보기 모드를 만들지 않는다.** 결과 예측은 편집 중 상시 제공한다
- 확대는 한 손가락 타일 선택과 충돌해서는 안 된다 `구체적 방식은 §9 비교 항목`
- 자동 바닥 추정이 가능하면 **일부 타일이 켜진 초기 상태**로 시작한다. 불가능하면 꺼진 상태로 시작한다. **어느 쪽이든 사용자의 조작은 동일하다**

## 3.10 첫 만남

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 선택한 캐릭터가 실제 공간에 등장하는 순간을 본다 |
| 진입 이유 | 캐릭터와 최소 공간 설정이 준비됐다 |
| 최초 인지 정보 | 캐릭터가 자신의 공간에 나타났다는 사실 |
| 주요 행동 | 없음. 5~10초를 본다 |
| CTA | 없음 |
| 즉각적 피드백 | 연속된 등장 + 시스템 문구 `{이름}가 우리 집으로 찾아왔어요.` |
| 성공 상태 | Home 자율 생활 상태로 전환. **완료 페이지 없음** |
| 다음 단계 | Home 도착 |
| 뒤로가기 · 수정 | 장면 중 뒤로가기가 설정을 되감지 않는다 |
| 실패 · 복구 | 애니메이션 실패 시 첫 만남만 재시도. 반복 실패 시 공간·캐릭터·확정 문구를 보여주는 안전한 정적 진입 |

**확정**
- **가상 생활 오브젝트를 두지 않는다.** 밥그릇·잠자리·장난감 없이 공간과 캐릭터만 등장한다
- **완료 플래그는 foreground에서 핵심 장면과 시스템 문구가 모두 표시되고 Home 전환이 끝난 뒤에만 기록**한다
- 그 전에 백그라운드로 가면 미완료다. 복귀 시 장면 시작 전이면 다시 시작, 진행 중이면 자연스러운 지점에서 재개
- 완료 뒤에는 자동 반복하지 않는다. 완료 후 수동 다시보기는 1차 범위 밖
- 멜로드라마 연출, 튜토리얼, 기능 설명, 배치 지시를 넣지 않는다

## 3.11 Home — 첫 도착

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 캐릭터를 바라보고 처음으로 교감한다 |
| 진입 이유 | 첫 만남이 자연스럽게 생활 상태로 전환됐다 |
| 최초 인지 정보 | 캐릭터의 현재 위치와 행동 |
| 주요 행동 | 없음(관찰만 해도 정상). 권장 첫 행동은 캐릭터 탭 |
| CTA | 화면 버튼이 아니라 **캐릭터 자체**가 첫 행동 대상 |
| 즉각적 피드백 | 탭 인지 → 확대 전환 → 부위 반응이 연속으로 |
| 성공 상태 | 첫 쓰다듬기에서 선호 부위 하트를 확인 = 가치 B 도달 |
| 다음 단계 | 확대 종료 후 **Home 관찰로 복귀. 여기서 어떤 과제도 자동 시작하지 않는다** |
| 뒤로가기 · 수정 | Home은 루트이므로 시스템 뒤로가기가 온보딩을 되감지 않는다 |
| 실패 · 복구 | 캐릭터 로드 실패 시 생성 결과를 삭제하지 않고 같은 Home에서 재시도. 말풍선·흔적이 없는 것은 정상 |

첫 만남 직후 캐릭터가 가까운 상태를 잠시 유지해 유효 타깃을 쉽게 만든다.

## 3.12 Home — 재방문

| 항목 | 내용 |
|---|---|
| 사용자 목표 | 지금 아이가 뭐 하고 있는지 바로 확인한다 |
| 진입 이유 | 설정 완료 후 앱을 다시 실행했다 |
| 최초 인지 정보 | 경과시간이 반영된 현재 위치·행동·생활 흔적 |
| 주요 행동 | 없음. 관찰하거나 원하는 상호작용을 고른다 |
| CTA | 없음 |
| 즉각적 피드백 | 이전 종료 시점과 달라진 현재 행동·위치·흔적 중 하나가 드러남 |
| 성공 상태 | 시간이 이어졌다고 이해하고 Home 생활로 들어감 |
| 다음 단계 | 자율 생활 관찰과 직접 교감 |
| 뒤로가기 · 수정 | Home 루트 원칙 유지 |
| 실패 · 복구 | 경과시간 계산 실패 시 부정적 상태를 만들지 않고 안전한 현재 상태로 진입 |

**확정**
- **첫 프레임에서 캐릭터가 보이거나 한 번의 명확한 단서로 즉시 찾을 수 있어야 한다**
- 활동 보고서, 과거 이벤트 목록, 미접속 시간 요약, 놓친 보상을 만들지 않는다
- 캐릭터는 사용자를 기다리는 자세가 아니라 자기 생활 중에 등장한다
- `기다렸어요`, `왜 이제 왔어요` 같은 표현 금지
- 연속성 이해가 약하다고 확인되면 **최초 재방문에 한해** 죄책감 없는 원리 설명을 한 번 비모달로 보조할 수 있다. 문구는 후속 카피 검토 대상

# 4. 핵심 Interactive Element Flow

토론에서 제거된 조작은 여기 없다. **다시 추가하지 않는다.**

### E1. 로그인 버튼 (3종 공통)
- **인지** 첫 화면의 독립 버튼 세 개
- **동기** 자신에게 익숙한 방식으로 빠르게 시작
- **기대** 인증 후 앱으로 돌아와 이어짐
- **조작** 한 번 탭 → (소셜은) 외부 계정 선택·동의
- **피드백** 탭 접수, 외부 전환, 복귀 후 처리 상태를 연속 표시
- **성공** 계정 연결 완료 및 상태 분기
- **오류** 취소·동의 거부·만료·네트워크·공급자 오류를 구분. 설정 데이터 삭제 없음
- **취소** 로그인 선택으로 복귀, 다른 방식 선택 가능
- **재조작** 처리 중 중복 인증 방지, 실패 후 재탭은 정상 재시도
- **다음** 신규 기본 정보 / 마지막 미완료 단계 / Home

### E2. 기본 정보 입력 (종 · 이름 · 성별)
- **인지** 한 화면 안의 세 항목. 종이 첫 항목
- **동기** 만들 아이가 누구인지 정한다
- **기대** 이후 단계에서 돌아와 수정 가능
- **조작** 종 탭(배타 선택) → 이름 입력 → 성별 탭
- **피드백** 각 항목의 선택·입력 상태 즉시 반영. 종을 바꾸면 문답 4 레이블과 종별 예시가 즉시 갱신
- **성공** 세 값이 초안 저장
- **오류** 빈 이름·미선택·저장 실패를 항목 위치에서 처리, 다른 입력은 보존
- **취소** 다른 값으로 교체. 키보드 완료가 화면 전체 제출로 오인되지 않게 함
- **재조작** 같은 값 재탭은 유지, 다른 값은 대체
- **다음** 사진 자료

### E3. 사진 추가 · 교체 · 삭제
- **인지** 빈 자료 상태와 명시적 추가 행동
- **동기** 닮은 결과가 나올 참고 자료 제공
- **기대** 업로드된 사진이 외형 생성에 쓰인다
- **조작** 추가 탭 → 기기에서 선택. 각 사진에 삭제·교체
- **피드백** 로컬 미리보기, 파일별 업로드 진행, 성공 시 `업로드 완료`, 적합성 점검 결과
- **성공** 유효 사진이 목록에 남고 진행 조건 충족
- **오류** 기술 실패는 파일 단위 재시도(성공 파일 유지). 품질 위험은 추가·교체·보류 제공
- **취소** 선택 취소 시 기존 목록 유지. 삭제 직후 되돌리기 제공. **마지막 유효 사진 삭제 시 진행 조건을 먼저 알린다**
- **재조작** 재탭은 추가. 교체 실패 시 기존 사진 유지
- **다음** 자료 편집 계속 또는 `이 사진으로 계속`

### E4. `이 사진으로 계속` (생성 커밋)
- **인지** 자료 단계를 마치는 주 CTA
- **동기** 자료가 준비됐고 결과를 보고 싶다
- **기대** 이 사진으로 캐릭터가 만들어지기 시작한다
- **조작** 한 번 탭
- **피드백** 확정과 생성 시작을 알림
- **성공** 생성 작업 버전 1 시작
- **오류** 저장·요청 실패 시 값을 유지한 채 재시도
- **취소** 이후 종·주 사진·피사체를 바꾸면 진행 중 작업을 **조용히 버리지 않고** "새 입력으로 다시 준비됨"을 알리고 새 버전을 시작. 완료된 이전 후보는 새 결과 성공 전까지 보존
- **재조작** 중복 생성 요청 방지
- **다음** 생활 문답 Q1

### E5. Q1 선택지 (머리 / 배 / 엉덩이 / 등)
- **인지** 네 부위가 각각 선택 가능하며 여러 개를 고를 수 있다는 것을 선택 전에 인지
- **동기** 실제로 좋아했던 부위를 반응에 반영
- **기대** 고른 부위를 문지르면 다른 부위보다 반응이 분명해진다
- **조작** 복수 선택(각 부위를 켜고 끔) 후 명시적 확인
- **피드백** 각 부위의 현재 선택 상태 즉시 표시
- **성공** 선호 영역이 저장되어 첫 쓰다듬기 반응 조건에 연결
- **오류** 저장 실패 시 화면 선택 유지. 미선택 시 이 질문 안에서 안내
- **취소** 재탭으로 개별 해제. 첫 교감 전이면 언제든 수정
- **재조작** 재탭 = 해제
- **다음** 생성 대기 또는 후보

### E6. 생성 대기에서 나가기
- **인지** 이 화면에 머무르지 않아도 된다는 것을 대기 중에 알 수 있어야 함
- **동기** 기다리는 동안 다른 일을 하거나 앱을 닫고 싶다
- **기대** 떠나도 지금까지의 입력과 작업이 사라지지 않는다
- **조작** 안전한 이전 상태로 이동하거나 앱을 닫음
- **피드백** 나가도 괜찮다는 사실을 명확히. 불안을 만드는 경고를 띄우지 않음
- **성공** 자발적으로 돌아왔을 때 `완료` / `진행 중` / `실패` 중 해당 상태로 복원
- **오류** 요청 지속이 불가능하면 **입력을 보존하고 재시작이 필요함을 정직하게 알린다**. 조용히 취소하지 않는다
- **취소** 해당 없음 — 나가는 것 자체가 취소가 아니다
- **재조작** 재진입할 때마다 동일하게 상태 조회
- **다음** 후보 또는 같은 대기 상태

### E7. 후보 카드 · `이 모습으로 계속`
- **인지** 2~3개가 비교 가능한 묶음이고 카드 전체가 탭 대상
- **동기** 기억에 가장 가까운 후보를 고른다
- **기대** 탭은 선택일 뿐 즉시 확정이 아니다
- **조작** 카드 탭으로 선택 → `이 모습으로 계속` 탭으로 확정
- **피드백** 현재 선택 후보를 즉시 구분
- **성공** 외형이 최종 저장
- **오류** 일부 후보 로드 실패 시 그 후보만 재시도, 나머지 보존
- **취소** 확정 전 자유롭게 변경. 뒤로가도 결과 파괴 없음
- **재조작** 선택 카드 재탭을 중복 확정으로 처리하지 않음. 저장 중 중복 요청 방지
- **다음** 공간 사진 또는 보정

### E8. `다시 준비하기`
- **인지** 확정과 구분된 보조 행동
- **동기** 만족할 후보가 없다
- **기대** 지금 후보가 사라지지 않는다
- **조작** 탭하면 `사진을 더하거나 바꾸기` / `기본 정보 확인` / `같은 입력으로 새 후보 받기`가 설명과 함께 열림
- **피드백** 어떤 입력으로 새 생성이 시작됐는지 알리고 기존 후보를 안전 상태로 보존
- **성공** 새 후보 세트를 비교 가능
- **오류** 새 생성 실패 시 기존 후보 복원. 기술 실패를 재생성 횟수로 세지 않음
- **취소** 취소 시 기존 후보로 복귀
- **재조작** 생성 중 중복 요청 차단. **반복 후에는 추가 사진 안내와 `나중에 계속`을 함께 제공**
- **다음** 새 후보 또는 선택한 입력 수정 단계

> **원인 진단을 먼저 요구하지 않는다.** 사용자가 왜 안 닮았는지 몰라도 한 단계 진행할 수 있어야 한다.

### E9. 이동 영역 타일 토글
- **인지** 기본 활성화된 단일 조작 + 최초 1회 짧은 과업 안내
- **동기** 아이가 다닐 수 있는 바닥을 정한다
- **기대** 고른 범위 안에서 캐릭터가 움직인다
- **조작** 타일 탭 또는 쓸기로 켜기, 같은 타일 재탭으로 끄기
- **피드백** 지연 없는 상태 변화 + 선택 영역 안의 도달 예시 상시 표시
- **성공** 유효 면적 확보
- **오류** 빈 영역·너무 작은 영역은 완료 전에 이유와 수정 방법을 함께 안내
- **취소** 재탭 · 1단계 실행 취소 · 전체 초기화. 뒤로가도 초안 보존
- **재조작** 반복 토글이 누적 왜곡을 만들지 않음
- **다음** `완료` → 첫 만남

> **없는 것:** 자유 곡선 브러시, 별도 지우개, 다시 실행, 별도 미리보기 모드.

### E10. 캐릭터 탭 → 확대
- **인지** 움직이는 대상 자체. 첫 만남 직후 가까운 상태를 잠시 유지해 타깃을 쉽게 만듦
- **동기** 가까이 보고 만지고 싶다
- **기대** 캐릭터가 알아차리고 가까운 상태로 전환
- **조작** 한 번 탭. **이동 중에도 접촉 실패가 과도하지 않도록 판정 범위를 관대하게**
- **피드백** 시선·작은 몸짓으로 탭을 인지한 뒤 확대 시작
- **성공** 부위를 만질 수 있는 확대 상태
- **오류** 로드 실패 시 Home 상태를 보존해 재시도. 빗나간 탭은 E14 규칙을 따름
- **취소** 전환 중 뒤로가면 기본 시점 유지, 생활 상태 불변
- **재조작** 전환 중 중복 확대 방지
- **다음** 쓰다듬기 또는 기본 시점 복귀

### E11. 쓰다듬기
- **인지** 첫 확대 때 한 번만 문지르는 방법을 알림
- **동기** 직접 교감하고 기억한 선호가 반영됐는지 확인
- **기대** 문지른 부위에 즉시 반응, 선호 부위에서 더 분명한 긍정 반응
- **조작 (3계층 — 확정)**
  - `탭` = **짧은 접촉.** 실패가 아니며 캐릭터의 미세한 인지 반응을 준다
  - `문지르기(실제 드래그)` = **본 쓰다듬기** — 유일한 조건이다
  - **선호 부위에서 본 쓰다듬기가 일어날 때만 하트와 분명한 긍정 반응**
- **피드백** 모든 유효 접촉에 즉시 반응. 반응 과잉은 제한
- **성공** 개인화가 실제 반응에 적용됐음을 체감 = 가치 B
- **오류** 입력을 실패로 표시하지 않는다. 안내를 반복하지 않는다
- **취소** 손을 떼면 현재 문지르기만 끝나고 확대는 유지. 잠시 멈추거나 다른 부위를 이어 만질 수 있음
- **재조작** 반복 가능하되 **점수·친밀도 수치·콤보·누적 경쟁을 만들지 않는다**
- **다음** 계속 교감 또는 기본 시점 복귀

**비선호 부위:** 오답이 아니다. 시선·깜박임·작은 몸짓 같은 중립적 수용 반응을 주고 하트만 생략한다. 화내기·밀어내기·도망·실패 문구·친밀도 감소를 만들지 않는다.

### E12. 확대 종료 / 기본 시점 복귀
- **인지** 확대 상태에서 항상 같은 자리에 있는 명시적 종료 수단
- **동기** Home 관찰로 돌아가거나 다른 대상과 상호작용
- **기대** 생활·교감 상태를 잃지 않고 복귀
- **조작** **1차: 명시적 닫기 / 2차: 시스템 뒤로가기 / 보조: 안전한 빈 여백 탭.** 아래로 스와이프는 쓰다듬기와 충돌하므로 사용하지 않음
- **피드백** 연속적인 시점 전환
- **성공** 캐릭터가 자연스럽게 자율 생활로 복귀
- **오류** 한 수단이 실패해도 시스템 뒤로가기가 안전한 대체 경로
- **취소** 캐릭터를 다시 탭하면 확대 복귀
- **재조작** 전환 중 반복 입력은 한 번만 처리
- **다음** Home 기본 시점. **여기서 어떤 과제도 자동 시작하지 않는다**

> `쓰다듬기 완료` 같은 제출 버튼을 만들지 않는다.

### E13. 밥그릇 (장난감 · 배변 흔적 공통 구조)
- **인지** 캐릭터의 관심 행동과 **관련 상황이 처음 발생할 때** 1회 안내
- **동기** 먹고 노는 생활 모습을 보고 싶다 / 공간을 정리하고 싶다
- **기대** 밥을 주면 전달된다 / 장난감을 누르면 놀이가 시작된다 / 흔적을 누르면 치워진다
- **조작** 한 번 탭. **작은 대상도 누르기 쉽게 판정 범위를 넓게**
- **피드백** 오브젝트 상태가 즉시 바뀌고, **캐릭터가 배고픔·상태와 무관하게 반드시 알아차린다**(시선·귀·짧은 몸짓 중 하나)
- **성공** 밥그릇: 필요하면 이동해 먹고, 아니면 먹이가 남아 이후 이용 / 장난감: 접근해 놀거나 현재 행동 뒤 자연스럽게 시작 / 배변: 흔적 제거
- **오류** 자거나 다른 행동 중인 것은 오류가 아니다. 경로 계산 실패에도 상태는 보존하고 거짓 성공을 표시하지 않음
- **취소** 해로운 결과가 없으므로 되돌리기가 필수는 아님. 위치는 이후 수정 가능
- **재조작** 이미 채워진 상태에서 중복 누적하지 않음. 놀이 중 반복 탭은 재시작이 아니라 현재 놀이의 추가 반응. 치운 자리 재탭은 무동작
- **다음** 해당 행동 후 자율 생활 지속. **첫 배변 흔적을 치운 직후에만** Q5를 비차단형으로 한 번 제안한다(§5.2 결정 B). 청소 자체는 그 전에 정상 완료되어야 하며, 질문 때문에 지연되지 않는다

**금지:** 강제 먹이기, 미청소 패널티, 청소 재촉, 점수·의무 보상, **청소 전 Q5 제시**, 배변 발생 즉시 팝업.

### E14. 상태 말풍선 · 빈 영역 탭 `비상호작용 — 규칙으로 고정`

**상태 말풍선**
- 읽기 전용이다. **탭 대상이 아니다.** 상태 변화에 따라 **자동 소멸**한다
- 말풍선 위의 터치는 **캐릭터로 전달**되어 확대를 방해하지 않는다
- 행동과 맞지 않는 오래된 말풍선은 상태 변경 시 제거한다. 말풍선이 없는 상태도 정상이다
- 말풍선을 밥·놀이의 간접 CTA로 사용하지 않는다(`배고파요`를 눌러 메뉴를 여는 구조 금지)

**빈 영역 탭**
- 세계를 바꾸지 않는다. 오류도 아니고 이동 명령도 아니다
- **캐릭터가 탭 지점을 바라보게 하지 않는다**(바닥 탭으로 펫을 지시할 수 있다는 오학습을 만든다)
- **빈 영역을 두 번 연속 탭하는 등 명확한 실패 시도**가 있을 때만 가장 가까운 유효 대상 하나에 힌트를 1회 제공한다
- **무입력 시간만으로 힌트를 띄우지 않는다**(§6, §8 참조)

### E15. 밥그릇 최초 배치
- **인지** 첫 중립적 식사 기회가 나타났을 때 1회 제안
- **동기** 이후 급식할 위치를 정한다
- **기대** 놓은 곳에서 밥 주기가 작동한다
- **조작** **드래그와 위치 탭을 모두 허용**
- **피드백** 유효·무효 위치를 이동 중 즉시 표시. 무효면 마지막 유효 위치로 복귀
- **성공** 캐릭터가 접근 가능한 위치에 저장
- **오류** 이동 영역 밖·접근 불가·경계 밖은 저장하지 않고 이유를 알림. 저장 실패 시 마지막 유효 상태 보존
- **취소** 놓기 전 취소, 배치 직후 재이동. **제안을 무시하거나 미뤄도 캐릭터에게 어떤 불이익도 없다**
- **재조작** 배치 상태의 탭·드래그는 재배치, 일반 Home의 탭은 급식
- **다음** Home 자율 생활. 잠자리·장난감은 **각각의 관련 상황에서** 별도로 제안

# 5. 첫 만남까지의 최종 UX

## 5.1 TTFV 관점

두 가치 순간을 분리해 다룬다.

| 지표 | 정의 |
|---|---|
| **가치 A / TTFV-A** | 앱 실행 → 실제 공간 속 캐릭터를 처음 보는 순간(첫 만남) |
| **가치 B / TTFV-B** | 앱 실행 → 선호 부위 개인화 반응(첫 하트)을 확인하는 순간 |

**필수 전이 단계 (설계 가설)**

| 안 | 단계 수 |
|---|---:|
| 현행 `USER_FLOW.md` | 16 |
| 최초 Codex안 | 13 |
| **최종안** | **8** |

> **이 숫자는 설계 가설이며 실측 TTFV가 아니다.** 실제 초 단위 TTFV-A·TTFV-B는 검증된 이동 영역 조작과 쓰다듬기 조작을 연결 Flow에 통합한 **연결 검증 단계에서만** 측정한다(§9). 그 전 단계의 시간 값을 `TTFV`라고 부르지 않는다.

## 5.2 생활 문답 Q1~Q6의 최종 위치 `확정 — 사용자 결정 반영 (2026-08-17)`

문답은 **한 번에 몰아 받는 설문이 아니라, 생활하면서 아이의 성향을 조금씩 맞춰가는 경험**이다. Q2~Q6은 첫 만남 전에 받지 않고, 관련 생활 상황에서 한 문항씩 만나게 한다.

| 문항 | 위치 | 제시 방식 |
|---|---|---|
| **Q1 쓰다듬기 선호 부위** | **첫 만남 전 (사진 확정 직후)** | 필수. 첫 하트 반응에 직접 필요 |
| **Q2 활동량** | 첫 교감 이후 Home | **상황형** — 아이가 집 안을 움직이는 장면 |
| **Q3 식사 주기** | 첫 교감 이후 Home | **상황형** — 사용자가 밥을 주는 순간 |
| **Q4 짖음/울음 정도** | 첫 교감 이후 Home | **사용자가 여는 경로에서만** (아래 참조) |
| **Q5 배변 주기** | 첫 교감 이후 Home | **상황형** — **첫 배변 흔적을 청소한 직후** `결정 B` |
| **Q6 수면양** | 첫 교감 이후 Home | **상황형** — 쉬거나 잠드는 장면 |

**두 표면은 별개 시스템이 아니다.** 미응답 문항은 모두 사용자가 원할 때 열 수 있는 **하나의 경로**에 항상 모여 있고, 그중 Q2·Q3·Q5·Q6이 관련 상황에서 기회가 있을 때 그 자리에서 답할 수 있게 표면에 떠오른다.

### Q5의 트리거 `확정 — 사용자 결정 B (2026-08-17)`

Q5는 사용자 진입형 메뉴에만 두지 않고 **첫 실제 배변과 연결한다.** 순서를 지킨다.

```
보리가 처음 배변  →  사용자가 흔적을 발견  →  흔적을 탭
                 →  청소를 먼저 정상 완료
                 →  청소 완료 후 Q5를 비차단형으로 제안
```

- **청소 전에 묻지 않는다.** 배변 발생 즉시 팝업을 띄우지 않는다
- 청소는 그 자체로 완결된 행동이며, 질문 때문에 지연되거나 방해받지 않는다
- 답하지 않아도 정상 생활은 그대로 계속된다
- 사용자가 청소하지 않고 넘어가면 Q5는 제안되지 않고 미응답으로 남는다

**Q5에도 유예 선택지를 두지 않는다.** `결정 A 확장 (2026-08-17)` 선택지는 `하루 1회 미만 / 1회 / 2회 / 3회 / 4회 이상` 다섯 개뿐이다. Q3와 같은 근거다 — 비차단 제안이므로 **답하지 않는 것 자체가 미응답이자 유예**이며, 응답 강제·기능 잠금·경고·패널티가 없다. 답하지 않으면 질문은 그대로 남고 생활은 정상적으로 계속된다(§5.7-4).

### Q4만 상황형에서 제외하는 이유 `확정`

질문을 띄우려면 시스템이 먼저 소리 내는 행동을 만들어야 하는데, **그 빈도가 바로 물어보려는 값이다.** 종에 따라(특히 고양이의 우는 장면) 불편함 신호로 읽힐 수 있다. Q4가 끝내 미응답으로 남아도 문제되지 않는다 — 비차단이며 기본값으로 생활이 정상 작동하고 어떤 패널티도 없다.

**확정된 규칙**
- Q2~Q6을 **생성 대기에서 완전히 제거**한다
- "첫 교감 이후"는 **노출 자격이 생기는 시점이지 즉시 삽입하는 시점이 아니다.** 첫 하트 직후 자동 전환·팝업·연속 과제로 제시하지 않고 먼저 Home 관찰로 돌려보낸다
- 상황형 제시는 §5.7의 공통 규칙을 따른다. **관찰을 끊는 능동적 개입이 아니라 무시할 수 있는 수동적 단서다**
- 상황형으로 답할 때는 **그 자리에서 한 문항만** 묻는다. 답한 뒤 다음 질문으로 이어붙이지 않는다
- 미응답을 미완료·결핍·경고로 표시하지 않고, 기능 잠금이나 캐릭터 불이익을 만들지 않는다
- 답한 항목까지 보존하고 언제든 이어갈 수 있다
- Q2~Q6은 **단일 선택 즉시 반영**이며 나중에 언제든 수정 가능하다. 반복되는 `다음` 버튼을 두지 않는다
- **Q3·Q5에는 `잘 모르겠어요` 선택지를 두지 않는다.** `결정 A` 둘 다 비차단 제안이므로 **답하지 않는 것 자체가 미응답이자 유예**다. 응답 강제·기능 잠금·경고·패널티가 없으므로 별도 유예 선택지가 필요하지 않다
- 답이 반영되면 **그 변화가 실제 행동에서 드러나야 한다.** 답하는 행위가 아이의 생활을 바꾼다는 것이 이 구조의 유일한 보상이다
- 여섯 문항 모두 `PRD.md`의 P0로 유지된다. **제거가 아니라 위치 이동이다**

**부트스트랩 특성 — 의도된 것이다.** Q2·Q6은 그 값이 결정하는 행동이 트리거이므로, 사용자는 기본값으로 움직이는 아이를 먼저 보고 그것을 교정하게 된다. 이는 결함이 아니라 "조금씩 맞춰간다"는 설계 의도 자체다. 다만 **질문을 시험이 아니라 조정으로 읽히게** 해야 하며, 답하기 전 상태를 틀린 상태처럼 표현하지 않는다.

**Q2~Q6 응답률은 TTFV와 합산하지 않고 "첫 교감 이후 선택적 개인화 참여율"로 별도 측정한다.**

## 5.3 캐릭터 생성 대기 중 사용자 경험 `확정`

- 생성은 **사용자가 `이 사진으로 계속`으로 사진을 확정한 시점**에 시작한다
- **실제 생성 소요 시간은 확인되지 않았다.** 특정 대기 시간을 전제로 Flow를 설계하지 않는다(§13)
- 대기는 **과제로 채우지 않는다.** 문답·설문·팁·미니게임을 넣지 않는다
- 사실로 확인 가능한 상태만 순차 표시한다. **가짜 퍼센트와 근거 없는 ETA를 만들지 않는다**
- **떠날 수 있어야 한다.** 화면을 벗어나거나 앱을 닫아도 요청과 입력이 유지되는 것이 UX 요구사항이다
- 완료를 **앱 밖으로 푸시하지 않는다.** 외부 알림은 P1 옵트인이므로 전제가 될 수 없다. 사용자가 **자발적으로 돌아왔을 때** 작업 상태를 조회해 `완료` / `진행 중` / `실패` 중 해당 상태로 복원한다
- 화면에 남아 결과를 기다리는 것도 사용자의 선택이며, 그 시간에 과제를 추가하지 않는다
- 요청 지속이 기술적으로 불가능하면 최소한 입력을 보존하고 재시작 필요를 정직하게 알린다. 조용히 취소하거나 처음부터 재입력시키지 않는다

## 5.4 오브젝트 배치 시점 `확정 — 사용자 결정 반영 (2026-08-17)`

세 오브젝트를 첫 만남 전에 모두 배치시키지 않는다. 아이를 먼저 만나고 첫 교감을 한 뒤, **각 오브젝트의 용도를 실제 행동과 함께 배우도록** 필요한 상황에서 하나씩 배치한다.

| 오브젝트 | 배치 시점 | 트리거 성격 |
|---|---|---|
| **밥그릇** | 첫 중립적 식사 기회 | **시스템이 한 번 제안** — 이 첫 제안이 배치 조작 자체를 가르친다 |
| **잠자리** | 아이가 쉬거나 잠드는 장면 | 상황형 제안 또는 사용자가 원할 때 |
| **장난감** | 아이가 노는 듯한 행동을 보일 때 | 상황형 제안 또는 사용자가 원할 때 |

**첫 오브젝트를 시스템이 제안하는 이유** `확정`
Home은 오브젝트를 직접 터치하는 구조다. 따라서 **오브젝트가 하나도 없으면 "놀아주고 싶다", "밥을 주고 싶다"는 의사를 표현할 표면 자체가 없다.** 여기에 메뉴를 만들면 직접 터치 원칙과 충돌한다. 그래서 첫 하나(밥그릇)만 시스템이 제안해 "물건은 놓을 수 있고, 놓으면 만질 수 있다"는 규칙을 한 번 학습시키고, 그 뒤로는 사용자가 스스로 필요할 때 놓을 수 있게 한다.

**확정된 규칙**
- **첫 만남 장면에 가상 생활 오브젝트를 두지 않는다**
- **첫 쓰다듬기 직후에도 배치 과제를 시작하지 않는다.** Home 관찰로 돌아간다
- 세 오브젝트를 온보딩 순서로 연달아 요구하지 않는다. §5.7의 공통 규칙을 따른다
- 그릇·잠자리가 없을 때 `배고파요`, 기다림, 불편함, 재촉처럼 **결핍으로 읽힐 표현을 사용하지 않는다.** 없는 상태는 정상이다
- 제안을 무시하거나 미뤄도 캐릭터의 상태·행동·관계에 불이익이 없다
- 배치는 드래그와 위치 탭을 모두 허용한다(E15)

## 5.5 첫 만남

§3.10 참조. 핵심은 셋이다 — **오브젝트 없음**, **foreground 완료 판정**, **완료 페이지 없이 Home으로 연속**.

## 5.6 첫 교감

첫 만남 직후 캐릭터가 가까운 상태를 잠시 유지해 탭하기 쉽게 만든다. `캐릭터 탭 → 확대 → 쓰다듬기 → 선호 부위 하트`가 가치 B 도달 경로다. 하트 직후 **설문 결과를 설명하는 팝업을 띄우지 않는다.** 사용자가 반응 자체로 연결을 깨닫게 한다.

## 5.7 상황형 제안 공통 규칙 `확정 — 사용자 결정 반영 (2026-08-17)`

Q2·Q3·Q5·Q6(§5.2)과 오브젝트 배치(§5.4)는 모두 **생활 상황에서 나타나는 제안**이라는 같은 성격을 가진다. 개별로는 작지만 합치면 최대 6번의 시스템 개입이 첫 교감 이후 Home 관찰 시간에 몰린다. **분산된 설문이 되지 않도록 아래를 공통 적용한다.**

1. **한 세션에 새로 제시하는 상황형 제안은 최대 1개.** 질문이든 배치든 합쳐서 하나다. 이미 떠 있는 미응답 질문은 새 제안으로 세지 않는다
2. **배치가 질문보다 먼저다.** 같은 상황에 둘 다 걸릴 때(식사 → 밥그릇 + Q3, 수면 → 잠자리 + Q6) 배치를 먼저 제안하고 질문은 다음 기회로 넘긴다. 배치가 행동을 가능하게 하고, 질문은 그 행동을 다듬기 때문이다
3. **능동적 개입이 아니라 수동적 단서다.** 화면을 덮는 모달, 진행 차단, 확인 요구를 만들지 않는다. 사용자가 보고 있던 장면을 계속 볼 수 있어야 한다
4. **한 번 나타난 질문은 사라지지 않는다.** `결정 C` 답하지 않아도 질문 UI가 화면에 그대로 유지된다. **시간 경과로 자동 소멸하지 않고, 여러 번 무시했다는 이유로도 소멸하지 않는다.** 별도 `건너뛰기`·`나중에 하기` 버튼은 두지 않는다 — 명시적 해제 버튼은 그 제안을 처리해야 할 과제로 만들기 때문이다
5. **질문이 떠 있어도 다른 모든 것이 가능하다.** 보리를 관찰하고, 탭하고, 확대하고, 쓰다듬고, 오브젝트를 만지는 데 아무 제약이 없다. 질문은 화면 한쪽에 머무를 뿐 흐름을 잡아두지 않는다
6. **재촉하지 않는다.** 미응답·미배치를 배지, 카운터, 알림, 미완료 목록, 강조 효과로 표시하지 않는다. 같은 질문을 다시 띄우거나 흔들거나 색을 바꾸지 않는다
7. **무입력 시간을 트리거로 쓰지 않는다.** 조용히 보고 있는 것은 유효한 이용이다(§6, §14-5)
8. **첫 교감 직후에는 어떤 제안도 하지 않는다.** 첫 하트 뒤에는 먼저 Home 관찰로 돌아가고, 다음 생활 상황이 자연스럽게 발생할 때까지 기다린다
9. **나중에 답하면 그때부터 반영한다.** 미응답 상태에서도 반려동물의 생활은 정상적으로 계속되며, 답하지 않은 값은 기본값으로 동작할 뿐 결핍이 아니다

|---|---|
| **캐릭터 발견** | 움직이는 대상 자체가 단서. 첫 만남 직후 가까운 상태를 잠시 유지 |
| **탭** | 한 번 탭 → 확대. 이동 중에도 관대한 판정 범위 |
| **확대** | 탭과 확대는 하나의 연속 동작. 별도 확대 버튼 없음 |
| **쓰다듬기** | 탭 = 짧은 접촉(미세 반응) / **문지르기(실제 드래그)만 = 본 쓰다듬기.** 반복 탭·이동 없는 길게 누르기는 하트를 만들지 않는다 |
| **favorite zone** | 본 쓰다듬기가 일어날 때만 하트 + 분명한 긍정 반응. 모든 부위에 같은 하트를 주지 않음. 점수·콤보·친밀도 수치를 연결하지 않음 |
| **nonfavorite zone** | 오답이 아님. 중립적 수용 반응(시선·깜박임·작은 몸짓), 하트만 생략. 화내기·밀어내기·도망·실패 문구 금지 |
| **확대 종료** | 1차 명시적 닫기 / 2차 시스템 뒤로가기 / 보조 안전한 빈 여백 탭. 아래로 스와이프 사용 안 함. 손을 뗐다는 이유만으로 자동 복귀하지 않음 |
| **밥그릇** | 직접 탭 = 급식. 배고픔과 무관하게 조작 인지 반응 보장, 강제 먹이기 없음 |
| **장난감** | 직접 탭 = 놀이. 자거나 다른 행동 중인 것은 오류가 아님 |
| **배변** | 직접 탭 = 치우기. 미청소 패널티·재촉·보상 없음 |
| **상태 말풍선** | 비상호작용. 자동 소멸. 터치는 캐릭터로 통과. 간접 CTA로 쓰지 않음 |
| **빈 영역 탭** | 세계를 바꾸지 않음. 캐릭터가 탭 지점을 바라보지 않음 |
| **최초 discovery** | 트리거는 **명확한 실패 시도(빈 영역 2회 연속 탭 등)뿐.** 무입력 시간 기반 트리거는 1차 기본안에서 제외. 힌트는 가장 가까운 유효 대상 하나만 1회. 체크리스트로 확장하지 않음 |
| **상황형 제안** (Q2·Q3·Q5·Q6, 오브젝트 배치) | 한 세션에 **새로** 제시하는 것은 최대 1개. 수동적 단서이며 모달·차단 없음. **한 번 나타난 질문은 답할 때까지 사라지지 않는다**(시간 경과·반복 무시로도 소멸 없음). `건너뛰기` 버튼 없음. 질문이 떠 있어도 모든 상호작용 가능. 배치가 질문보다 먼저. 자세한 규칙은 §5.7 |
| **재접속 자율 생활 발견** | 첫 프레임 캐릭터 가시성 보장 + 이전과 다른 행동·위치·흔적 하나. 활동 보고서 없음. 이해가 약할 때만 최초 재방문 1회 비모달 원리 설명 |

**관찰만 하다 앱을 나가는 것은 유효한 이용이며 실패가 아니다.** 어떤 지표에서도 미완료로 기록하지 않는다.

# 7. 오류 / 취소 / 수정 / 뒤로가기

## 7.1 세 가지 실패 범주 — 복구 방식이 다르다

| 범주 | 예 | 복구 방식 |
|---|---|---|
| **기술 실패** | 권한, 네트워크, 파일 손상, 생성 요청 실패, 저장 실패 | 실패 범위만 재시도 |
| **품질 위험** | 피사체 너무 작음, 여러 피사체, 심한 가림, 결과 불만족 | 원인 가까이에서 자료 보완 |
| **정서적 중단** | 후보를 더 보고 싶지 않음, Q3·Q5를 지금 답하기 어려움, 조용히 종료하고 싶음 | **이유를 묻지 않고** 저장 후 나갈 수 있게 함 |

## 7.2 전역 원칙

1. 실패 범위만 재시도한다
2. 성공한 입력을 보존한다. 인증 변경·네트워크 단절·앱 종료가 사진·문답·후보를 초기화하지 않는다
3. **뒤로가기는 삭제가 아니다.** 이전 단계로 가는 것과 등록 포기는 다르다
4. 파괴적 변경 전에 영향 범위를 알린다(공간 사진 교체로 이동 영역 무효화 등)
5. 새 결과가 성공하기 전에 기존 결과를 보존한다
6. 오류 메시지는 원인과 다음 행동을 함께 제공한다
7. 선택 사항의 실패가 핵심 경로를 막지 않는다
8. **죄책감과 책임 전가를 금지한다.** 업로드·배치·청소 실패를 사용자의 돌봄 부족처럼 표현하지 않는다

## 7.3 단계별 뒤로가기

| 현재 단계 | 뒤로가기 결과 | 보존 | 확인이 필요한 경우 |
|---|---|---|---|
| 외부 로그인 | 로그인 선택 | 앱 내부 기존 설정 | 없음 |
| 기본 정보 | 로그인 | 종·이름·성별 초안 | 계정 전환 시 |
| 사진 자료 | 기본 정보 | 성공 업로드와 실패 파일 상태 | 없음 |
| Q1 | 사진 자료 | 답 초안 | 없음 |
| 생성 대기 | 안전한 이전 상태 | 요청과 모든 입력 | 없음 |
| 후보 선택 | 이전 입력 수정 경로 | 현재 후보 세트 | 입력 변경으로 재생성이 필요할 때 |
| 보정 | 후보 선택 | 기준 후보와 보정 초안 | 초안 폐기 시 |
| 공간 사진 | 후보 결과 | 공간 사진 초안 | 없음 |
| 이동 영역 | 공간 사진 | 이동 영역 초안 | 공간 사진 교체로 무효화될 때 |
| 첫 만남 | 온보딩으로 되감지 않음 | 완료 상태 | 없음 |
| Home | 앱 루트 동작 | 전체 생활 상태 | 없음 |

## 7.4 상위 입력 수정이 뒤 단계에 미치는 영향

| 수정 대상 | 영향 | 복구 원칙 |
|---|---|---|
| 종 | 문답 4, 종 종속 생성 입력 | 영향받는 항목만 재확인. 새 생성 성공 전 기존 결과 보존 |
| 이름 | 표시 문구 | 즉시 반영, 재생성 불필요 |
| 성별 | 미확정 | 실제 생성 입력 여부가 정해질 때까지 전체 무효화를 가정하지 않음 |
| 주 사진 | 외형 생성 핵심 입력 | 새 작업 버전 시작, 이전 후보 보존 |
| 추가 사진·동영상 | 생성 보조 입력 | 새 결과 필요 여부를 먼저 알리고 사용자 확정 후 시작 |
| Q1 | 첫 쓰다듬기 반응 | 즉시 반영, 이후에도 수정 가능 |
| Q2~Q6 | 생활 행동 | 후보 외형을 무효화하지 않고 행동 설정만 갱신 |
| 공간 사진 | 이동 영역·오브젝트 위치 | 교체 전 무효화 범위를 알림 |
| 이동 영역 | 오브젝트 접근성 | 완료 전에 문제 오브젝트만 다시 배치 |

## 7.5 중단 후 재개 지점

UX 수준에서는 **마일스톤만** 정의한다: 인증 완료 / 기본 정보 완료 / **사진 확정** / Q1 완료 / **후보 확정** / **공간 확정** / 이동 영역 완료 / 첫 만남 완료.
사진 한 장 단위·문답 한 문항 단위의 저장 지점은 구현 단계 사안이다.
재개 시 **등록을 중단했다는 이유로 죄책감이나 손실 경고를 주지 않는다.**

# 8. 첫 방문 튜토리얼 최종 범위

**전체 기능 투어를 만들지 않는다.** 튜토리얼은 아래 3가지가 전부다.

| # | 안내 | 트리거 | 횟수 |
|---|---|---|---|
| 1 | 이동 영역의 과업("캐릭터가 다녀도 되는 바닥을 고른다") | 이동 영역 화면 최초 진입 | 1회 |
| 2 | 확대 상태에서 문지르는 방법 | 첫 확대 진입 시 | 1회 |
| 3 | 가장 가까운 유효 상호작용 하나 | **빈 영역 2회 연속 탭 등 명확한 실패 시도** | 1회 |

**튜토리얼로 설명하지 않는 것 — 직접 발견 가능하다**
- 캐릭터를 탭할 수 있다는 것 (움직이는 대상 + 첫 만남 직후 가까운 상태가 단서)
- 밥그릇·장난감·배변 흔적을 누를 수 있다는 것 (관련 상황이 발생할 때 자연스럽게 안내되므로 사전 설명 불필요)
- 확대를 종료하는 방법 (명시적 닫기가 항상 같은 자리에 있다)
- 꾸미기·앨범·상점·알림 (첫 세션에서 설명하지 않는다)

**규칙**
- 안내는 성공 즉시 사라지고 무시할 수 있어야 한다
- 반복 재촉하지 않는다
- **무입력만으로 안내를 띄우지 않는다**
- 진행을 막거나 완료 체크를 요구하지 않는다
- 관찰만 하다 나가는 것을 미완료로 기록하지 않는다

**`안내`와 `제안`은 다르다 — 튜토리얼 예산에 함께 넣지 않는다.**
위 3가지는 **조작 방법을 모르는 사용자를 돕는 안내**다. §5.7의 상황형 제안(Q2·Q3·Q5·Q6, 오브젝트 배치)은 **사용자가 원할 수 있는 행동의 기회를 여는 것**이며 조작 설명이 아니다. 다만 사용자 체감으로는 둘 다 "시스템이 말을 거는 것"이므로, **한 세션에 안내와 제안을 합쳐 2개를 넘기지 않는다.**

> `PRD.md`의 P0 `첫 사용 튜토리얼`을 위 3가지의 합으로 충족한 것으로 볼지는 **사용자 결정**이다(§12).

# 9. Low-fi 1차에서 반드시 검증할 UX

**시제품을 세 묶음으로 나눈다.** 가설이 요구하는 행동을 재현할 수 있는 매체를 각각 쓴다.

## 9.1 A — 흐름 시제품 (로그인 → 첫 만남 도착)

| 가설 | 관찰할 것 |
|---|---|
| Q1만 선행하는 경로가 이해되고 완주된다 | 필수 전이 수, 완주율, 단계별 멈춤·뒤로가기·이탈 지점 |
| Q2~Q6이 선행 경로에서 빠졌다는 것을 이해한다 | 등록이 끝났다고 인식하는가, 빠진 질문을 찾는가 |
| 사진 적합성 신호가 늦은 실패를 막는다 | 부적합 사진만 가진 참가자가 **어느 단계에서** 문제를 인지하는가 |
| 후보 복구 경로를 원인 진단 없이 사용할 수 있다 | 불만족 시 무엇을 먼저 누르는가, 경로 차이를 이해하는가 |
| 기본 정보 통합이 부담을 만들지 않는다 | 종 변경 시 문답 4 갱신을 이해하는가 |

**주의:** 이동 영역이 실제 제스처로 통합되기 전에는 A의 초 단위 값을 `TTFV-A`라고 부르지 않는다. 흐름 시간의 대리값이다.

## 9.2 B — 인터랙션 시제품 (실제 조작)

**장면 1 — 이동 영역**

| 가설 | 관찰할 것 |
|---|---|
| 타일 토글이 첫 시도에 성공한다 | 첫 시도 성공률, 완료 시간, 수정 횟수 |
| 같은 타일 재탭 = 제외를 이해한다 | 지우개를 찾는가, 재탭을 시도하는가 |
| 상시 도달 예시가 결과 예측을 돕는다 | 완료 전에 영역을 조정하는가 |
| 복구 수단을 이해한다 | 실행 취소·초기화 사용과 이해도 |
| 확대 방식이 타일 선택과 충돌하지 않는다 | **두 손가락 확대안 vs 명시적 확대 상태안 비교** |

**장면 2 — Home 첫 교감**

| 가설 | 관찰할 것 |
|---|---|
| 안내 없이 캐릭터를 발견해 탭한다 | 첫 입력까지의 행동, 첫 탭 대상 |
| 탭 → 확대 → 쓰다듬기가 연결된다 | 확대 후 첫 입력이 탭인지 문지르기인지 |
| 3계층 접촉 규칙이 실패를 만들지 않는다 | 탭이 무시됐다고 느끼는가 |
| 선호 부위 반응이 개인화로 읽힌다 | 하트 발생 시 반응, 문답과 연결짓는가 |
| 확대 종료 방법을 찾는다 | 종료까지의 시도 횟수 |
| 빈 영역 탭 규칙이 작동한다 | 2회 연속 탭 후 힌트가 도움으로 읽히는가, 관찰을 깨는가 |
| 첫 급식이 인지된다 | 배고프지 않을 때도 전달됐다고 느끼는가 |

**측정 값의 이름:** 장면 2의 시간은 전체 TTFV-B가 아니라 **`Home 도착 → 개인화 반응 구간 시간`**으로 기록한다.

## 9.3 C — 분리 시나리오

| 시나리오 | 관찰할 것 |
|---|---|
| 생성 대기 중 이탈·복귀 | 떠날 수 있음을 발견하는가, 떠날 때 불안한가, 재진입 시 `완료`/`진행 중`/`실패`를 이해하는가, 재입력이 필요하다고 느끼는가 |
| 첫 만남 도중 전화·알림·백그라운드 전환 | 복귀 시 장면을 놓쳤다고 느끼는가 |
| 첫 하트 뒤 과제 없는 시간 | 편안한가, 무엇을 해야 하는지 몰라 불안한가 |
| 식사 상황에서 밥그릇 배치 제안 | 이유를 추가 설명 없이 이해하는가, **"지금 반드시 해결해야 할 문제"로 오해하지 않는가**, 미뤄도 된다고 이해하는가, 배치 후 밥그릇 직접 터치와 캐릭터 반응의 관계를 발견하는가 |
| **상황형 질문(Q2·Q3·Q5·Q6)의 누적 부담** | **여러 세션에 걸쳐 제안이 반복될 때 "설문이 흩어져 있을 뿐"이라고 느끼는가.** 제안을 방해로 인식하는 시점이 몇 번째인가. 답하지 않은 질문이 계속 떠 있는 것을 부담으로 느끼는가. `건너뛰기` 버튼을 찾는가 |
| **답이 행동을 바꾼다는 인식** | Q2·Q6에 답한 뒤 아이의 움직임·휴식이 달라졌다고 느끼는가. 답하기 전 상태를 "틀린 상태"로 인식하지는 않는가 |
| Q3·Q5를 답하기 어려운 상황 | 유예 선택지를 발견하고 사용하는가, 정서적 망설임이 어디서 나타나는가. **Q5를 상황형에서 뺀 판단이 맞는지 — 사용자가 배변 흔적 옆에서 이 질문을 받는 것을 어떻게 느끼는지 별도 확인** |
| 적합한 사진이 없는 상황 | 비난받는다고 느끼는가, 안전하게 중단하고 돌아올 수 있다고 이해하는가 |
| 후보가 닮지 않거나 불편한 상황 | `지금은 그만 보기`를 발견하는가, 반복 재생성 루프에 갇히는가 |
| 첫 재방문 | 캐릭터를 몇 초 만에 찾는가, 시간이 이어졌다고 이해하는가 |

**재방문 시뮬레이션은 "상태가 달라졌음을 이해하는가"까지만 검증한다.** 실제로 다시 오고 싶어지는지는 후속 종단 검증 대상이다.

## 9.4 연결 검증 (B에서 조작이 안정된 뒤)

B에서 선택된 이동 영역·쓰다듬기 조작을 연결 Flow에 통합한 다음에만 아래를 실제 초 단위로 측정한다.

- 앱 실행 → 첫 만남까지의 **TTFV-A**
- 앱 실행 → 첫 개인화 반응까지의 **TTFV-B**
- 전체 필수 입력 수와 재작업 시간

**A의 구조 시간, B의 과업 시간, 연결 검증의 실제 TTFV는 서로 다른 지표다. 합산하지 않는다.**

## 9.5 실패 신호

- 죄책감·의무·방치에 관한 **자발적 발화**가 나오면 실패로 기록한다
- 관찰만 하는 행동을 미완료로 기록하지 않는다
- 참가자가 관찰 중일 때 진행자가 개입하지 않는다

# 10. Low-fi 1차에서 제외할 것

- 상점, 결제, 재화
- 앨범 전체 구조
- 추억 사진의 저장·공유 확장
- 알림 옵트인 시점과 빈도
- 꾸미기 전체 편집기와 장식 카탈로그
- `함께한 날`의 정보 구조

**구조**
1. 종·이름·성별을 한 단계로 통합한다. 종이 선행 항목이다
2. 필수 사진·추가 사진·선택 동영상을 하나의 자료 단계로 묶는다. 동영상 독립 화면과 `건너뛰기`를 만들지 않는다

6. **Q5는 첫 배변 흔적을 청소한 직후에만 제안한다.** 청소 전에 묻지 않고, 배변 발생 즉시 팝업을 띄우지 않는다 `결정 B`

8. **첫 만남 장면에 가상 오브젝트를 두지 않는다.** 첫 쓰다듬기 직후에도 배치 과제를 시작하지 않는다 `사용자 결정 2026-08-17`

10. **상황형 제안은 §5.7의 공통 규칙을 따른다:** 한 세션에 새로 제시하는 것은 최대 1개, 배치가 질문보다 먼저, 수동적 단서, **한 번 나타난 질문은 사라지지 않음**, `건너뛰기` 버튼 없음, 첫 교감 직후에는 제안 없음 `결정 C 반영`
11. 첫 만남 뒤 완료 페이지 없이 Home으로 연속한다

**조작**
12. 이동 영역의 기준 조작은 **큰 타일 토글**이다. 자유 브러시 폐기, 별도 지우개 없음, 별도 미리보기 모드 없음. 남는 도구는 실행 취소(1단계)·초기화·완료
13. 자동 바닥 추정은 대안이 아니라 **초기값**이다. 되든 안 되든 사용자의 조작은 같다
14. 쓰다듬기는 2계층이다: 탭·반복 탭·이동 없는 길게 누르기=짧은 접촉(하트 없음) / **문지르기(실제 드래그)=본 쓰다듬기** / 선호 부위 문지르기에서만 하트 `사용자 결정 2026-08-18`
15. 확대 종료는 명시적 닫기 1차, 시스템 뒤로가기 2차, 안전한 빈 여백 탭 보조
16. 상태 말풍선은 비상호작용이며 자동 소멸하고 터치를 캐릭터로 통과시킨다
17. **빈 영역 탭은 세계를 바꾸지 않고 캐릭터가 그쪽을 바라보지도 않는다.** 명확한 실패 시도에만 힌트 1회
18. **무입력 시간 기반 힌트 트리거를 1차 기본안에서 제외한다**
19. 모든 핵심 조작에 관대한 대체 입력·넓은 판정 범위·시간 압박 없음·중간 상태 보존을 적용한다. 오브젝트 배치는 드래그와 위치 탭을 모두 허용한다

**복구·안전**
20. 기술 실패 / 품질 위험 / 정서적 중단을 구분해 복구한다
21. 사진 적합성을 업로드 직후 확인한다. 품질 점수를 만들지 않고 생성 품질을 보장하지 않는다
22. 후보 불만족 복구는 `다시 준비하기` 하나 + 원인별 보조 경로다. 원본 사진은 요청 시에만 참조한다
23. `지금은 그만 보기`로 이유 없이 나갈 수 있고 입력은 보존된다. **재진입 시 기존 결과를 자동으로 크게 노출하지 않고 계속 볼지 선택하게 한다**
24. 생성 대기는 과제로 채우지 않고 떠날 수 있는 상태로 설계한다. 완료를 앱 밖으로 푸시하지 않고 자발적 복귀 시 상태를 복원한다
25. 첫 만남 완료 플래그는 foreground에서 장면·문구·Home 전환이 모두 끝난 뒤에만 기록한다. 미완료 복구와 완료 후 수동 재생은 다른 정책이며 후자는 1차 범위 밖이다
26. 재방문 첫 프레임에서 캐릭터가 보이거나 즉시 찾을 수 있어야 한다. 활동 보고서를 만들지 않는다
27. 성공한 입력을 보존하고, 새 결과가 성공하기 전에 기존 결과를 지우지 않는다
28. **미응답 문항과 미배치 오브젝트는 결핍이 아니다.** 배지·카운터·알림·미완료 목록으로 표시하지 않고, 없는 상태를 정상으로 다룬다
29. **보정은 원본 복원과 직전 변경 취소(undo)를 구분한다.** 실패한 변경만 이전값으로 복구하고 다른 성공 변경은 보존한다

**검증**
30. Low-fi 1차를 A(흐름) / B(인터랙션) / C(분리 시나리오)로 나누고, 연결 검증 전의 시간 값을 `TTFV`라고 부르지 않는다
31. UX 위험은 `차단 여부 / 정서적 손실 / 발생 가능성 / 복구 비용` 네 축으로 기록하며 PRD의 P0/P1/P2 표기와 분리한다
32. 보정은 1차에서 대표 속성 2종만 검증한다. 저장은 마일스톤 단위로만 UX 정의한다
33. **이동 영역의 최소 유효 면적은 제품 규칙이 아니다.** 빈 영역·지나치게 작은 영역의 완료를 막는다는 **규칙만 확정**이고, 구체적 임계값은 확정된 바 없다. Low-fi에서 임시값을 쓰는 경우 반드시 `Low-fi 테스트용 임시 파라미터`로 표기하며, 그 값을 제품 규칙으로 승격하지 않는다

**토론 중 근거 문서로 해소된 항목**
34. **Q2~Q6은 외형 생성 입력이 아니다.** `staypet_context.md`의 개인화 절이 외형(사진·동영상)과 행동(이름·성별·문답 6종)을 분리해 명시하므로, Q2~Q6의 후행 배치는 문서상 설계와 충돌하지 않는다. 실제 생성 파이프라인 입력 목록은 §13에서 최종 확인한다
35. **성별은 P0 필수로 유지한다.** 같은 절이 성별을 **행동** 개인화 입력으로 명시하므로 "쓰이지 않는 입력"이라는 전제는 성립하지 않는다. 남은 것은 구체적 효과 정의이며 Low-fi를 막지 않는다

# 14. Low-fi 제작자가 반드시 지켜야 할 UX 규칙

시각 디자인 지시가 아니라 **구조와 동작 기준**이다.

**하지 말 것**
1. 첫 만남 **전에** 오브젝트 배치, Q2~Q6, 튜토리얼, 소개 화면을 넣지 말 것
2. 첫 만남과 첫 하트 **직후에** 어떤 과제도 자동으로 시작하지 말 것
3. 생성 대기를 문답·설문·팁·미니게임으로 채우지 말 것
4. 가짜 진행률(%)이나 근거 없는 남은 시간을 표시하지 말 것
5. 무입력 시간만으로 힌트·안내를 띄우지 말 것
6. 이동 영역에 자유 곡선 브러시, 별도 지우개, 별도 미리보기 모드를 넣지 말 것
7. 확대 상태에서 탭을 실패로 처리하지 말 것
8. 말풍선을 탭 대상이나 간접 메뉴로 만들지 말 것
9. 빈 영역 탭에 캐릭터가 반응하게 만들지 말 것
10. 숫자 상태 게이지(Hunger/Happiness/Cleanliness), 점수, 친밀도 수치, 콤보, 연속 출석을 만들지 말 것
11. 항상 떠 있는 버튼을 여러 개 두거나 Dashboard 카드·RPG HUD를 만들지 말 것
12. 미접속·미청소·미배치를 결핍·경고·미완료로 표시하지 말 것
13. 캐릭터가 실제 사망한 반려동물 본인인 것처럼 말하게 하지 말 것. `기다렸어요`, `왜 이제 왔어요`, `사진 1장만으로도 시작할 수 있어요` 금지
14. 후보 복구에서 네 경로를 대등하게 나열하지 말 것
15. 원본 사진을 후보 옆에 상시 병치하지 말 것
16. **한 세션에 상황형 제안을 2개 이상 띄우지 말 것.** 안내까지 합쳐도 2개를 넘기지 말 것
17. **상황형 제안에 `건너뛰기`·`나중에 하기` 버튼을 만들지 말 것.** 답하지 않으면 질문은 그대로 남는다(결정 C)
18. **Q4(짖음/울음)를 상황형으로 밀지 말 것.** 사용자가 여는 경로에만 둘 것
19. **한 번 나타난 상황형 질문을 자동으로 사라지게 하지 말 것.** 시간이 지나서도, 여러 번 무시해서도 소멸하지 않는다. 대신 같은 질문을 다시 띄우거나 흔들거나 강조해 재촉하지도 말 것
20. **배변 흔적을 청소하기 전에 Q5를 묻지 말 것.** 배변 발생 즉시 팝업도 금지. 청소가 정상 완료된 뒤에만 한 번 제안할 것
21. 답하기 전이나 배치하기 전의 상태를 틀린 상태·부족한 상태처럼 표현하지 말 것
22. **이동 영역의 최소 유효 면적 임시값을 제품 규칙처럼 표기하지 말 것.** Low-fi에서 쓰는 값은 `Low-fi 테스트용 임시 파라미터`로 명시할 것

**반드시 할 것**
23. 첫 만남은 5~10초 자동 진행, 완료 페이지 없이 Home으로 연속
24. 첫 만남 직후 캐릭터가 가까운 상태를 잠시 유지해 탭하기 쉽게 할 것
25. 확대 상태에 항상 같은 자리의 명시적 닫기를 둘 것
26. 선호 부위에서만 하트를 주고, 비선호 부위에는 중립적 수용 반응을 줄 것
27. 첫 급식은 배고픔과 무관하게 조작 인지 반응을 보장할 것
28. 이동 영역에 도달 예시를 편집 중 상시 표시할 것
29. 사진 적합성 결과를 업로드 직후 같은 자리에서 알리고 추가·교체·보류를 제공할 것
30. 모든 실패 상태에 원인과 다음 행동을 함께 제시할 것
31. 뒤로가기에서 이미 성공한 입력을 보존할 것
32. Q2~Q6·오브젝트 배치·힌트를 모두 **무시 가능**하게 만들 것. 무시해도 진행이 막히거나 캐릭터가 불이익을 받지 않아야 함
33. **질문이 화면에 떠 있어도 관찰·탭·확대·쓰다듬기·오브젝트 조작이 모두 가능하게 할 것.** 질문은 흐름을 잡아두지 않는다
34. **같은 상황에 배치와 질문이 함께 걸리면 배치를 먼저 제안할 것.** 질문은 다음 기회로
35. **Q2·Q6에 답한 결과가 실제 행동 변화로 드러나게 할 것.** 답이 아이의 생활을 바꾼다는 것이 이 구조의 유일한 보상이다
36. **보정에서 원본 복원과 직전 변경 취소를 구분해 제공할 것.** 실패한 변경만 되돌리고 다른 성공 변경은 보존
37. **`지금은 그만 보기` 후 재진입 시 기존 후보를 자동으로 크게 노출하지 말 것.** 계속 볼지 먼저 선택하게 할 것
38. 관찰만 하는 참가자를 미완료로 기록하지 말고 진행자가 개입하지 말 것

# Low-fi 진행 판정

## A. Low-fi 시작 가능

Low-fi를 막던 두 결정(생활 문답 순서, 기본 오브젝트 배치 순서)에 2026-08-17 제품 소유자의 승인이 나왔고 §5.2·§5.4·§5.7·§11에 반영됐다. **Low-fi 제작에 필요한 UX 의사결정은 완료됐다.**

- §12.2의 남은 사용자 결정 4개는 **어느 것도 만들 화면을 바꾸지 않는다.** 병행 확인해도 된다
- §13의 기술 검증 8개는 결과가 어느 쪽이든 **조작과 화면 구성이 동일하도록 설계돼 있다.** 병행 확인해도 된다
- 시작 지점은 §9.1의 흐름 시제품 A다. §14의 규칙을 지켜 제작한다

**문서 상태:** `USER_FLOW.md`는 v1.1로 동기화되어 이 문서와 일치한다(2026-08-17). Low-fi 제작 시 두 문서 중 어느 쪽을 봐도 같은 Flow가 나오며, 세부 상호작용 규칙과 검증 범위는 이 문서에만 있다.
