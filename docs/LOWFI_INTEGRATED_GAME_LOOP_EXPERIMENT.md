## 1. 목표 (Goal)

참가자 #1·#2 테스트는 **단일 상호작용**만 검증했다. rev 1 에서 하트를 벌고 쓰는 순환을 붙였고,
rev 2 는 그 순환을 **여러 세션에 걸쳐 지속되는 형태**로 늘린다.

이번 회차의 질문은 둘이다.

> **(1) 첫 하트와 상점 사이의 인과를 참가자가 즉시 이해하는가?**
> **(2) 오늘 할 일이 끝나도 다시 오고 싶은 이유가 생기는가?**

(1) 은 rev 1 에서 실패한 지점이다. 하트를 얻은 뒤 Home 으로 돌아갔다가 상점이 열려서
"내가 한 일"과 "상점"이 끊겨 읽혔다. rev 2 는 확대(쓰다듬기) 맥락에서 바로 잇는다.

(2) 는 게이지·만실 보너스·연속 방문·긴 가격 곡선으로 시험한다.
단, 이것들이 **과제·의무·압박**으로 읽히면 실패다. StayPet 의 핵심은 관리가 아니라 함께 지내는 일상이다.

## 3. 하트 경제 (Heart economy)

### 획득

| 원천 | 보상 | 비고 |
|---|---|---|
| 쓰다듬기 (선호 부위) | ♥3 | 첫 하트의 유일한 경로 |
| 밥 주기 | ♥2 | 밥그릇 배치 후 |
| 청소 | ♥4 | 배변 흔적 탭 |
| 놀이 | ♥3 | 장난감 탭 |
| **세 게이지 만실** | **♥5** | 세트를 완성한 순간 1회 |
| **그날 첫 방문** | **♥2~5** | 이번 달 연속 일수에 따름 |

전부 **LOW-FI PLACEHOLDER** 다.

### 소비

♥5 (기지개 켜기) ~ ♥1,200 (최상급 소가죽 소파).
첫 세션에서 벌 수 있는 양은 대략 ♥10~25 이고, 최상위 아이템은 수십 회의 방문이 필요하다. 의도된 격차다.

### 파밍 방지 (내부 전용)

```js
var FARM_COOLDOWN_MS = 45000;   // 같은 종류의 행동 반복 보상 차단
```

- 쿨다운을 **화면에 표시하지 않는다.** 남은 시간도, "아직이에요" 문구도 없다.
- 쿨다운 중에도 보리는 **정상적으로 반응한다.** 놀고, 먹고, 좋아한다. 하트만 안 나온다.
- 만실 보너스는 별도 래치(`bonusArmed`)로 막는다. 만실이 유지되는 동안에는 다시 주지 않는다.
- 방문 보상은 시뮬레이션 날짜당 1회로 막는다.

### 하지 않은 것

현금 재화 없음 · 확률형 보상 없음 · 광고 없음 · 일일 미션 없음 · 미션 카운터 없음 ·
에너지 없음 · 일일 상한 표시 없음 · 스트릭 압박 UI 없음.

## 4. 첫 하트 → 상점 전환 (First-heart Shop transition)

rev 1 의 흐름은 이랬다.

```
쓰다듬기 → ♥ → Home 복귀 → 자율 행동 1회(조용한 한 박자) → 그때 상점이 열림
```

문제: **"내가 한 일"과 "상점"이 시간적으로 끊겨** 인과가 읽히지 않았다.
상점이 열린 이유를 참가자가 자기 행동과 연결하지 못하면, 상점은 그냥 튀어나온 화면이 된다.

rev 2 의 흐름:

```
선호 부위 문지르기
  → 보리의 긍정 반응 ("♥ 보리가 기분 좋아해요 · 머리")
  → ♥ 잔액이 눈앞에서 오름 (확대 화면 위에 잔액이 계속 떠 있다)
  → 아주 짧은 한 박자 (0.7s)
  → 같은 확대 화면 안에서 한 줄: "상점에서 하트를 사용할 수 있어요"
  → (0.9s) 상점으로 전환
```

구현상 중요한 두 가지:

```js
openShop(true);                    // 먼저 화면을 상점으로 바꾸고
if (w.isConnected) w.remove();     // 그 다음 확대를 걷는다
```

**순서가 뒤바뀌면 한 프레임 동안 Home 이 드러난다.** 그러면 rev 1 과 같은 단절이 생긴다.
검증 항목 #4 는 이 한 프레임을 실제로 감시한다(하트 시점부터 상점 전환까지 60ms 간격 샘플링).

- 감정 반응 자체는 보존한다. 반응을 건너뛰고 바로 상점으로 밀지 않는다.
- 튜토리얼도, 다음 버튼도 없다.
- 상점을 닫으면 Home 으로 돌아가고 자율 생활이 이어진다.
- **자동 노출은 여기 한 번뿐이다.** 이후의 모든 하트 획득은 상점을 열지 않는다.

## 5. 생활 상태 게이지 (Life-state gauges)

Home 우상단에 3종. 하트 잔액은 좌상단이다.

```
포만감  ▰▰▱
피로도  ▰▱▱
즐거움  ▰▰▰
```

| 쓰는 말 | 쓰지 않는 말 | 방향 |
|---|---|---|
| 포만감 | ~~배고픔~~ | 높을수록 좋다 (3 = 배부름) |
| 피로도 | ~~피로도를 숨긴 '휴식'~~ | **낮을수록 좋다 (0 = 잘 쉰 상태)** |
| 즐거움 | ~~심심함~~ | 높을수록 좋다 (3 = 신남) |

rev 2 에서는 `휴식`(높을수록 좋음)이었다. rev 3 에서 `피로도`로 바꿨고 **방향이 반대**다.

| 피로도 | 상태 |
|---|---|
| 0 | 기운이 남아 있다 |
| 1 | 조금 피곤하다 |
| 2 | 피곤하다 |
| 3 | 졸리다 → 잠으로 이어진다 |

### 표현 규칙

- 세 게이지를 **같은 막대로** 그린다. 피로도만 색·아이콘·깜박임을 달리하지 않는다.
- **낮은 피로도를 문제처럼 보이게 하지 않는다.** 경고색·위험 아이콘·죄책감 표현이 없다.
- 보리보다 시각적으로 뒤에 있어야 한다. 옅은 테두리, 작은 글씨, `pointer-events: none`.
- 어떤 게이지가 0 이어도 **아무 일도 일어나지 않는다.** 굶주림·질병·죽음·슬픔·패널티가 없다.
- 확대(쓰다듬기) 중에는 게이지 HUD 를 걷는다. 교감 장면에 상태창이 겹치지 않게.

**감수한 것**: 피로도 0 은 빈 막대라서 '채워야 할 것'으로 오독될 수 있다.
그래도 색이나 경고를 넣는 쪽이 더 나쁘다고 판단했다 — 참가자 관찰 항목으로 남긴다(H-X3).

### 변화 규칙 (전부 임시값 · LIFE 설정에 모여 있다)

| 원인 | 변화 | Low-fi 간격 |
|---|---|---|
| 밥 주기 | 포만감 +1 | 즉시 |
| 놀이 성공 | 즐거움 +1 | 즉시 |
| 잠 완료 | 피로도 → 0 | 잠이 끝난 뒤 |
| 시간 경과 | 포만감 −1 | 60~90초 |
| 깨어 있는 시간 | 피로도 +1 | 35~50초 (자는 중엔 멈춤) |
| 시간 경과 | 즐거움 −1 | 75~120초 |

rev 2 의 '무작위로 아무 게이지나 하나 −1' 방식은 **버렸다.**
이제 각 게이지의 변화에 의미가 있다 — 포만감은 시간이 지나 줄고, 피로는 깨어 있어서 쌓이고,
즐거움은 놀지 않아서 식는다.

## 6. 이상 상태 보너스 (All-good bonus)

rev 2 의 조건(세 게이지 모두 full)은 피로도가 역방향이 되어 **무효**다.

**현재 조건**

```
포만감 = 3   AND   피로도 = 0   AND   즐거움 = 3
```

→ 그 상태에 **막 도달한 순간** ♥5 + 가벼운 한 줄

```
"보리가 아주 편안해 보여요"   ♥ +5
```

래치 원리는 그대로다.

```js
function checkIdeal() {
  if (!idealState()) { state.bonusArmed = true; return; }   // 벗어나면 자격 회복
  if (!state.bonusArmed) return;                            // 유지 중에는 반복 지급 없음
  state.bonusArmed = false; state.hearts += ALL_FULL_BONUS; ...
}
```

- 도달한 **순간**에만 준다. 머물러 있다고 반복 지급하지 않는다.
- 한 번이라도 벗어나야 다시 자격이 생긴다. 나중에 다시 도달하면 다시 받는다.
- 체크리스트·`3/3 완료`·일일 퀘스트·스트릭 UI 를 만들지 않았다.

**도달 난이도가 rev 2 보다 올라갔다.** 피로도 0 은 잠이 끝난 직후에만 성립하므로,
세 조건이 겹치는 창이 좁다. 의도한 것이지만 참가자가 이 규칙을 알아챌 수 있는지는 미검증이다(H-W).

## 7. 이번 달 연속 방문 보상 (Monthly consecutive-visit reward)

그날 **첫 방문**에 1회. 기준은 **이번 달 안에서의 연속 방문 일수**다.

```js
v.streak = (같은 달 && 바로 다음 날) ? v.streak + 1 : 1;
```

| 조건 | 결과 |
|---|---|
| 같은 달, 어제 방문함 | 연속 +1 |
| 하루라도 건너뜀 | 다음 방문에 조용히 1일차부터 |
| 달이 바뀜 | 1일차부터. **하트·구매·배치·해금은 그대로** |
| 같은 날 재진입 | 중복 지급 없음 |

### 지키는 것

- **"연속이 끊겼어요" 같은 문구를 쓰지 않는다.** UI 는 그냥 현재 연속 일수를 말한다.
- 카운트다운·"내일 또 오세요"·상실 경고·붉은 불꽃 아이콘 없음.
- 끊겨도 하트를 회수하지 않는다.

## 8. 출석 보상 표 (Attendance reward tiers)

| 이번 달 연속 일수 | 그날 보상 |
|---|---|
| 1–5일 | ♥2 |
| 6–12일 | ♥3 |
| 13–25일 | ♥4 |
| 26–30일 | ♥5 |
| 31일 (31일 달) | ♥5 (최상위 티어 유지) |

한 달 최대 누적: 대략 ♥110 (30일 개근 기준).
최상위 가구 하나(♥1,200)는 출석만으로는 약 1년이 걸린다 — 출석은 **보조 흐름**이지 주 수입원이 아니다.

### 표시

```
이번 달 8일 연속으로 만났어요
오늘 ♥3                        [확인]
```

- Home 진입 0.9초 뒤에 한 번. 방 위쪽에 뜬다(하단은 탭 힌트 자리라 비워 둔다).
- 확인 한 번으로 닫힌다. 자율 생활을 멈추지 않는다.
- 배치 중이면 뜨지 않는다.
- 큰 게임형 달력은 만들지 않았다.

## 9. 확장된 상점 경제 (Expanded Shop economy)

카테고리는 그대로 4개. 바뀐 것은 **가격 폭**이다.

| 구간 | 범위 | 심리적 역할 |
|---|---|---|
| 아주 저렴 | ♥5–20 | "지금 살 수 있다" |
| 보통 | ♥25–80 | "한두 번 더 오면 산다" |
| 높음 | ♥100–250 | "며칠 모으면 산다" |
| 프리미엄 | ♥300–600 | "이번 달 목표" |
| 장기 / 최상위 | ♥700–1,200 | "언젠가 저걸" |

세 지평(**지금 / 조금 모아서 / 언젠가**)이 **한 화면 안에서 동시에 보여야** 한다.
전부 비싸면 상점이 벽이 되고, 전부 싸면 다시 올 이유가 없다.

첫 상점(♥5 보유 기준: 방문 ♥2 + 첫 쓰다듬기 ♥3)에서는
94개 중 **정확히 1개**(기지개 켜기 ♥5)만 살 수 있다. 인위적으로 하트를 얹지 않았다.

## 10. 갱신된 가격 곡선 (Updated price curve)

총 **94개** (rev 1 은 92개 — 가구 상위 2종 추가).

## 11. 카탈로그 구조 (Catalog structure)

```js
{ id, name, price, tag? }
```

구현 원칙은 rev 1 과 같다: **94개를 위한 코드는 없다.**
배치 문법 1개, 놀이 메커니즘 1개, 행동 표현 1개가 전 카탈로그를 처리한다.
가격을 전부 바꾸는 데 든 변경은 데이터뿐이고 로직은 한 줄도 건드리지 않았다.

## 12. 배치 문법 (Placement grammar)

참가자 #2 에서 검증된 문법을 그대로 쓴다. 새 문법을 만들지 않았다.

```
[놓기] → Home → 안내 한 줄 + 고스트 → 손가락으로 끌어 놓음(드래그 전용)
   → 미리보기 + 원형 체크(46×46) → 체크를 눌러야 확정
```

빈 곳 탭으로 위치가 바뀌지 않는다 · 바닥 밖이면 확인 비활성 ·
드래그 리스너는 `document` 에 붙는다(터치 라우팅) · `.room.placing { touch-action: none }`.

재배치: 오브젝트가 1개 이상일 때 **편집** 이 나타나고, 같은 문법을 재사용한다.

## 15. 배변 흐름 (Bowel flow)

```
휴식 뒤 → 배변 흔적이 조용히 생김 → 참가자가 발견하고 탭 → 사라짐 + ♥4
   → 1.6초 뒤 Q5 제안 (비차단)
```

알림·배지·경고 없이 생긴다 · 안 치워도 **아무 일도 없다** · 건강 감소·기분 나빠짐·재촉 없음 ·
Q5 는 청소 완료 뒤에만 · 이미 떠 있는 미응답 질문은 덮어쓰지 않는다 ·
선택지는 정확히 `하루 1회 미만 / 1회 / 2회 / 3회 / 4회 이상` · `잘 모르겠어요` 없음 · 건너뛰기 없음.

참가자가 시작한다(보리가 조르지 않는다) · 놀이 중 재탭 무시 · 끝나면 스스로 자율 생활로 돌아간다.

## 17. 통합 루프 (Integrated loop)

```
방문 보상 → Home → 보리를 봄 → 쓰다듬기 / 밥 / 놀이 / 청소
   → 하트 획득 → 포만감·휴식·즐거움 상승
   → 셋 다 차면 보너스 → 상점
   → 가구 / 행동 / 장난감 / 옷 구매 → 배치·착용·해금
   → 보리의 생활이 달라짐 → 자율 생활 지속 → 다음 방문
```

이 루프가 **과제 목록으로 읽히면 실패**다.
퀘스트 로그·미션 트래커·XP 바·배틀패스·에너지 시스템을 만들지 않았다.

| H-Z3 | 장기 가격(♥700~1,200)이 **포기가 아니라 목표**로 읽힌다 | "언젠가 저거 살래" | "저건 못 사겠네" 하고 무시 |

### 장기 진행 (Long-term progression hypothesis)

> **가설**: 하루치 상호작용으로는 최상위 아이템에 닿지 못한다는 사실이,
> 이탈 이유가 아니라 **다시 올 이유**가 된다.
>
> 성립 조건은 세 가지다.
> (1) 오늘도 살 수 있는 것이 있다 (♥5~20 구간)
> (2) 며칠이면 닿는 것이 있다 (♥25~80)
> (3) 언젠가의 목표가 명확히 보인다 (♥700+)
>
> 하나라도 빠지면 곡선은 벽이 되거나 평지가 된다.
>
> **이 가설은 단일 세션 테스트로 검증할 수 없다.** §23 참조.

### 회귀 (깨지지 않았는가)

| # | 확인 |
|---|---|
| H-R | 첫 세션 흐름: 첫 만남 → 탭 → 쓰다듬기 → 첫 하트 |
| H-S | 실제 문지르기만 하트를 만든다 (짧은 탭·반복 탭 무효) |
| H-T | 배치는 드래그 전용, 원형 체크로 확정 |
| H-U | 참가자 화면에 진행자·메타·디버그 UI 가 없다 |

## 23. 사람으로 확인해야 하는 것 (What must be tested with humans)

코드로 확인할 수 없는 것들. 아래는 **전부 관찰·인터뷰 대상**이다.

| 항목 | 왜 코드로 알 수 없나 | 어떻게 확인하나 |
|---|---|---|
| 첫 하트 → 상점의 인과가 읽히는가 | 화면 순서는 검증했지만 **이해**는 검증 못 한다 | 상점이 열린 직후 "지금 무슨 일이 일어난 것 같아요?" |
| 게이지가 압박으로 읽히는가 | 문구는 긍정이어도 **수용**은 다를 수 있다 | 게이지를 처음 본 순간의 표정·발화 |
| 만실 보너스 규칙 발견 | 발견 여부는 행동으로만 드러난다 | 세 번째 게이지를 의도적으로 채우는지 |
| 출석 보상이 의무로 느껴지는가 | 저충실도에서도 부담은 생긴다 | "내일도 와야 할 것 같나요?" |
| 장기 가격이 목표인가 벽인가 | **단일 세션으로는 불가능** | 다회차 일기 연구 / 2주 이상 관찰 |
| 연속 끊김의 감정 | 시뮬레이션으로는 상실감이 안 생긴다 | 실제로 하루 건너뛴 뒤의 재방문 인터뷰 |
| 죄책감 발생 여부 | 이번 제품의 최대 위험 | 전 구간 발화 기록 + 사후 인터뷰 |
| 재방문 의사 | Low-fi 로 측정 불가 | 종료 후 "또 열어 보고 싶나요? 왜요?" |

**특히 장기 진행 가설(H-Z3)과 출석 부담(H-Z)은 이번 회차로 결론 낼 수 없다.**
이번 테스트가 답할 수 있는 것은 "첫 만남에서 이 구조가 어떻게 읽히는가"까지다.

## 24. 반복 생활 주기 (Recurring Life Cycle)

rev 2 까지 이 프로토타입은 **끝이 있는 시연**이었다. 첫 식사·첫 휴식·첫 배변을 한 번씩 보여주고
나면 보리는 영원히 걸어다니기만 했다. rev 3 은 그 뒤를 잇는다.

```
첫 세션          →  기본 생활 루프를 배운다 (그대로 유지)
그 다음          →  평범한 자율 생활
                    쓰다듬기 · 식사 · 피로 · 잠 · 배변 · 놀이가 자연히 반복된다
                    사용자는 언제든 다시 개입할 수 있다
```

목표는 '유한한 튜토리얼'이 아니라 **살아 있는 반려동물 시뮬레이션**으로 읽히는 것이다.

### 24.1 타이머 구조 — 스케줄러는 하나뿐

타이밍 규칙을 파일 곳곳에 흩지 않는다. 바꿀 값은 전부 `LIFE` 한 곳에 있다.

```js
var LIFE = {
  rewardCooldownMs:  45000,            // 하트 보상 반복 방지 (4종 공통)
  mealIntervalMs:   [45000,  75000],   // LOW-FI_COMPRESSED_MEAL_INTERVAL
  satietyDecayMs:   [60000,  90000],
  fatigueGainMs:    [35000,  50000],
  funDecayMs:       [75000, 120000],
  sleepDurationMs:   9000,
  majorEventGapMs:  [8000,   15000],
  clockMs:           1000,
  bowelByAnswer: { ... }               // Q5 응답별
};
```

중첩된 `setTimeout` 사슬을 쌓지 않는다. 대신 **생활 시계 하나**가 1초마다 돌며
`state.due` 에 담긴 **절대 시각**을 확인한다.

```js
state.due  = { satiety, fatigue, fun, meal, bowel }   // 절대 시각(ms)
state.want = { sleep, poop, meal }                    // 다음 조용한 박자에 꺼낼 사건
```

이 구조가 보장하는 것:

| 요구 | 어떻게 만족하는가 |
|---|---|
| 조정이 쉽다 | 숫자가 `LIFE` 한 곳에 모여 있다 |
| QA 압축이 쉽다 | 진행자 패널에서 모든 `due` 를 한 번에 당길 수 있다 |
| 규칙 중복이 없다 | 각 주기가 정확히 한 곳에서만 갱신된다 |
| 중복 스케줄러가 없다 | `startLifeClock()` 은 이미 돌고 있으면 새로 만들지 않는다 |
| Home↔상점 왕복에 안전하다 | `due` 가 절대 시각이라 진행이 0 으로 되돌아가지 않는다 |
| 초기화 시 누수가 없다 | `stopLifeClock()` + `clearTimers()` 가 시계·잠 타이머를 모두 정리한다 |
| 나중에 실제 시간축으로 교체하기 쉽다 | `due` 를 실제 경과 시간으로 바꾸면 된다 |

### 24.2 피로 → 잠 → 리셋

```
깨어 있는 생활
  → (35~50초) 피로도 1
  → (35~50초) 피로도 2
  → (35~50초) 피로도 3  → 졸린 티 (하아암… + 머무는 시간 1.6배)
  → 다음 조용한 박자에 잠
  → 잠 9초 (놓인 쉼터가 있으면 그 자리를 더 좋아한다)
  → 잠이 끝나면  피로도 0
  → 다시 처음부터, 세션이 끝날 때까지 무한히
```

- **피로도는 잠이 끝난 뒤에** 0 이 된다. 잠들 때가 아니다.
- **자는 동안에는 피로가 쌓이지 않는다.**
- 별도의 '수면' 과제나 체크리스트를 만들지 않았다.
- **잠자리를 사야 잘 수 있는 것이 아니다.** `rest_surface` 오브젝트가 있으면 그 자리를 선호할 뿐이고,
  없으면 평범한 유효 위치에서 잔다.
- 잠은 일회성 튜토리얼 사건이 아니다. 주기의 일부다.

### 24.3 반복 쓰다듬기 — 상호작용과 보상을 분리한다

```
쓰다듬기 상호작용  →  언제나 가능. 보리는 언제나 반응한다.
하트 보상          →  반파밍 쿨다운(45초)의 대상.
```

쿨다운 때문에 **쓰다듬기를 막지 않는다.** 쿨다운 중에도

- 유효한 문지르기는 그대로 인식된다
- 보리는 그대로 좋아한다 (`♥ 보리가 기분 좋아해요 · 머리`)
- 하트만 추가로 나오지 않는다
- **'쿨다운' 안내나 남은 시간 표시가 없다**

### 24.4 반복 식사

```
제품 개념 | 대략 4~6시간마다 다음 식사 맥락
Low-fi    | LOW-FI_COMPRESSED_MEAL_INTERVAL = 45~75초 (랜덤)
```

한 끼를 **완료한 시점**부터 다음 식사 맥락을 예약한다. 완전히 결정적이지 않게 범위 안에서 흔든다 —
로봇처럼 정확한 간격이면 살아 있는 느낌이 깨진다.

식사 맥락이 다시 열릴 때:

- **팝업으로 밀지 않는다.** 밥그릇이 이미 있으면 보리가 그 앞으로 가서 `킁킁` 한다.
- 밥그릇이 아직 없을 때만 놓아주기 제안을 띄운다(미응답 질문은 덮지 않는다).
- 먹이면 포만감 +1, 하트는 기존 반파밍 규칙을 따른다.
- **안 먹여도 재촉하지 않는다.** 다음 기회만 조용히 다시 잡는다.
- 굶주림·건강 악화·부정적 결과가 없다.

포만감은 60~90초마다 −1 (최소 0). 회복량은 rev 2 와 같은 **+1 을 유지**했다.
한 번에 여러 칸을 올리면 이해가 쉬울 수는 있지만, 기존 동작을 바꿀 근거가 없어 보존했다.

### 24.5 반복 배변 — Q5 응답을 실제로 쓴다

첫 배변 → 청소 → Q5 흐름은 그대로다. **Q5 응답 이후의 배변 간격이 그 응답을 따른다.**

| Q5 응답 | Low-fi 압축 간격 |
|---|---|
| 하루 1회 미만 | 150~180초 |
| 1회 | 120~150초 |
| 2회 | 90~120초 |
| 3회 | 70~100초 |
| 4회 이상 | 50~80초 |
| (응답 전) | 90~120초 — 2회/일 상당의 중립 기본값 |

범위 안에서 약간 흔든다. **이것이 최종 생리 모델이라고 주장하지 않는다.** 비례만 맞춘 압축값이다.

- 청소는 **여전히 선택**이다. 안 치워도 질병·패널티·죄책감·경고 단계가 없다.
- **치우지 않은 배변이 있으면 새 배변을 겹쳐 만들지 않는다.** 시계가 조용히 미룬다.
- 첫 배변은 첫 식사 국면이 열린 뒤부터 예약된다 — 배변이 밥그릇 제안보다 먼저 나와
  첫 세션의 학습 순서를 흐트리지 않게.

### 24.6 사건 조정 (Event arbitration)

식사 맥락 · 졸림→잠 · 새 배변 · 상황형 제안은 **주요 사건**이다.
한 번에 하나만 주의를 요구하고, 사건 사이에 **8~15초의 조용한 간격**을 둔다.

우선순위: **잠 > 배변 > 첫 식사 제안 > 반복 식사 맥락**.
잠이 가장 앞서는 이유는 그것이 요구가 아니라 보리 자신의 상태이기 때문이다.

**검증 중 고친 것**: 처음에는 '미응답 질문이 떠 있으면 주요 사건을 멈춘다'로 만들었다.
그러자 참가자가 밥그릇 제안에 답하지 않은 채로 두면 **잠도 배변도 영구히 멈춰**
보리가 걷기만 하는 죽은 상태가 됐다. 지금은 조정 규칙이 **'조용한 간격'만** 보고,
`sugKey` 는 **새 질문을 띄우는 경로에서만** 확인한다. 생리는 멈추지 않는다.

스케줄러는 참가자에게 보이지 않는다. `다음 사건이 시작됨` 이 아니라 `보리가 살고 있다` 로 읽혀야 한다.

### 24.7 첫 세션 → 반복 생활 전환

첫 세션의 학습 순서는 그대로다.

```
첫 만남 → 탭 힌트 → 보리 탭 → 확대 → 문지르기 → 첫 하트 → 상점 소개(1회) → 밥그릇 제안
```

그 뒤로 죽은 상태가 없다. 첫 주기가 끝나면

- 이동이 계속된다
- 쓰다듬기는 언제나 가능하다
- 식사 맥락이 다시 온다
- 피로가 다시 쌓이고 다시 잔다
- 배변이 다시 일어난다
- 놀이는 언제나 가능하다
- 하트 보상이 반파밍 규칙 아래 다시 발생한다

### 24.8 제품 시간 vs Low-fi 시간

| | 제품 개념 | Low-fi (이번 회차) |
|---|---|---|
| 식사 | 대략 4~6시간마다 | 45~75초 |
| 배변 | 개인화 응답을 따름 | 50~180초 (응답별) |
| 피로 | 깨어 있는 동안 누적 | 35~50초마다 +1 |
| 포만감 감소 | 식사 간격에 비례 | 60~90초마다 −1 |
| 즐거움 감소 | 훨씬 완만 | 75~120초마다 −1 |
| 잠 | 실제 수면 시간 | 9초 |
| 쓰다듬기 | 언제나 가능 | 동일 (보상만 45초 쿨다운) |

**Low-fi 의 초를 제품 규칙으로 제시하지 않는다.** 한 세션 안에서 주기를 관찰 가능하게 만들려고
압축한 테스트 픽스처다. 생리 모델도 경제 밸런스도 아니다.

### 24.9 이번 회차에서 여전히 실험적인 것

| 항목 | 왜 미확정인가 |
|---|---|
| 모든 압축 간격 | 실제 세션 길이·방문 패턴 데이터가 없다 |
| 게이지 해상도 3칸 | 3 vs 5 vs 연속 중 무엇이 읽기 쉬운지 미검증 |
| 피로도의 빈 막대 표현 | '부족'으로 오독될 수 있다 (H-X3) |
| 이상 상태 도달 난이도 | 피로도 0 창이 좁아 보너스가 너무 드물 수 있다 |
| Q5 → 배변 간격 매핑 | 비례만 맞춘 것이고 실제 생리와 무관하다 |
| 사건 간격 8~15초 | 실기기에서 충분히 '조용한'지 미검증 |
| 잠 9초 | 너무 짧아 잠으로 안 읽힐 수 있다 |
| 식사 회복 +1 | 한 번에 여러 칸이 이해가 쉬울 수 있으나 근거가 없어 보존했다 |

## 부록 A. 진행자 지침 — 설명하면 안 되는 것

| 설명 금지 | 이유 |
|---|---|
| 하트를 어떻게 버는지 | H-E 무효화 |
| 상점이 어디 있는지 | H-F 무효화 |
| 게이지가 무엇이고 어떻게 올리는지 | H-X, H-W 무효화 |
| 피로도의 방향(낮을수록 좋다)을 알려주는 것 | H-X3 무효화 |
| 피로가 쌓이면 잠을 잔다는 것 | H-Y2 무효화 |
| 식사·배변이 다시 온다는 것 | H-Z4 무효화 |
| 만실 보너스의 존재 | H-W 무효화 |
| 출석 보상 구조 | H-Z 무효화 |
| 산 행동이 언제 나오는지 | H-G 무효화 |
| 배변 흔적을 눌러야 한다는 것 | H-N 무효화 |
| 편집으로 오브젝트를 옮길 수 있다는 것 | H-M 무효화 |

참가자가 **직접 물으면** 답한다. 다만 답한 시점을 기록한다 — 그 지점이 발견성 실패 지점이다.

막혀서 30초 이상 정지하면 순서대로, **정확히 3개**만:

1. "화면을 좀 더 둘러보셔도 돼요."
2. "보리를 눌러 보세요."
3. "손가락으로 보리를 천천히 쓰다듬어 주세요."

## 부록 B. 진행자 전용 조작

`D` 키 또는 좌상단 3회 탭으로 진행자 패널. **참가자 화면에는 노출되지 않는다.**

연속 방문 시뮬레이션: `다음 날 방문(+1)` / `이틀 뒤 방문(연속 끊김)` /

### rev 3 검증 중 발견해 고친 실제 결함

1. **미응답 질문이 생활을 영구 정지시켰다.** 조정 규칙이 `sugKey` 를 보게 만든 탓에,
   밥그릇 제안에 답하지 않으면 잠도 배변도 오지 않고 보리가 걷기만 했다.
   → 조정은 '조용한 간격'만 보고, `sugKey` 는 새 질문을 띄우는 경로에서만 확인하도록 바꿨다.
2. **잠들 때마다 생활 루프 사슬이 하나씩 늘어났다.** 도착 콜백이 `goSleep()` 이 잡은
   `idleTimer` 를 덮어써 `lifeTick` 사슬이 둘로 갈라졌다.
   → 사건이 시작됐으면(`state.life !== 'idle'`) 도착 콜백이 다시 예약하지 않도록 했다.
3. **깨어날 예약이 지워질 수 있었다.** 잠이 `idleTimer` 를 공유해, 자는 동안의
   `renderHome()`/`startLife()` 가 깨어날 타이머를 취소하면 영구 수면이 됐다.
   → 잠에 전용 핸들(`sleepTimer`)을 주고, `startLife()` 는 자는 중이면 아무것도 하지 않는다.

세 결함 모두 **영구적인 죽은 상태 또는 스케줄러 증식**으로 이어지는 것이었고,
단일 상호작용 테스트로는 드러나지 않았다. 반복 주기를 실제로 여러 바퀴 돌려야 보였다.
