# StayPet Low-fi UX Review — Codex V2

검수 기준: `docs/UX_FINAL.md`를 UX source of truth로 두고 `docs/USER_FLOW.md`, `docs/LOWFI_WIREFRAME_SPEC.md`, 현재 `lowfi/index.html`, `lowfi/styles.css`를 대조했다. 정적 코드 확인뿐 아니라 참가자 모드에서 Critical Path와 Home 후속 시나리오를 실제로 조작했다.

확인된 사실과 추정을 구분한다.

- **브라우저에서 확인:** 기본 정보 완료 조건, Q1, 생성 대기, 후보·보정 진입, 이동 영역 토글·복구, 첫 만남 자동 전환, Home 힌트, Q2 행동 변화, 밥그릇 배치·급식, Q5 청소 후 노출·지속, 미응답 질문 충돌.
- **코드에는 있으나 이번 자동 조작으로 확인하지 못함:** 450ms press-and-hold 판정. 실제 대상 터치 기기에서 별도 확인이 필요하다.
- **제품 값이 아님:** 생성 소요 시간과 이동 영역 최소 6칸. 전자는 아직 확정되지 않았고 후자는 Low-fi 임시 파라미터다.

# 1. Overall assessment

이번 버전은 이전의 45개 정적 프레임보다 크게 개선됐다. 이동 영역, 보정, 첫 만남, Home, Q2, 밥그릇, Q5가 실제 상태 변화로 연결되며 참가자 화면도 기본값에서는 진행자 정보 없이 시작한다. 특히 다음은 사용자 테스트에 필요한 최소 충실도에 도달했다.

- 이동 영역의 타일 토글, 재탭 해제, 실행 취소, 초기화, 최소 기준 미달 차단
- 첫 만남의 CTA 없는 자동 진행과 Home 연결
- Q2 응답에 따른 실제 위치·유휴 이동 폭 변화
- 밥그릇 배치 후 `인지 → 이동 → 먹기 → 일상 복귀`
- 배변 흔적 발견·청소 후 Q5 제안, `잘 모르겠어요` 미노출, 미응답 상태에서도 Home 사용
- 보정의 2개 대표 속성, 직전 변경 되돌리기, 원본 복원, 속성 단위 실패 복구

그러나 현재 그대로는 주 Critical Path를 참가자 입력만으로 끝까지 완주할 수 없다. 생성 대기에서 성공 완료를 발생시키는 진행자용 이벤트가 없고, 직접 문지르기 제스처도 실제 브라우저 드래그에서 계속 짧은 탭으로 판정됐다. 또한 일부 필수 상태가 누락돼도 진행할 수 있고, 참가자가 누를 수 있는 no-op CTA와 개인화 가설의 정답을 미리 말하는 문구가 남아 있다.

결론적으로 **UX 구조의 재설계는 필요 없지만, 신뢰할 수 있는 테스트를 위해 소수의 동작·테스트 인프라 수정이 먼저 필요하다.**

# 3. Remaining P0 — must fix before user testing

아래는 단순 완성도 문제가 아니라 현재 테스트 결과를 무효화하거나 심하게 왜곡하는 항목만 포함한다.

## P0-1. 생성 성공 전환을 진행자가 발생시킬 수 없다 — 테스트 인프라

Q1 확정 후 `gen-wait`에 도달한 뒤 6.5초 이상 기다려도 화면은 그대로였다. 참가자에게 성공 CTA를 주는 것은 잘못이지만, 진행자에게도 `생성 완료 성공` 이벤트가 없어서 직접 `candidates` 화면으로 점프해야 한다. 이는 참가자가 “기다린 결과 자동으로 후보가 도착했다”는 인과를 경험하지 못하게 한다.

수정 범위는 제품 UX가 아니라 테스트 인프라다.

- 진행자 패널에만 `생성 성공 완료` 이벤트를 둔다.
- 실행 시 참가자 화면이 별도 CTA 없이 자동으로 후보 선택으로 전환되게 한다.
- 고정 20초·90초 같은 시간을 제품 전제로 넣지 않는다. 진행자가 관찰 상황에 맞춰 성공 신호를 보낸다.
- 실패·진행 중·완료 복귀는 기존처럼 별도 시나리오로 유지한다.

## P0-2. 필수 입력과 후보 선택의 완료 조건이 source of truth와 다르다

브라우저에서 종·성별을 명시적으로 선택하지 않고 이름만 입력한 뒤 `다음`을 눌러 사진 단계로 진행할 수 있었다. 코드상 `species`가 처음부터 `강아지`로 저장되고 완료 조건은 종·이름만 검사하며 성별은 검사하지 않는다. `UX_FINAL.md`는 성별을 P0 필수 입력으로 유지한다.

후보 화면에서는 아무 후보도 고르지 않은 상태에서 `조금 다듬기`를 눌러 보정으로 진입할 수 있었다. 이 경우 “처음 후보”가 어떤 후보인지 정해지지 않아 후보 비교·보정 가설이 성립하지 않는다.

최소 수정:

- 종은 화면에서 사용자가 명시적으로 선택하기 전까지 미선택 상태여야 한다.
- 종·이름·성별이 모두 유효할 때만 다음 단계가 활성화돼야 한다.
- 후보 확정뿐 아니라 보정 진입도 후보 선택 후에만 가능해야 한다.

## P0-3. 핵심 rub/drag가 실제 입력에서 안정적으로 판정되지 않는다

현재 mental model은 올바르게 바뀌었다. 그러나 확대된 캐릭터의 머리에서 여러 지점을 거쳐 26px보다 긴 drag를 반복 입력했음에도 결과는 모두 `보리가 눈을 깜박였어요 · 짧은 접촉`이었다. 코드에 press-and-hold 대체 판정은 존재하지만 이번 브라우저 조작 도구로는 실제 450ms 지속 입력을 독립 확인하지 못했다.

첫 하트는 가치 B의 도달점이므로 “코드에 조건이 있다”만으로 충분하지 않다. 실제 테스트에 사용할 모바일 브라우저·터치 기기에서 다음을 직접 확인해야 한다.

1. 한 번의 자연스러운 rub가 본 쓰다듬기로 판정되는가.
2. 선호 부위 rub는 하트, 비선호 부위 rub는 중립 반응인가.
3. 짧은 탭은 하트를 만들지 않는가.
4. press-and-hold가 rub가 어려운 참가자에게 실제 대안이 되는가.

재현되면 이동량 누적 방식만 고치면 되며 UX 구조를 바꿀 필요는 없다.

**권장 canonical rule:** `rub/drag = 기본 쓰다듬기`, `press-and-hold = 접근성 대안`, `짧은 탭 = 짧은 접촉`으로 통일한다. 같은 부위 반복 탭을 본 쓰다듬기로 승격하는 옛 문구는 제거하는 편이 낫다. 반복 탭은 우연한 연타만으로 하트를 만들어 “문지른다”는 핵심 mental model을 흐리고 탭과 쓰다듬기의 경계를 불안정하게 만든다. 이 권고는 아직 원문을 수정하라는 뜻이 아니라, 문서와 구현 중 하나를 정할 때의 기준이다.

## P0-4. 참가자·진행자 모드가 입력 상황에서 완전히 격리되지 않는다 — 테스트 인프라

기본 진입은 참가자 모드지만 전역 `D` 단축키가 입력 요소를 구분하지 않는다. 이름 입력창에서 `d`를 누르자 진행자 패널, 가설 태그, 화면 점프 도구가 즉시 노출됐다. 이는 영문 이름 입력을 포함한 테스트를 오염시킨다.

최소 수정:

- 텍스트 입력·선택 입력에 포커스가 있을 때는 `D` 단축키를 무시한다.
- 진행자 전환은 좌상단 3회 탭 또는 입력 포커스 밖의 조합키로만 허용한다.
- 참가자에게 진행자 패널이 한 번이라도 보이면 해당 세션의 자연 발견성 측정은 폐기해야 한다.

## P0-5. 보이는 no-op CTA가 Critical Path와 복구 시나리오에 남아 있다

실제 확인한 no-op은 다음과 같다.

- 주 사진 화면의 `동영상 추가 (선택)`
- 사진 품질 문제 화면의 `이 사진 교체`, `나중에 계속`
- 사진 업로드 실패 화면의 `사진 2 다시 시도`, `사진 2 삭제`

이 요소는 참가자가 자연스럽게 선택할 수 있고, 특히 현재 프로토타입이 별도 `복구 · 예외` 시나리오를 지원한다고 선언했기 때문에 정적 placeholder로 둘 수 없다. 눌러도 아무 일도 없으면 복구 가능성보다 프로토타입 결함을 측정하게 된다.

Low-fi에서 실제 파일 선택·업로드를 구현할 필요는 없다. 각 버튼이 최소한 `성공 유지 / 실패 항목 제거 / 교체된 placeholder / 보류 상태` 중 해당 상태로 전환되게 하거나, 이번 테스트 범위에서 검증하지 않을 요소는 참가자 화면과 테스트 과제에서 제거해야 한다.

## P0-6. 개인화 인식 가설이 설명 문구와 질문 상태 충돌로 왜곡된다

Q2에는 응답 전 `답하면 움직이는 정도가 달라져요`, 응답 직후 `더 활발해졌어요` 또는 `차분해졌어요`가 나온다. 실제 이동 변화는 충분히 분명했지만, H16은 참가자가 **행동 변화를 스스로 인지하는지**를 확인하는 가설이다. 현재 문구는 테스트할 정답을 전후로 직접 알려 준다.

또 미응답 Q2가 떠 있는 상태에서 배변 흔적을 청소하자 질문 제목이 Q2에서 Q5로 바뀌었다. 즉 Q2는 답할 때까지 유지되지 않고 Q5에 덮어써졌다. 단일 `sugKey` 상태가 원인이다. 이는 최신 미응답 유지 결정과 직접 충돌한다.

최소 수정:

- Q2 테스트에서는 결과를 설명하는 문구를 제거하고 실제 움직임 변화만 남긴다. 저장 피드백이 필요하다면 행동 변화의 정답을 말하지 않는 중립 피드백이어야 한다.
- 새 상황이 발생해도 기존 미응답 질문을 교체하거나 소멸시키지 않는다.
- Low-fi에서는 복잡한 질문 스케줄러를 만들지 말고, 기존 질문이 있는 동안 새 질문을 덮어쓰지 않는 최소 보호만 둔다. 여러 미응답 질문의 동시 노출·대기열 정책은 이 Low-fi에서 새로 확정하지 않는다.

# 4. P1 — recommended improvements

1. **Q5 노출을 청소 완료 피드백 뒤로 조금 더 분리한다.** 현재 청소 직후 Q5는 즉시 뜨지 않지만, `치웠어요`가 1.5초 유지되는 동안 Q5가 약 0.9초 후 나타나 약 0.6초 겹친다. 흔적이 제거됐다는 사실은 먼저 성립하지만 감정적 순서는 여전히 급하다.
2. **첫 확대 안내는 최초 1회만 보여준다.** `UX_FINAL.md`는 첫 확대 때 한 번만 문지르는 방법을 알리도록 한다. 현재 `손가락으로 문질러 보세요`는 확대할 때마다 다시 나타난다.
3. **반응 문구에서 내부 부위명 노출을 제거하는 안을 테스트한다.** 현재 반응 뒤의 `· 머리`, `· 등`은 invisible hit area를 사후에 정답 영역처럼 학습시킨다. 하트·중립 반응만으로도 개인화 가설을 확인할 수 있다.
4. **확대 종료의 보조 복구를 맞춘다.** 명시적 `✕`는 충분히 찾을 수 있지만 source of truth의 시스템 뒤로가기와 안전한 빈 여백 탭은 아직 없다. H11이 명시적 닫기 발견만 보는 1차 테스트라면 현 상태로 충분하고, 종료 복구까지 시험할 때만 추가한다.
5. **후보 재생성 패널에서 기본 후보 footer를 숨긴다.** 현재 `regen` 상태에서도 `이 모습으로 계속 / 다시 준비하기 / 지금은 그만 보기` footer가 남아 있어 재생성 선택지와 경쟁한다.
6. **첫 만남 재개의 의미를 통일한다.** `meet-resume`은 “이어서 볼게요”라고 하지만 `이어서 보기` CTA 뒤 첫 만남을 처음부터 다시 실행한다. 회복 시나리오를 실제 행동 테스트로 쓸 경우 재개 또는 재시작 중 하나만 표현해야 한다.
7. **진행자 시나리오 시작 시 상태를 명확히 초기화한다.** 현재 시나리오 버튼은 첫 화면으로 점프할 뿐 상태를 초기화하지 않는다. 발견성 시나리오를 눌러도 이전의 유효 탭 기록이 남아 힌트가 발생하지 않았고, 별도 `Home 초기화` 후에야 2회 탭 힌트를 확인했다. 자동 초기화가 아니라면 진행자 스크립트에 필수 초기 상태를 명시해야 한다.
8. **개인화 경로 진입의 검증 범위를 명시한다.** `보리에 대해 더 알려주기`는 진행자 직접 점프로만 들어갈 수 있다. H17이 목록 자체의 설문성만 보는 것이라면 충분하지만, Home에서 이 경로를 발견하는지까지 측정할 수는 없다.
9. **사진 성공 상태의 조작 단위를 최소한 보존한다.** 현재 `사진 추가` 한 번으로 사진 2장이 동시에 생긴다. Critical Path 속도 측정용으로는 충분하지만, 추가·삭제·교체의 이해를 측정하는 세션에는 적합하지 않다.
10. **문서의 오래된 문구를 다음 동기화 때 정리한다.** `UX_FINAL.md`와 `LOWFI_WIREFRAME_SPEC.md` 일부에는 반복 탭, Q5 유예 선택지, 무시 시 소멸 같은 과거 결정이 남아 있다. 이번 검수에서는 최신 구체 결정과 실제 사용자 지시를 우선했지만 이후 제작자가 다시 회귀할 위험이 있다.

# 5. New issues introduced by the revision

이번 재작성으로 새로 생겼거나 단일 프로토타입 구조에서 처음 드러난 문제는 다음과 같다.

- 전역 `D` 키가 이름 입력과 충돌해 참가자 화면을 오염시킨다.
- 생성 성공을 발생시키는 진행자 이벤트가 없어 “자동 완료”를 화면 직접 점프로 대체한다.
- `candidate = 0` 초기 상태에서도 보정 진입이 가능하다.
- 하나의 `sugKey`만 사용해 새 Q5가 기존 미응답 Q2를 덮어쓴다.
- Q2 변화가 실제로 구현된 대신, 변화의 의미를 설명하는 문구가 H16의 관찰을 편향시킨다.
- rub/drag 거리를 `movementX/Y` 누적으로만 판정하는 현재 동작이 실제 브라우저 입력에서 안정적으로 재현되지 않았다.
- 시나리오 버튼이 상태 초기화 없이 화면만 이동해 이전 시나리오의 기록이 다음 시나리오를 오염시킨다.
- 재생성 패널과 기본 후보 footer가 동시에 노출된다.

| Interaction | 판정 | 실제 확인 및 해석 |
|---|---|---|
| **generation waiting** | **Insufficient** | 과제 없는 대기, 이탈, 복귀, 실패 화면은 존재한다. 하지만 성공 완료 이벤트가 없어 Critical Path가 멈춘다. 제품 시간이 아닌 진행자 제어 성공 신호가 필요하다. |
| **tuning** | **Sufficient after entry guard** | 형태·색/무늬를 바꾸면 현재 미리보기가 변하고, 2회 변경 후 undo는 변경 수를 2→1로 줄였다. 강제 실패 시 실패한 속성만 이전 값으로 돌아가고 다른 변경은 유지됐다. 원본 복원도 별도다. 후보 미선택 진입만 막으면 된다. |
| **movement area** | **Sufficient** | 토글·재탭 해제·undo·reset·인라인 오류·유효 완료가 모두 동작한다. 6칸은 임시값으로 명시돼 있다. 연결성 판정이나 실제 이동 물리까지 추가할 필요가 없다. |
| **first meeting** | **Main flow sufficient / recovery partial** | 메인 장면은 CTA 없이 약 5.2초 뒤 Home으로 연결됐고 오브젝트도 없었다. 재개 화면은 실제 재개가 아니라 CTA 후 처음부터 재생하므로 회복 가설에는 부족하다. |

# 7. What should NOT be implemented further in Low-fi

다음은 이미 검증에 충분하거나 현재 가설과 무관하므로 더 구현하지 않는다.

- 실제 AI 생성, 실제 생성 시간, 백엔드 작업 큐, 푸시 알림
- 실제 사진·동영상 업로드 파이프라인과 기기 권한 처리. 버튼별 최소 상태 변화만 있으면 된다
- 자율 NPC 생활 엔진, 정교한 경로 탐색, 물리 충돌, 종별 전체 행동 세트
- 이동 영역 연결성 판정, 자유 곡선 brush, 확대·미리보기 모드, 제품용 최소 타일 값 확정
- 보정의 나머지 4개 이상 속성, 고해상도 캐릭터 생성, 실제 생성 재시도
- 잠자리·장난감의 완결 구현. 밥그릇 하나가 후행 배치와 오브젝트 학습 고리를 대표한다
- 여러 질문의 장기 스케줄러·알림·배지. 이번 Low-fi는 미응답 보존과 덮어쓰기 방지만 확인하면 된다
- 모든 Home 기능을 설명하는 튜토리얼이나 inactivity detector
- 상점, 앨범, 추억 사진, 함께한 날, 꾸미기 편집기, 최종 내비게이션
- 실제 통화·백그라운드 lifecycle. 첫 만남 재개 가설에는 최소 시뮬레이션이면 된다
- High-fi 애니메이션과 감정 표현의 세분화

# 8. Recommended participant test scenarios

모든 상태를 한 세션에 강제로 연결하지 않는다. 참가자 화면에는 진행자 패널을 노출하지 않고, 진행자는 각 시나리오 시작 전 필요한 상태를 초기화한다.

## Scenario 1. Main Critical Path and TTFV-A/B

1. 로그인 방식 선택
2. 종·이름·성별 입력
3. 사진 추가와 Q1 선택
4. 생성 대기 진입
5. 진행자가 보이지 않는 `생성 성공 완료` 신호 실행
6. 후보 선택, 필요하면 보정, 확정
7. 공간 사진과 이동 영역 조정
8. 첫 만남 자동 진행
9. 아무 요구 없는 Home 관찰
10. 캐릭터 발견 → 확대 → 직접 rub → 선호 부위 하트 → 종료

측정: 첫 만남 도달 시간, 첫 하트 도달 시간, 중단·망설임 지점. petting P0가 실제 기기에서 해결되기 전에는 이 시나리오를 실행하지 않는다.

## Scenario 2. Candidate dissatisfaction and tuning recovery

- 후보를 선택한 뒤 `다시 준비하기`, 원본 보기, 보정 진입을 자발적으로 구분하는지 본다.
- 형태·색/무늬를 두 번 바꾸게 한 뒤 `직전 변경 되돌리기`와 `처음 후보로`를 구분하는지 본다.
- 한 속성 실패를 발생시켜 다른 변경이 유지됐다고 이해하는지 본다.
- `지금은 그만 보기` 후 재진입에서 후보가 갑자기 노출되지 않는 흐름을 확인한다.

## Scenario 3. Movement-area recovery

- 자동 추정 타일이 켜진 상태에서 수정하게 한다.
- 같은 타일 재탭으로 제외, 실행 취소, 전체 초기화를 관찰한다.
- 너무 작은 영역 완료 시 스스로 복구하는지 본다.
- 6칸이라는 숫자 자체에 대한 선호는 묻지 않는다. 이는 제품 정책이 아니다.

## Scenario 4. Home discovery

- 완전히 초기화된 Home에서 아무 설명 없이 관찰한다.
- 캐릭터를 먼저 찾는지, 빈 공간을 누르는지 기록한다.
- 빈 공간 2회 후 힌트가 과도하거나 적절한지 확인한다.
- 유효 상호작용 뒤에는 힌트가 다시 나오지 않는지 확인한다.

## Scenario 5. Q2 progressive personalization

- 첫 교감과 분리된 세션에서 기본 움직임을 먼저 보게 한다.
- 진행자가 이동 맥락만 발생시킨다.
- 결과를 설명하는 문구 없이 Q2에 답하게 한 뒤 움직임 변화를 스스로 알아차리는지 묻는다.
- “답하기 전 보리가 틀린 상태였다”고 느끼는지도 확인한다.

## Scenario 6. Bowl placement and feeding

- 식사 맥락에서 밥그릇 제안
- 잘못된 위치와 유효 위치 배치
- 배치 후 별도 설명 없이 밥그릇을 다시 누르는지 관찰
- 인지, 이동, 먹기, 일상 복귀를 하나의 결과로 이해하는지 확인

## Scenario 7. Q5 and persistent unanswered state

- 배변 흔적 발생 → 발견 → 탭 → 청소 완료 → Q5 제안 순서
- Q5에 답하지 않은 채 캐릭터 확대·쓰다듬기·밥그릇 사용을 시도
- 질문이 계속 보이는 것이 관찰을 방해하는지 확인
- 별도 세션에서 미응답 Q2가 이미 떠 있을 때 배변을 청소해 기존 질문이 보존되는지 확인

## Scenario 8. Recovery states

- 생성 대기 이탈·진행 중 복귀·실패 복귀
- 사진 품질 문제의 추가·교체·보류
- 파일 단위 업로드 재시도·삭제
- 첫 만남 중단 후 복귀

이 시나리오는 해당 CTA가 실제 상태를 바꾸도록 수정된 뒤에만 행동 테스트로 사용한다. 수정하지 않는 항목은 정적 화면 이해 인터뷰로만 다루고 성공률을 기록하지 않는다.

# 9. Final verdict

## READY AFTER MINOR FIXES

수정 우선순위:

1. **진행자용 `생성 성공 완료` 신호를 추가해 Critical Path를 자동 전환으로 연결한다.**
2. **실제 대상 터치 기기에서 rub·hold를 검증하고, rub가 탭으로 판정되는 문제를 해결한 뒤 canonical rule을 `rub + hold 대안`으로 통일한다.**
3. **참가자 오염과 상태 우회를 막는다: 입력 중 `D` 차단, 종·이름·성별 필수, 후보 선택 전 보정 진입 차단.**
4. **개인화 테스트를 보호한다: Q2 결과 설명 제거, 기존 미응답 질문 덮어쓰기 방지.**
5. **테스트 범위에 남길 사진·동영상·복구 CTA는 최소 상태 변화를 구현하고, 나머지 no-op CTA는 해당 테스트에서 제외한다.**

이 다섯 묶음은 새 UX Flow나 기능 추가가 아니라 현재 확정 UX를 테스트 가능하게 만드는 좁은 수정이다. 완료되면 Low-fi 구조를 더 확장하지 않고 사용자 테스트로 넘어가는 것이 맞다.
