# 1. 현재 Flow의 핵심 문제

## 1.1 첫 가치 경험보다 입력과 설정이 앞선다

현재 Flow는 로그인 이후 종, 이름/성별, 사진, 추가 사진, 선택적 동영상, 생활 문답 6개, AI 생성, 후보 선택/보정, 공간 사진, 이동 영역, 기본 오브젝트 배치를 모두 지나야 첫 만남에 도달한다. 각 단계는 개별적으로 이유가 있지만, 사용자에게는 “아이를 보기 전에 계속 자료를 제출하고 설정하는 경험”으로 누적될 수 있다.

특히 사진을 고르는 행위 자체가 정서적으로 무거울 수 있다는 점을 고려하면, 단순한 탭 수보다 **정서적 부담 뒤에 보상이 얼마나 빨리 오는가**가 더 중요하다.

## 1.2 종·이름·성별이 하나의 짧은 맥락인데 화면이 분리되어 있다

세 정보는 모두 “누구를 만들 것인가”라는 한 가지 사용자 목표에 속한다. 종 선택과 이름/성별을 별도 화면으로 나누면 단계가 늘어나고, 각 화면의 정보량은 지나치게 적다. 하나의 기본 정보 단계로 합쳐도 사용자의 판단 난이도는 크게 증가하지 않는다.

## 1.3 선택적인 자료가 필수 경로처럼 느껴질 위험이 있다

동영상은 P1이며 선택 사항이지만 사진 다음에 독립 단계로 등장하면 사용자는 “건너뛰면 결과가 나빠지는가?”라고 느끼기 쉽다. 추가 사진 여부를 별도 분기로 묻는 것도 같은 문제를 만든다. 선택 자료는 핵심 경로를 막는 화면이 아니라 사진 단계 안에서 보조적으로 다루는 편이 자연스럽다.

## 1.4 여섯 문답이 짧더라도 설문 피로가 누적된다

문답 내용은 생활 개인화와 직접 연결되므로 제거할 근거는 없다. 문제는 질문 수보다 다음과 같은 구조다.

- 매 질문이 별개의 화면 전환처럼 느껴질 수 있다.
- 답을 고른 뒤 매번 같은 CTA를 반복하면 기계적인 설문처럼 느껴진다.
- 어느 정도 남았는지 모르면 실제보다 길게 느껴진다.
- 사진과 동영상 업로드 직후 이어지면 입력 작업이 연속된다.

여러 질문을 한 화면에 빽빽하게 묶는 것은 인지 부하를 줄이기보다 설문지 느낌을 강화한다. 한 번에 한 질문을 유지하되 하나의 연속된 문답 단계로 인식시키고, 현재 위치와 수정 가능성을 명확히 하는 편이 적절하다.

## 1.5 생성 대기와 문답이 직렬로 놓여 있다

외형 생성이 사진·종·기본 정보만으로 시작 가능하다는 기술적 전제가 성립한다면, 사진 검증 직후 생성을 백그라운드에서 시작하고 사용자가 생활 문답을 답하는 동안 처리할 수 있다. 현재처럼 문답이 끝난 뒤 생성을 시작하면 사용자는 입력을 모두 마친 뒤 다시 기다려야 한다.

이 병렬 처리가 기술적으로 불가능하다면 기존 순서를 유지해야 한다. 따라서 이는 제품 정책 변경이 아니라 **기술 검증이 선행되어야 하는 UX 추천**이다.

## 1.6 후보 불만족 시 복구 경로들의 관계가 불명확하다

현재의 `다시 만들기`, 사진 추가, 이전 정보 수정, 간단 보정은 서로 다른 문제를 해결하지만 하나의 복구 체계로 정리되어 있지 않다.

- 전체적인 인상이 다름 → 다른 후보 생성
- 특정 부위만 다름 → 간단 보정
- 원본 사진이 부족하거나 잘못됨 → 사진 추가·교체 후 재생성
- 종·이름·성별 등 입력이 잘못됨 → 이전 정보 수정

`다시 만들기` 하나가 이 모든 의미를 맡으면 사용자는 어떤 데이터가 유지되고 무엇이 사라지는지 알기 어렵다. 새 후보가 성공하기 전까지 기존 후보를 보존하는 안전한 복구 구조가 필요하다.

## 1.7 이동 영역 지정은 첫 사용자의 학습 비용이 가장 큰 단계다

Brush, 지우기, 초기화, 미리보기는 이미지 편집 경험을 요구한다. 사용자는 다음을 즉시 이해해야 하지만 현재 문서만으로는 세부 로직이 정해져 있지 않다.

- 어디를 칠해야 하는가
- 칠한 영역과 캐릭터의 실제 이동이 어떻게 연결되는가
- 한 손가락 칠하기와 사진 확대·이동을 어떻게 구분하는가
- 잘못 칠한 부분을 어느 수준까지 되돌릴 수 있는가
- 완료 전에 결과를 어떻게 예측하는가

단순 설명문보다 짧은 최초 안내, 조작 중 즉각 피드백, 실행 취소, 실제 이동 예시가 함께 있어야 한다.

## 1.8 첫 만남 직전의 오브젝트 배치가 감정 흐름을 끊는다

후보를 고르고 실제 공간까지 선택한 시점은 기대감이 가장 높은 구간이다. 여기서 밥그릇·잠자리·장난감을 모두 배치하게 하면 첫 만남이 보상이 아니라 설정 완료 뒤의 보상처럼 느껴진다.

**추천:** 이동 영역 확인 뒤 첫 만남을 먼저 보여주고, 기본 오브젝트의 수동 배치는 Home에서 첫 생활을 시작하는 맥락으로 옮긴다. 첫 만남에 오브젝트가 반드시 필요하다면 시스템이 임시 위치를 제안하고 사용자가 나중에 수정하는 방식도 후보가 될 수 있다. 자동 임시 배치 여부는 사용자 결정과 기술 검토가 필요하다.

## 1.9 Home의 몰입과 발견성이 충돌한다

Home에서 버튼을 최소화하면 몰입은 좋아지지만, 캐릭터·밥그릇·장난감·배변 흔적이 터치 가능하다는 사실은 약해진다. 모든 기능을 설명하는 튜토리얼은 몰입을 깨고 기억되지도 않는다. 첫 만남 직후에는 캐릭터 상호작용 하나만 알려 주고, 다른 기능은 실제 상황이 발생할 때 한 번씩 알려 주는 점진적 발견 구조가 필요하다.

## 1.10 중단·실패 시 처음부터 다시 해야 한다는 불안이 크다

사진 업로드, 문답, 생성, 이동 영역은 시간과 감정이 들어가는 작업이다. 앱 종료나 네트워크 실패 후 진행 내용이 보존되는지 불분명하면 이탈 가능성이 높아진다. 단계별 저장, 실패 지점에서의 재시도, 상위 입력 변경 시 영향 범위 안내가 Flow의 일부로 설계되어야 한다.

# 2. 추천 전체 Flow

## 2.1 추천 원칙

1. 첫 만남 전에는 외형 생성과 실제 공간에 필요한 정보만 필수로 받는다.
2. 확정된 6개 문답은 유지하되 하나의 연속된 문답 단계로 구성한다.
3. 가능하면 생성 처리와 문답 시간을 겹쳐 체감 대기를 줄인다.
4. 선택 자료는 핵심 경로를 막지 않는다.
5. 불만족 시 재생성부터 요구하지 않고 문제 원인에 맞는 복구 경로를 제공한다.
6. 첫 만남 직전에는 기술적 설정을 최소화한다.
7. Home 튜토리얼은 기능 목록이 아니라 실제 행동 순간에 하나씩 나타난다.
8. 뒤로가기와 재시도는 이미 완료한 작업을 기본적으로 보존한다.

## 2.2 신규 사용자 추천 Journey

1. **앱 실행 및 세션 확인**
   - 미로그인 사용자는 로그인으로 이동한다.
   - 인증됐지만 등록이 중단된 사용자는 저장된 마지막 안전 지점에서 재개한다.
   - 설정 완료 사용자는 경과시간 시뮬레이션 뒤 Home으로 이동한다.
2. **로그인**
   - 현재 확정된 일반, Kakao, Google 세 경로를 유지한다.
3. **반려동물 기본 정보 한 화면** `추천`
   - 강아지/고양이, 이름, 성별을 같은 단계에서 입력한다.
4. **사진 준비**
   - 최소 1장의 유효한 사진을 추가한다.
   - 추가 사진의 추가·삭제·교체를 같은 단계에서 처리한다.
   - 선택적 동영상은 별도 필수 단계가 아니라 이 단계의 보조 행동으로 두거나 Low-fi 1차에서 제외한다.
5. **캐릭터 생성 처리 시작** `기술 검증 필요`
   - 유효 사진과 필수 기본 정보가 준비되면 외형 생성을 백그라운드에서 시작한다.
6. **생활 문답 6개**
   - 한 번에 한 질문을 보여 주는 하나의 연속 단계로 구성한다.
   - `현재 질문/전체 질문`을 알려 주고 이전 답을 즉시 수정할 수 있게 한다.
   - 여러 질문을 한 화면에 묶지 않는다.
7. **생성 대기 또는 결과 준비 확인**
   - 문답 중 생성이 끝났다면 바로 후보로 이동한다.
   - 아직 진행 중이라면 입력을 다시 요구하지 않는 대기 상태를 제공한다.
8. **후보 2~3개 비교 및 선택**
   - 후보를 먼저 선택하고, 바로 확정하거나 선택한 후보를 보정할 수 있다.
   - 불만족 시 `다른 후보 생성`, `사진 수정`, `이전 정보 수정`을 구분한다.
9. **선택적 간단 보정**
   - 귀·털·체형·눈·색·무늬를 수정하고 원본/직전 상태로 되돌릴 수 있다.
10. **실제 공간 사진 업로드**
11. **이동 가능 영역 지정 및 미리보기**
   - Brush를 기본 도구로 시작하되 지우기, 실행 취소, 초기화, 미리보기, 완료를 제공한다.
12. **첫 만남** `추천 순서 변경`
   - 기본 오브젝트 수동 배치보다 먼저 진행한다.
   - 5~10초 후 `{이름}가 우리 집으로 찾아왔어요.`를 보여 주고 Home으로 자연스럽게 이어진다.
13. **Home 첫 도착**
   - 잠시 관찰할 여지를 준 뒤 캐릭터 직접 터치만 최초로 안내한다.
14. **캐릭터 확대 및 첫 쓰다듬기**
   - 선호 부위 반응으로 생활 문답이 실제 경험에 연결됐음을 처음 확인한다.
15. **기본 오브젝트 배치** `추천 순서 변경`
   - Home 맥락에서 밥그릇·잠자리·장난감을 한 번에 하나씩 배치하거나, 임시 배치를 나중에 수정한다.
16. **Home의 점진적 발견**
   - 밥, 놀이, 배변은 관련 상태가 처음 발생할 때 각각 한 번만 안내한다.
   - 꾸미기 외 P1 기능은 첫 핵심 교감 이후에만 노출한다.

## 2.3 추천 Flow가 성립하지 않을 때의 안전한 대안

- 백그라운드 생성이 불가능하면 문답 완료 후 생성을 시작하되, 입력값을 모두 저장하고 실패 시 생성만 재시도한다.
- 첫 만남에 오브젝트가 기술적으로 필수라면 세 오브젝트를 모두 정밀 배치시키기보다 시스템 제안 위치를 확인하는 최소 단계로 축소한다.
- 선택적 동영상이 생성 전에 반드시 필요하다는 기술 근거가 생기더라도 독립 화면에서 선택을 강요하지 않고 사진 단계 안에서 명확히 선택 사항으로 제공한다.
- 이동 미리보기가 실제 캐릭터로 불가능하면 최소한 이동 가능·불가능 영역과 예시 경로를 확인한 뒤 편집으로 돌아갈 수 있게 한다.

# 3. 화면별 UX 분석

아래의 “화면”은 시각 레이아웃을 뜻하지 않는다. 같은 화면 안에서 바뀌는 상태도 사용자의 목표와 시스템 반응이 달라지면 별도 UX 단계로 분석한다.

## 3.1 앱 실행 및 세션 분기

- **사용자의 현재 목표:** 앱을 시작해 중단했던 설정 또는 현재 Home으로 빠르게 들어간다.
- **이 단계에 들어온 이유:** 앱을 실행했기 때문이다.
- **꼭 필요한 이유:** 로그인 여부와 반려동물 설정 완료 여부에 따라 서로 다른 안전한 시작점을 정해야 한다.
- **가장 먼저 인지해야 하는 정보:** 사용자가 읽거나 선택할 정보보다 앱이 정상적으로 시작되고 있다는 사실이다.
- **사용자가 알아야 하는 정보:** 이전 설정이 있으면 이어진다는 점. 단, 이를 매번 설명하는 별도 화면은 필요하지 않다.
- **사용자가 해야 하는 행동:** 정상 상태에서는 없음.
- **주요 CTA:** 오류가 발생했을 때의 재시도만 필요하다.
- **즉시 피드백:** 빈 화면에 머물지 않고 로그인, 재개 단계 또는 Home으로 전환한다.
- **다음 단계:** 미로그인 → 로그인, 인증·미완료 → 마지막 저장 단계, 설정 완료 → 경과시간 처리 후 Home.
- **뒤로가기 / 수정 방법:** 진입 분기 자체에는 수정할 값이 없다.
- **취소 / 이탈 가능성:** 앱 종료는 언제나 가능하고 데이터 손실을 만들지 않아야 한다.
- **오류 / 실패 / 빈 상태:** 세션 확인 실패 시 저장된 설정을 삭제하거나 신규 사용자로 오판하지 않고 재시도한다.
- **망설임 / 혼란:** 긴 무응답은 앱 고장으로 받아들여진다.
- **불필요한 인지 부하:** 세션 확인을 별도 설명 화면이나 활동 보고서로 만드는 것.
- **합칠 수 있는지:** 앱 실행과 세션 확인은 하나의 시스템 단계로 합친다.
- **첫 만남 지연 요소:** 필요 이상의 시작 화면 체류와 반복 소개.

## 3.2 로그인

- **사용자의 현재 목표:** 자신에게 편한 방식으로 인증하고 다음 단계로 간다.
- **이 단계에 들어온 이유:** 로그인된 세션이 없기 때문이다.
- **꼭 필요한 이유:** 생성 결과, 공간, 생활 상태를 사용자 계정에 연결해야 한다는 현재 제품 Flow 때문이다.
- **가장 먼저 인지해야 하는 정보:** `로그인하기`, `Kakao로 시작하기`, `Google로 시작하기` 세 가지 선택이 있다는 점.
- **사용자가 알아야 하는 정보:** 각 버튼이 일반 인증인지 외부 계정 인증인지, 취소하면 이 화면으로 돌아온다는 점.
- **사용자가 해야 하는 행동:** 세 로그인 방식 중 하나를 선택하고 필요한 인증을 완료한다.
- **주요 CTA:** 세 로그인 버튼. 어느 하나를 임의로 기본 선택으로 만들 근거는 현재 문서에 없다.
- **즉시 피드백:** 탭 접수, 외부 인증 전환, 앱 복귀 후 처리 상태를 지연 없이 알린다.
- **다음 단계:** 신규 → 기본 정보, 등록 중단 → 마지막 저장 단계, 기존 → Home.
- **뒤로가기 / 수정 방법:** 외부 인증에서 취소하면 로그인 선택으로 돌아오고 다른 방식을 선택할 수 있다.
- **취소 / 이탈 가능성:** 경험 가치를 보기 전 인증을 요구하므로 첫 이탈 가능성이 있다. 별도 소개 화면을 추가하는 방식으로 해결하지는 않는다.
- **오류 / 실패 / 빈 상태:** 네트워크, 사용자 취소, 동의 거부, 공급자 오류를 구분하고 같은 위치에서 재시도한다.
- **망설임 / 혼란:** `로그인하기`가 신규 일반 가입도 포함하는지, 소셜 방식 간 계정 연결이 가능한지가 불명확하다.
- **불필요한 인지 부하:** 로그인 전에 서비스 설명 슬라이드, 기능 목록, 긴 약속을 추가하는 것.
- **합칠 수 있는지:** 앱 소개와 합치지 않고 현재처럼 로그인 목적 하나만 유지한다.
- **첫 만남 지연 요소:** 일반 로그인 상세 절차가 길거나 외부 인증 뒤 앱으로 복귀하지 못하는 경우.

## 3.3 반려동물 기본 정보 `추천: 통합 화면`

- **사용자의 현재 목표:** 만들 반려동물이 누구인지 최소 정보로 정한다.
- **이 단계에 들어온 이유:** 신규 계정 인증이 끝났기 때문이다.
- **꼭 필요한 이유:** 종은 생성과 종별 질문을, 이름은 첫 만남과 Home 개인화를, 성별은 현재 P0 입력을 구성한다.
- **가장 먼저 인지해야 하는 정보:** 이 단계가 강아지/고양이, 이름, 성별을 정하는 짧은 기본 정보 단계라는 점.
- **사용자가 알아야 하는 정보:** 입력값은 다음 단계에서도 돌아와 수정할 수 있다는 점. 성별이 결과에 미치는 영향은 아직 문서상 불명확하다.
- **사용자가 해야 하는 행동:** 종 하나 선택, 이름 입력, 문서에 따라 정해질 성별 선택지 중 하나 선택.
- **주요 CTA:** 필수 입력을 검토한 뒤 사진 단계로 가는 `다음` 의미의 CTA.
- **즉시 피드백:** 각 값의 선택·입력 상태와 누락·형식 문제를 해당 항목에서 즉시 보여준다.
- **다음 단계:** 사진 준비.
- **뒤로가기 / 수정 방법:** 로그인으로 돌아가도 입력 초안을 보존하고, 이후 단계에서도 이 화면으로 돌아와 수정한다.
- **취소 / 이탈 가능성:** 이름을 입력하는 순간 정서적 부담이 생길 수 있다. 재촉하거나 감정을 해석하는 문구를 사용하지 않는다.
- **오류 / 실패 / 빈 상태:** 빈 이름, 미선택 종·성별, 저장 실패를 각각 처리하고 다른 정상 입력은 보존한다.
- **망설임 / 혼란:** 성별 선택지와 필수 이유, 이름 허용 문자·길이가 미확정이다.
- **불필요한 인지 부하:** 세 항목을 각각 독립 화면으로 만들거나 아직 필요하지 않은 상세 프로필을 묻는 것.
- **합칠 수 있는지:** 종·이름·성별을 합치는 것을 추천한다. 종을 먼저 선택해 이후 문구 분기를 안정시킨다.
- **첫 만남 지연 요소:** 한두 번의 선택을 위해 화면을 반복 전환하는 것.

## 3.4 사진 및 선택 자료

- **사용자의 현재 목표:** 캐릭터가 닮게 만들어질 수 있는 사진을 제공하고 필요하면 자료를 더한다.
- **이 단계에 들어온 이유:** 기본 정보가 준비됐고 외형 생성에 사진이 필요하기 때문이다.
- **꼭 필요한 이유:** 최소 1장의 사진은 반실사형 2.5D 외형 생성의 핵심 입력이다. 동영상은 선택적 P1 입력이다.
- **가장 먼저 인지해야 하는 정보:** 사진 추가가 이 단계의 필수 행동이라는 점. 금지된 카피 `사진 1장만으로도 시작할 수 있어요`는 사용하지 않는다.
- **사용자가 알아야 하는 정보:** 어떤 파일이 업로드 중·완료·실패인지, 추가 자료는 선택인지, 삭제·교체할 수 있는지.
- **사용자가 해야 하는 행동:** 최소 한 장의 유효한 사진을 선택하고 필요하면 추가 사진·동영상을 관리한다.
- **주요 CTA:** 사진 추가와, 유효 사진이 준비된 뒤 다음 단계로 가는 CTA. 동영상 추가는 보조 행동이다.
- **즉시 피드백:** 사진 단위 미리보기와 업로드 상태, 완료 시 `업로드 완료`, 실패한 파일의 이유와 재시도를 제공한다.
- **다음 단계:** 생활 문답. 기술적으로 가능하면 사진 검증 직후 백그라운드 생성을 시작한다.
- **뒤로가기 / 수정 방법:** 기본 정보로 돌아가도 업로드 성공 자료를 보존한다. 각 사진과 동영상을 삭제·교체할 수 있다.
- **취소 / 이탈 가능성:** 사진첩 권한 거부, 적절한 사진을 찾는 부담, 사진을 다시 보는 정서적 부담 때문에 이탈할 수 있다. 진행 초안을 저장한다.
- **오류 / 실패 / 빈 상태:** 권한 거부, 취소, 지원하지 않는 파일, 손상 파일, 일부 업로드 실패를 파일 단위로 처리한다.
- **망설임 / 혼란:** 권장 사진 조건, 허용 개수·용량, 동영상이 결과에 얼마나 필요한지가 미정이다.
- **불필요한 인지 부하:** `추가 사진이 있나요?`, `동영상을 올릴까요?`를 각각 독립 화면으로 묻는 것.
- **합칠 수 있는지:** 필수 사진, 추가 사진, 선택 동영상을 하나의 자료 단계에서 관리하는 것을 추천한다.
- **첫 만남 지연 요소:** 선택적 동영상의 독립 화면, 전체 업로드 재시도, 업로드가 끝난 뒤에야 생성 준비를 시작하는 구조.

## 3.5 생활 문답 1~6 `하나의 연속 단계`

- **사용자의 현재 목표:** 기억하는 생활 습관을 짧게 답해 행동과 교감 반응을 개인화한다.
- **이 단계에 들어온 이유:** 외형 자료가 준비됐고 자율 생활 파라미터가 필요하기 때문이다.
- **꼭 필요한 이유:** 쓰다듬기, 활동, 식사, 발성, 배변, 수면은 P0 생활 경험과 직접 연결된다.
- **가장 먼저 인지해야 하는 정보:** 현재 질문 내용과 전체 6개 중 몇 번째인지.
- **사용자가 알아야 하는 정보:** 정답은 없고 이전 답을 수정할 수 있으며, 답이 질병·죽음·방치 패널티를 만들지 않는다는 제품 원칙. 이 원칙을 매 질문마다 반복 설명할 필요는 없다.
- **사용자가 해야 하는 행동:** 현재 질문의 선택지를 고르고 다음으로 이동한다.
- **주요 CTA:** `이전`, `다음`; 마지막 CTA는 이후 캐릭터 결과로 이어진다는 의미를 예고해야 한다.
- **즉시 피드백:** 선택 상태, 저장 상태, 질문 번호 변경을 즉시 보여준다.
- **다음 단계:** 다음 질문 또는 생성 결과 준비 상태.
- **뒤로가기 / 수정 방법:** 한 단계씩 이전 질문으로 돌아가 선택값을 바꾸며 다른 답은 유지한다.
- **취소 / 이탈 가능성:** 반복 탭과 기억 부담으로 중단할 수 있으므로 질문별 임시 저장 후 재개한다.
- **오류 / 실패 / 빈 상태:** 미선택 질문에서는 해당 질문 안에서 안내하고, 저장 실패 시 선택값을 잃지 않는다.
- **망설임 / 혼란:** 쓰다듬기 복수 선택 여부, 주관적 빈도의 기준, `잘 모르겠어요` 허용 여부가 미확정이다.
- **불필요한 인지 부하:** 한 화면에 여러 질문을 몰아넣기, 매 질문마다 긴 설명, 답 선택 직후 예고 없는 자동 이동.
- **합칠 수 있는지:** 여섯 질문을 한 화면에 합치지는 않는다. 하나의 문답 흐름 안에서 한 번에 한 질문을 유지한다.
- **첫 만남 지연 요소:** 선택적 자료 뒤 바로 이어지는 설문 피로와 문답 종료 후 별도로 시작되는 생성 대기.

## 3.6 캐릭터 생성 진행

- **사용자의 현재 목표:** 입력을 잃지 않고 결과가 준비되기를 기다린다.
- **이 단계에 들어온 이유:** 외형 생성 요청에 필요한 입력이 준비됐기 때문이다.
- **꼭 필요한 이유:** 처리 시간이 즉시 끝나지 않을 수 있으므로 시스템 상태와 복구 가능성을 알려야 한다.
- **가장 먼저 인지해야 하는 정보:** 생성 요청이 정상 접수됐는지, 사용자가 추가로 해야 할 일이 있는지.
- **사용자가 알아야 하는 정보:** 앱을 잠시 나가도 작업이 유지되는지, 실패 시 무엇을 다시 해야 하는지. 구체 시간은 근거 없이 약속하지 않는다.
- **사용자가 해야 하는 행동:** 기본적으로 없음. 실패했을 때만 재시도 또는 입력 수정 경로를 선택한다.
- **주요 CTA:** 정상 처리 중에는 불필요한 CTA를 두지 않고, 실패 시 `다시 시도`와 문제 입력 수정 경로를 제공한다.
- **즉시 피드백:** 접수, 처리 중, 완료, 실패를 서로 구분한다. 가짜 진행률이나 확정되지 않은 남은 시간을 사용하지 않는다.
- **다음 단계:** 후보 2~3개.
- **뒤로가기 / 수정 방법:** 뒤로가면 진행 중 요청이 어떻게 되는지 알려야 한다. 추천은 요청을 유지하고 사용자가 결과로 다시 돌아오게 하는 방식이다.
- **취소 / 이탈 가능성:** 무응답·긴 대기·백그라운드 실패가 이탈 원인이다. 완료 후 안전한 재진입 지점이 필요하다.
- **오류 / 실패 / 빈 상태:** 생성 실패는 사진·문답 초기화가 아니라 생성 요청만 재시도한다. 반복 실패 시 사진 수정으로 안내한다.
- **망설임 / 혼란:** 재시도하면 새 비용·횟수가 소모되는지, 기존 결과가 사라지는지 미정이다.
- **불필요한 인지 부하:** AI 기술 설명, 반복 팁, 사용자가 해결할 수 없는 내부 단계 노출.
- **합칠 수 있는지:** 가능하면 문답과 시간상 병렬 처리한다. 결과 준비가 끝났다면 별도 대기 화면을 생략한다.
- **첫 만남 지연 요소:** 문답 완료 후 처음 생성 요청을 보내는 직렬 구조와 실패 시 전체 재입력.

## 3.7 캐릭터 후보 선택

- **사용자의 현재 목표:** 자신이 기억하는 모습과 가장 가까운 후보를 비교하고 안전하게 선택한다.
- **이 단계에 들어온 이유:** 후보 2~3개가 생성됐기 때문이다.
- **꼭 필요한 이유:** AI가 하나의 결과를 강요하지 않고 사용자가 유사도를 판단하게 한다.
- **가장 먼저 인지해야 하는 정보:** 후보끼리 비교할 수 있고 하나를 선택한 뒤 확정·보정할 수 있다는 점.
- **사용자가 알아야 하는 정보:** 선택은 확정 전까지 바꿀 수 있고, 만족하지 않으면 보정·사진 수정·다른 후보 생성 중 문제에 맞는 경로를 고를 수 있다는 점.
- **사용자가 해야 하는 행동:** 후보를 살펴보고 하나를 선택한다.
- **주요 CTA:** 선택 후보 확정. 간단 보정과 불만족 복구는 보조 행동이다.
- **즉시 피드백:** 어떤 후보가 현재 선택됐는지, 크게 확인한 대상이 무엇인지 즉시 알려준다.
- **다음 단계:** 직접 확정하면 공간 사진, 보정을 선택하면 보정 단계.
- **뒤로가기 / 수정 방법:** 후보 선택을 바꾸거나 사진·기본 정보로 돌아간다. 상위 입력 수정이 재생성을 요구하면 영향 범위를 먼저 알린다.
- **취소 / 이탈 가능성:** 모든 후보가 닮지 않았거나 재생성 결과를 예측할 수 없으면 이탈 가능성이 매우 높다.
- **오류 / 실패 / 빈 상태:** 일부 후보만 로드되지 않으면 정상 후보를 유지하고 실패분만 재시도한다. 후보가 전혀 없으면 생성 재시도를 제공한다.
- **망설임 / 혼란:** `다시 만들기`가 기존 후보 삭제, 사진 변경, 같은 입력 재생성 중 무엇인지 불명확하다.
- **불필요한 인지 부하:** 선택 전에 모든 보정값을 보여주거나 재생성 경로를 하나의 모호한 행동으로 묶는 것.
- **합칠 수 있는지:** 후보 선택, 보정 진입, 최종 확정을 같은 후보 단계에서 시작할 수 있다. 보정 편집 자체는 별도 상태가 필요하다.
- **첫 만남 지연 요소:** 비교 기준 불명확, 기존 후보를 잃는 재생성, 불필요한 보정 강제.

## 3.8 캐릭터 간단 보정 `선택 상태`

- **사용자의 현재 목표:** 전반적으로 닮은 후보의 특정 외형 차이만 조정한다.
- **이 단계에 들어온 이유:** 후보는 마음에 들지만 귀·털·체형·눈·색·무늬 중 일부가 다르기 때문이다.
- **꼭 필요한 이유:** 사진을 다시 올리고 전체 생성하는 것보다 작은 차이를 직접 복구할 수 있다.
- **가장 먼저 인지해야 하는 정보:** 지금 수정 중인 기준 후보와 수정 가능한 범위.
- **사용자가 알아야 하는 정보:** 언제든 원본 또는 직전 상태로 되돌릴 수 있고, 확정 전에는 결과가 Home에 적용되지 않는다는 점.
- **사용자가 해야 하는 행동:** 속성을 선택하고 값을 변경한 뒤 비교·확정한다.
- **주요 CTA:** 보정 확정. 되돌리기와 취소는 항상 안전한 보조 행동이다.
- **즉시 피드백:** 값 변경이 결과에 반영되는 중인지, 반영됐는지, 실패했는지를 해당 속성 단위로 보여준다.
- **다음 단계:** 확정 후 공간 사진.
- **뒤로가기 / 수정 방법:** 후보 선택으로 돌아갈 때 변경을 유지할지 폐기할지 결정한다. 원본 복원과 직전 변경 취소를 구분한다.
- **취소 / 이탈 가능성:** 조절 기준이 모호하거나 변화가 느리면 반복 조작 피로가 생긴다.
- **오류 / 실패 / 빈 상태:** 특정 보정 실패 시 마지막 성공 상태와 원본 후보를 보존한다.
- **망설임 / 혼란:** 각 보정값의 범위, 상호 영향, 변경 결과 생성 시간이 미정이다.
- **불필요한 인지 부하:** 모든 속성을 반드시 수정하게 하거나 RPG 캐릭터 꾸미기처럼 많은 값을 노출하는 것.
- **합칠 수 있는지:** 후보 선택 화면에서 진입하되 편집 중에는 하나의 집중된 보정 상태를 유지한다.
- **첫 만남 지연 요소:** 선택 보정을 필수 단계처럼 보이게 하는 것과 작은 변화마다 긴 재생성을 요구하는 것.

## 3.9 실제 공간 사진

- **사용자의 현재 목표:** 캐릭터가 생활할 실제 공간 한 곳을 정한다.
- **이 단계에 들어온 이유:** 캐릭터 외형이 확정됐고 Home 배경이 필요하기 때문이다.
- **꼭 필요한 이유:** 실제 집 공간에서 생활한다는 StayPet의 핵심 차별점을 만든다.
- **가장 먼저 인지해야 하는 정보:** 캐릭터가 생활할 공간 사진 한 장을 선택하는 단계라는 점.
- **사용자가 알아야 하는 정보:** 다음 단계에서 이동 영역을 직접 지정하고, 사진은 교체할 수 있다는 점.
- **사용자가 해야 하는 행동:** 공간 사진을 선택·업로드하고 결과를 확인한다.
- **주요 CTA:** 공간 사진 업로드, 성공 후 이동 영역 지정으로 가는 CTA.
- **즉시 피드백:** 미리보기, 업로드 상태, 실패 이유, 성공 상태를 보여준다.
- **다음 단계:** 이동 가능 영역 편집.
- **뒤로가기 / 수정 방법:** 보정·후보로 돌아가도 공간 사진 초안을 보존한다. 사진 교체 시 기존 이동 영역이 무효화됨을 먼저 알린다.
- **취소 / 이탈 가능성:** 적절한 공간 사진이 없거나 방 전체가 보여야 한다고 오해하면 중단할 수 있다.
- **오류 / 실패 / 빈 상태:** 권한 거부, 파일 오류, 업로드 실패를 사진 단계에서 해결한다.
- **망설임 / 혼란:** 촬영을 제공하는지, 어떤 구도까지 허용하는지, 공간 사진 변경 후 기존 배치 처리 방식이 미정이다.
- **불필요한 인지 부하:** 공간 종류를 분류하게 하거나 첫 등록에서 여러 공간을 요구하는 것.
- **합칠 수 있는지:** 업로드 성공 후 같은 맥락에서 이동 영역 편집으로 이어지되, 조작 목표가 달라 별도 상태는 필요하다.
- **첫 만남 지연 요소:** 사진 선택 실패와 사진 요구 조건의 불명확성.

## 3.10 이동 가능 영역 편집

- **사용자의 현재 목표:** 캐릭터가 자연스럽고 안전하게 움직일 범위를 지정한다.
- **이 단계에 들어온 이유:** 공간 사진만으로 시스템이 사용자 의도를 확실히 알 수 없기 때문이다.
- **꼭 필요한 이유:** 현재 확정된 Home Mode에서 사용자가 이동 영역을 직접 표시한다.
- **가장 먼저 인지해야 하는 정보:** “캐릭터가 다녀도 되는 바닥을 칠한다”는 하나의 과업과 현재 활성 도구.
- **사용자가 알아야 하는 정보:** 한 손가락 칠하기, 사진 확대·이동 방식, 지우기, 실행 취소, 초기화, 미리보기, 완료의 차이.
- **사용자가 해야 하는 행동:** 영역을 칠하고 잘못된 부분을 복구한 뒤 미리보기로 확인한다.
- **주요 CTA:** 영역 완료. 미리보기는 완료 판단을 돕는 핵심 보조 행동이다.
- **즉시 피드백:** 손가락 경로에 맞춘 영역 변화, 지우기 결과, 유효성 문제, 현재 편집 상태를 지연 없이 보여준다.
- **다음 단계:** 추천안에서는 첫 만남. 현재 Flow를 유지하면 오브젝트 배치.
- **뒤로가기 / 수정 방법:** 실행 취소·지우기·초기화로 화면 안에서 복구하고, 사진 단계로 돌아갈 때 편집 초안을 보존한다.
- **취소 / 이탈 가능성:** 이미지 편집에 익숙하지 않거나 결과를 예측하지 못하면 가장 큰 기술적 이탈 지점이 된다.
- **오류 / 실패 / 빈 상태:** 영역 없음, 지나치게 작은 영역, 지원되지 않는 분리 영역, 저장 실패를 완료 시점 전에 안내한다. 유효성 기준은 기술 결정이 필요하다.
- **망설임 / 혼란:** 사진 이동과 칠하기의 제스처 충돌, Brush 크기, 캐릭터 크기 대비 영역 판단.
- **불필요한 인지 부하:** 긴 사전 설명, 처음부터 모든 편집 도구를 동일 중요도로 학습시키는 것.
- **합칠 수 있는지:** 사진 업로드와 연속 진입은 가능하지만 편집 목적이 달라 같은 조작 상태로 합치지는 않는다.
- **첫 만남 지연 요소:** 정밀함을 과도하게 요구하는 것, 실행 취소 부재, 결과를 볼 수 없는 채 완료를 요구하는 것.

## 3.11 첫 만남

- **사용자의 현재 목표:** 선택한 캐릭터가 실제 공간에 등장하는 순간을 보고 Home으로 들어간다.
- **이 단계에 들어온 이유:** 캐릭터와 최소 공간 설정이 준비됐기 때문이다.
- **꼭 필요한 이유:** 설정 과정의 감정적 보상이자 제품의 핵심 약속을 처음 체감하는 순간이다.
- **가장 먼저 인지해야 하는 정보:** 캐릭터가 자신의 공간에 나타났다는 사실. 기능 설명이나 메뉴보다 장면 자체가 우선이다.
- **사용자가 알아야 하는 정보:** 별도 완료 작업 없이 Home으로 이어진다는 점은 흐름으로 이해할 수 있어야 한다.
- **사용자가 해야 하는 행동:** 필수 행동 없음. 5~10초의 진행을 본다.
- **주요 CTA:** 기본적으로 없음. 건너뛰기·재생 여부는 사용자 결정이 필요하다.
- **즉시 피드백:** 장면이 정상 진행되고 있다는 연속적인 변화와 확정 문구 `{이름}가 우리 집으로 찾아왔어요.`를 제공한다.
- **다음 단계:** 완료 페이지 없이 Home.
- **뒤로가기 / 수정 방법:** 진행 중 실수로 이전 설정으로 돌아가지 않게 한다. Home 이후 공간·외형 수정 경로는 별도다.
- **취소 / 이탈 가능성:** 앱 중단 시 장면을 영구히 놓쳤다고 느끼지 않도록 다음 실행에서 안전하게 이어가거나 다시 보여 주는 정책이 필요하다.
- **오류 / 실패 / 빈 상태:** 애니메이션 실패가 첫 만남 자체를 막지 않도록 공간·캐릭터·확정 문구를 보여 주는 안전한 대체 상태가 필요하다.
- **망설임 / 혼란:** 사용자가 탭해야 진행되는지 자동인지 불명확하면 감정에 집중하지 못한다.
- **불필요한 인지 부하:** 튜토리얼, 기능 설명, 오브젝트 배치 지시, 멜로드라마 카피.
- **합칠 수 있는지:** 첫 만남과 Home은 장면 전환 단절 없이 이어지는 하나의 경험이어야 한다.
- **첫 만남 지연 요소:** 이 단계 자체가 아니라 바로 직전의 수동 오브젝트 배치와 과도한 로딩.

## 3.12 Home 첫 도착 및 첫 교감

- **사용자의 현재 목표:** 캐릭터를 바라보고 처음으로 직접 교감한다.
- **이 단계에 들어온 이유:** 첫 만남 장면이 자연스럽게 생활 상태로 전환됐기 때문이다.
- **꼭 필요한 이유:** 생성 콘텐츠가 자율적인 일상 경험으로 바뀌는 핵심 공간이다.
- **가장 먼저 인지해야 하는 정보:** 캐릭터의 위치와 행동, 그리고 캐릭터를 직접 누를 수 있다는 최소한의 단서.
- **사용자가 알아야 하는 정보:** 관찰만 해도 괜찮고, 캐릭터·생활 오브젝트를 직접 터치할 수 있으며 돌봄을 하지 않아도 해로운 패널티가 없다는 원칙.
- **사용자가 해야 하는 행동:** 필수 행동 없음. 추천 첫 행동은 캐릭터 탭 → 확대 → 쓰다듬기다.
- **주요 CTA:** 지배적인 화면 버튼보다 캐릭터 자체가 첫 행동 대상이다.
- **즉시 피드백:** 캐릭터 탭 인지, 확대 전환, 문지른 부위 반응을 연속적으로 제공한다.
- **다음 단계:** 계속 관찰, 쓰다듬기, 기본 오브젝트 배치, 이후 밥·놀이·배변 발견.
- **뒤로가기 / 수정 방법:** Home은 루트이므로 시스템 뒤로가기가 온보딩을 되감지 않는다. 수정은 해당 편집 경로로 들어간다.
- **취소 / 이탈 가능성:** 언제든 종료 가능하며 불이익이 없다. 다음 실행은 현재 생활 상태로 돌아온다.
- **오류 / 실패 / 빈 상태:** 생활 흔적·말풍선이 없는 것은 정상이다. 캐릭터 로드 실패는 생성 결과를 삭제하지 않고 Home에서 재시도한다.
- **망설임 / 혼란:** 무엇을 누를 수 있는지, 확대를 어떻게 종료하는지, 캐릭터가 스스로 생활하는지 알기 어렵다.
- **불필요한 인지 부하:** 첫 진입에 모든 메뉴와 기능을 한꺼번에 설명하는 것.
- **합칠 수 있는지:** 첫 만남, Home 진입, 첫 캐릭터 발견을 끊김 없이 연결한다. 전체 튜토리얼 화면은 합치지 않고 제거한다.
- **첫 만남 지연 요소:** 이미 첫 만남 뒤이므로 해당 없음. 다만 첫 교감 전에 메뉴 설명이 나오면 감정적 정점을 약화한다.

## 3.13 Home 안의 기본 오브젝트 배치 `추천: 첫 만남 뒤`

- **사용자의 현재 목표:** 캐릭터가 생활할 밥그릇·잠자리·장난감의 위치를 정한다.
- **이 단계에 들어온 이유:** 첫 만남과 첫 교감 뒤 생활을 준비하거나, 사용자가 직접 꾸미기에 들어왔기 때문이다.
- **꼭 필요한 이유:** 기본 생활 오브젝트와 행동 연결은 P0이다. 다만 첫 만남 전에 모두 수동 배치할 필요는 확정되지 않았다.
- **가장 먼저 인지해야 하는 정보:** 지금 배치할 오브젝트 하나와 놓을 수 있는 영역.
- **사용자가 알아야 하는 정보:** 위치는 나중에 다시 바꿀 수 있고 기본 생활 오브젝트는 무료라는 확정 원칙.
- **사용자가 해야 하는 행동:** 오브젝트를 유효 위치로 이동하고 해당 배치를 확정한다.
- **주요 CTA:** 현재 오브젝트 배치 확정 또는 전체 변경 저장. 정확한 단위는 사용자 결정이 필요하다.
- **즉시 피드백:** 유효·무효 위치, 현재 선택 대상, 저장 성공·실패를 즉시 알려준다.
- **다음 단계:** 다음 기본 오브젝트 또는 Home 자율 생활.
- **뒤로가기 / 수정 방법:** 직전 위치로 되돌리거나 변경을 폐기하고 Home으로 돌아간다. 이후 꾸미기에서 재배치한다.
- **취소 / 이탈 가능성:** 세 개를 연속 강제하면 첫 교감 직후 다시 설정 과제로 느껴질 수 있다. 나중에 하기 또는 임시 위치 정책이 필요하다.
- **오류 / 실패 / 빈 상태:** 유효 영역 없음, 오브젝트 겹침, 저장 실패 시 마지막 유효 배치를 보존한다.
- **망설임 / 혼란:** 첫 만남 때 기본 오브젝트가 어떻게 존재하는지, 자동 임시 위치와 수동 위치의 관계가 미정이다.
- **불필요한 인지 부하:** 전체 카탈로그·상점·재화를 기본 배치와 함께 보여주는 것.
- **합칠 수 있는지:** 세 오브젝트는 하나의 기본 배치 모드 안에서 순차 처리할 수 있지만 각각의 성공 상태는 독립적이어야 한다.
- **첫 만남 지연 요소:** 추천 순서에서는 첫 만남 뒤이므로 지연하지 않는다.

## 3.14 재방문 Home

- **사용자의 현재 목표:** 지금 캐릭터가 무엇을 하고 있는지 바로 확인한다.
- **이 단계에 들어온 이유:** 설정 완료 후 앱을 다시 실행했기 때문이다.
- **꼭 필요한 이유:** 재방문은 MVP의 Primary 검증 목표다.
- **가장 먼저 인지해야 하는 정보:** 경과시간 결과가 반영된 현재 위치·행동·생활 흔적.
- **사용자가 알아야 하는 정보:** 앱을 꺼둔 동안의 일상을 보고서로 읽을 필요 없이 현재 장면으로 이해할 수 있어야 한다.
- **사용자가 해야 하는 행동:** 없음. 관찰하거나 원하는 직접 상호작용을 선택한다.
- **주요 CTA:** 없음. 캐릭터와 실제 생활 오브젝트가 행동 대상이다.
- **즉시 피드백:** 이전과 달라진 현재 행동·위치·흔적을 일관되게 보여준다.
- **다음 단계:** Home 자율 생활과 직접 교감.
- **뒤로가기 / 수정 방법:** Home 루트 원칙을 유지한다.
- **취소 / 이탈 가능성:** 언제든 종료 가능하며 미접속 기간과 관계없이 불이익이 없다.
- **오류 / 실패 / 빈 상태:** 경과시간 계산 실패 시 부정적 상태를 만들지 말고 안전한 현재 상태로 진입한다.
- **망설임 / 혼란:** 활동 보고서가 없으면 실제로 생활이 이어졌는지 눈치채지 못할 수 있다.
- **불필요한 인지 부하:** 과거 이벤트 목록, 접속하지 않은 시간, 놓친 보상을 진입 팝업으로 보여주는 것.
- **합칠 수 있는지:** 경과시간 계산은 앱 실행 중 시스템 처리로 합치고 Home 앞에 별도 화면을 만들지 않는다.
- **첫 만남 지연 요소:** 신규 첫 만남과 무관하며, 재방문 Home 진입도 보고서 때문에 지연시키지 않는다.

# 4. Element-level UX Flow

이 절은 화면 설명을 반복하는 대신 **각 Element 하나를 사용자가 발견하고, 조작하고, 실패에서 회복해 다음 상태로 가는 독립 Flow**로 다룬다. `추천`으로 표시된 동작은 아직 제품 결정이 아니다.

## 4.1 앱 실행과 로그인

### 4.1.1 앱 실행 및 세션 분기

1. **인지:** 앱 실행 자체가 진입 조작이며 별도 Element 학습은 필요 없다.
2. **사용 동기:** 중단한 설정을 이어가거나 현재 생활을 확인하려 한다.
3. **기대:** 로그인·설정 상태에 맞는 곳으로 자동 이동하고 저장 정보가 유지되기를 기대한다.
4. **조작:** 앱을 실행하거나 백그라운드에서 다시 연다.
5. **즉각적 피드백:** 앱이 응답 중임을 알리고 불필요한 선택 없이 세션을 확인한다.
6. **성공 상태:** 미로그인, 설정 미완료, 설정 완료 중 올바른 상태가 판별된다.
7. **실패 / 오류 상태:** 세션 확인 실패를 신규 상태로 오인하지 않고 같은 정보로 재시도한다.
8. **취소 / 되돌리기 / 수정:** 사용자는 앱을 닫을 수 있으며 저장 데이터는 그대로다.
9. **재조작:** 재실행해도 중복 등록이나 중복 생성이 일어나지 않는다.
10. **다음 상태:** 로그인, 마지막 미완료 단계 또는 경과시간 처리 후 Home.
11. **존재 필요성:** 반드시 필요한 시스템 분기지만 사용자에게 별도 화면으로 오래 노출할 필요는 없다.

### 4.1.2 일반 로그인 버튼

1. **인지:** 첫 화면의 `로그인하기`라는 독립 버튼으로 조작 가능함을 안다.
2. **사용 동기:** 소셜 계정을 사용하지 않거나 기존 일반 계정으로 접근하려 한다.
3. **기대:** 일반 인증 절차가 열리고 성공 후 신규 설정 또는 기존 Home으로 이어질 것으로 예상한다.
4. **조작:** 버튼을 한 번 탭한다. 이메일·휴대전화 등 상세 인증 방식은 사용자 결정이 필요하다.
5. **즉각적 피드백:** 탭 접수와 인증 단계 전환을 즉시 보여주며 처리 중 중복 탭을 막는다.
6. **성공 상태:** 계정 인증과 설정 완료 여부가 확인된다.
7. **실패 / 오류 상태:** 네트워크, 자격 정보, 서버 오류를 구분하고 입력값을 보존한 채 재시도한다. 계정이 없을 때의 가입 전환 방식은 미확정이다.
8. **취소 / 되돌리기 / 수정:** 인증을 취소하면 로그인 선택으로 돌아오고 다른 방식을 고를 수 있다.
9. **재조작:** 처리 중에는 하나의 요청만 유지하고 실패 뒤 재탭은 정상 재시도로 처리한다.
10. **다음 상태:** 신규 기본 정보, 마지막 미완료 단계 또는 Home.
11. **존재 필요성:** 확정된 로그인 방식이므로 필요하다. 다만 `로그인하기`가 신규 일반 가입도 포함하는지는 반드시 결정해야 한다.

### 4.1.3 Kakao 로그인 버튼

1. **인지:** `Kakao로 시작하기`가 외부 계정을 이용하는 독립 선택임을 안다.
2. **사용 동기:** 별도 계정·비밀번호 없이 익숙한 계정으로 빠르게 시작하려 한다.
3. **기대:** Kakao 인증 후 StayPet으로 자동 복귀할 것으로 예상한다.
4. **조작:** 버튼 탭 → Kakao 계정 선택·동의.
5. **즉각적 피드백:** 외부 인증 전환과 앱 복귀 후 처리 상태를 연속해서 알린다.
6. **성공 상태:** StayPet 계정 연결이 완료되고 사용자 상태에 맞게 분기된다.
7. **실패 / 오류 상태:** 사용자 취소, 동의 거부, 인증 만료, 네트워크·공급자 오류를 구분하고 재시도를 제공한다.
8. **취소 / 되돌리기 / 수정:** 취소하면 로그인 화면으로 돌아오며 다른 Kakao 계정 또는 다른 로그인 방식을 선택할 수 있다.
9. **재조작:** 처리 중 중복 인증을 만들지 않고 실패·취소 후에는 다시 시작한다.
10. **다음 상태:** 신규 기본 정보, 마지막 미완료 단계 또는 Home.
11. **존재 필요성:** 빠른 진입을 위한 확정 Element다. 다른 로그인 방식과의 중복 계정 연결·병합 정책은 미확정이다.

### 4.1.4 Google 로그인 버튼

1. **인지:** `Google로 시작하기`가 Google 계정 인증 행동임을 안다.
2. **사용 동기:** 별도 가입 입력 없이 Google 계정으로 시작하려 한다.
3. **기대:** 계정 선택·동의 후 앱으로 돌아와 이어질 것으로 예상한다.
4. **조작:** 버튼 탭 → Google 계정 선택·동의.
5. **즉각적 피드백:** 외부 인증 전환과 복귀 후 결과 처리 상태를 보여준다.
6. **성공 상태:** 인증된 사용자 상태에 맞는 다음 단계가 열린다.
7. **실패 / 오류 상태:** 계정 선택 취소, 동의 거부, 인증 만료, 네트워크 오류를 구분하며 설정 데이터를 삭제하지 않는다.
8. **취소 / 되돌리기 / 수정:** 로그인 화면으로 돌아와 다른 계정이나 방식을 선택한다.
9. **재조작:** 중복 요청을 막고 실패 뒤 같은 버튼으로 재시도한다.
10. **다음 상태:** 신규 기본 정보, 마지막 미완료 단계 또는 Home.
11. **존재 필요성:** 확정된 빠른 로그인 방식이다. Kakao·일반 계정과의 연결 정책은 사용자 결정이 필요하다.

## 4.2 반려동물 기본 정보

### 4.2.1 강아지 / 고양이 선택

1. **인지:** `강아지`, `고양이`가 서로 배타적인 탭 선택지임을 안다.
2. **사용 동기:** 만들 반려동물의 종과 이후 질문·행동 기준을 정하려 한다.
3. **기대:** 선택 종에 맞춰 외형 생성과 짖음/울음 질문, 대표 행동이 달라질 것으로 예상한다.
4. **조작:** 두 선택지 중 하나를 탭한다.
5. **즉각적 피드백:** 선택 항목이 즉시 바뀌고 같은 화면의 이름·성별 입력은 유지된다.
6. **성공 상태:** 하나의 종이 기본 정보 초안에 저장된다.
7. **실패 / 오류 상태:** 미선택 상태로 다음을 누르면 해당 항목에서 선택 필요성을 알리고, 저장 실패 시 화면 선택을 보존한다.
8. **취소 / 되돌리기 / 수정:** 다음 단계 전에는 다른 종을 탭해 바꾼다. 문답 뒤 변경하면 짖음/울음 답을 다시 확인하는 것을 추천한다.
9. **재조작:** 같은 종 재탭은 유지, 다른 종 탭은 대체로 동작한다.
10. **다음 상태:** 같은 기본 정보 단계에서 이름·성별을 완료한다.
11. **존재 필요성:** 생성과 종별 생활에 필수지만 별도 화면일 필요는 없다.

### 4.2.2 이름 입력

1. **인지:** `이름` 입력 영역과 커서·키보드 반응으로 편집 가능함을 안다.
2. **사용 동기:** 첫 만남과 Home에서 사용할 반려동물 이름을 지정하려 한다.
3. **기대:** 입력한 이름이 `{이름}가 우리 집으로 찾아왔어요.` 등 개인화에 그대로 쓰일 것으로 예상한다.
4. **조작:** 입력 영역을 탭하고 이름을 입력·수정한다.
5. **즉각적 피드백:** 문자가 즉시 보이고 유효하지 않은 값은 입력 위치에서 알려준다.
6. **성공 상태:** 유효한 이름이 초안에 저장되고 다음 진행 조건을 충족한다.
7. **실패 / 오류 상태:** 빈 값·공백만 있는 값 등을 해당 위치에서 수정하게 한다. 허용 문자와 길이는 사용자 결정이 필요하다.
8. **취소 / 되돌리기 / 수정:** 내용을 지우거나 바꾸며, 이후 돌아와 수정하면 뒤 단계의 이름도 갱신한다.
9. **재조작:** 기존 값을 보존한 채 다시 편집한다. 키보드 완료가 화면 전체 제출로 오인되지 않게 한다.
10. **다음 상태:** 같은 단계의 남은 입력 또는 사진 준비.
11. **존재 필요성:** 감정적 개인화에 필수지만 독립 화면은 불필요하다.

### 4.2.3 성별 선택

1. **인지:** 제공된 항목이 탭 가능한 단일 선택임을 안다.
2. **사용 동기:** 기억하는 반려동물 정보를 정확히 반영하려 한다.
3. **기대:** 선택이 외형·호칭·행동 중 어떤 부분에 의미 있게 사용될 것으로 예상한다.
4. **조작:** 제공된 성별 선택지 중 하나를 탭한다. 선택지 구성은 아직 미확정이다.
5. **즉각적 피드백:** 현재 선택을 즉시 확인할 수 있다.
6. **성공 상태:** 선택값이 기본 정보 초안에 저장된다.
7. **실패 / 오류 상태:** 필수인데 미선택이면 해당 항목에서 안내하고 저장 실패 시 선택을 보존한다.
8. **취소 / 되돌리기 / 수정:** 다른 항목으로 바꾸거나 이후 기본 정보로 돌아와 수정한다.
9. **재조작:** 같은 항목은 유지, 다른 항목은 대체한다.
10. **다음 상태:** 기본 정보 완료 후 사진 준비.
11. **존재 필요성:** 현재 P0 입력이지만 실제 경험에 미치는 영향은 문서에 없다. 의미 있게 쓰이지 않는다면 필수 여부를 재검토해야 하며, 별도 화면은 필요 없다.

### 4.2.4 기본 정보·자료 단계의 다음 버튼

1. **인지:** 현재 입력을 저장하고 다음 단계로 가는 주요 CTA임을 안다.
2. **사용 동기:** 필요한 입력을 마치고 캐릭터 준비를 계속하려 한다.
3. **기대:** 입력이 보존되고 다음 단계로 한 번만 이동할 것으로 예상한다.
4. **조작:** 버튼을 한 번 탭한다.
5. **즉각적 피드백:** 조건 충족 시 저장·전환 상태를, 미충족 시 누락 항목과 수정 위치를 알려준다.
6. **성공 상태:** 현재 초안이 저장되고 다음 UX 단계가 열린다.
7. **실패 / 오류 상태:** 저장·네트워크 실패 시 값을 유지하고 재시도한다. 업로드 중이면 기다리는 이유와 대상 파일을 알린다.
8. **취소 / 되돌리기 / 수정:** 다음 단계에서 돌아오면 기존 값 그대로 수정할 수 있다.
9. **재조작:** 처리 중 중복 저장·전환을 만들지 않고 오류 뒤 탭은 재시도로 동작한다.
10. **다음 상태:** 기본 정보 → 사진, 사진 → 문답.
11. **존재 필요성:** 여러 값을 검토하는 단계에는 필요하다. 선택 직후 자동 이동으로 바꾸면 오선택 복구가 어려워진다.

## 4.3 사진과 선택적 동영상

### 4.3.1 사진 추가

1. **인지:** 사진을 추가하는 명시적 행동과 빈 자료 상태를 통해 탭 가능함을 안다.
2. **사용 동기:** 실제 모습과 닮은 캐릭터를 만들 참고 자료를 제공하려 한다.
3. **기대:** 선택한 사진이 업로드되고 외형 생성에 사용될 것으로 예상한다.
4. **조작:** 사진 추가를 탭하고 기기에서 사진을 선택한다. 촬영 지원과 최대 장수는 미확정이다.
5. **즉각적 피드백:** 로컬 미리보기, 파일별 업로드 진행, 성공 시 `업로드 완료`를 보여준다.
6. **성공 상태:** 성공한 사진이 목록에 남고 최소 한 장이 준비되면 진행 가능해진다.
7. **실패 / 오류 상태:** 권한 거부, 형식·손상·네트워크 오류를 사진 단위로 처리하며 성공 파일은 유지한다.
8. **취소 / 되돌리기 / 수정:** 사진 선택을 취소하면 기존 목록으로 돌아오고 업로드 중 취소해도 완료 사진은 남긴다.
9. **재조작:** 다시 탭하면 추가 사진을 선택한다. 중복 파일 처리 규칙은 사용자 결정이 필요하다.
10. **다음 상태:** 사진 관리, 선택 동영상 추가 또는 문답.
11. **존재 필요성:** 외형 생성에 필수이며 별도 `추가 사진 여부` 화면보다 같은 단계 안에서 반복 추가하는 것이 자연스럽다.

### 4.3.2 업로드된 사진 삭제 / 교체

1. **인지:** 각 사진에 적용되는 삭제·교체 행동이 대상 사진과 명확히 연결되어 있음을 안다.
2. **사용 동기:** 잘못 고르거나 품질이 낮은 사진을 제거하고 더 적합한 자료를 쓰려 한다.
3. **기대:** 삭제는 그 사진만 제거하고 교체는 새 업로드 성공 뒤 해당 사진만 바꿀 것으로 예상한다.
4. **조작:** 대상 사진의 삭제 또는 교체를 선택하고, 교체 시 새 파일을 고른다.
5. **즉각적 피드백:** 삭제 대상과 결과, 교체 파일의 업로드 상태를 즉시 알린다.
6. **성공 상태:** 다른 사진은 보존된 채 대상만 제거·교체된다.
7. **실패 / 오류 상태:** 마지막 유효 사진 삭제 시 진행 조건을 알린다. 교체 실패 시 기존 사진을 유지한다.
8. **취소 / 되돌리기 / 수정:** 삭제 직후 되돌리기를 추천하며, 교체 선택 취소 시 기존 사진을 유지한다.
9. **재조작:** 반복 삭제 요청을 만들지 않고 교체 뒤 다시 교체·삭제할 수 있다.
10. **다음 상태:** 자료 편집을 계속하거나 문답으로 진행한다.
11. **존재 필요성:** 결과 품질과 직접 연결되어 필요하다. 마지막 사진 손실 위험 때문에 `삭제 후 추가`보다 직접 교체가 안전하다.

### 4.3.3 동영상 추가

1. **인지:** 사진과 구분된 자료 추가 행동이며 **선택 사항**임을 먼저 안다.
2. **사용 동기:** 움직임과 다른 각도를 외형 보조 자료로 더 제공하려 한다.
3. **기대:** 없어도 진행 가능하고, 업로드하면 외형 생성에 보조적으로 쓰일 것으로 예상한다.
4. **조작:** 동영상 추가를 탭하고 파일을 선택한다.
5. **즉각적 피드백:** 파일 식별 정보, 업로드 진행, 완료를 보여준다.
6. **성공 상태:** 동영상이 선택 자료로 저장되며 같은 단계에서 계속 진행할 수 있다.
7. **실패 / 오류 상태:** 권한·형식·용량·길이·네트워크 오류를 구분하며 실패가 필수 사진이나 다음 진행을 막지 않는다.
8. **취소 / 되돌리기 / 수정:** 선택 취소, 업로드 취소, 삭제·교체가 가능해야 한다.
9. **재조작:** 허용 개수가 하나라면 재탭은 교체로 연결한다. 개수·길이·용량은 미확정이다.
10. **다음 상태:** 문답 또는 자료 단계 유지.
11. **존재 필요성:** P1 선택 기능이므로 첫 만남 전 독립 화면은 필요 없다. 첫 Low-fi 포함 여부도 사용자 결정이 필요하다.

### 4.3.4 동영상 건너뛰기

1. **인지:** 독립 동영상 화면을 유지할 경우에만 동영상 없이 정상 진행하는 행동임을 안다.
2. **사용 동기:** 동영상이 없거나 찾기 어렵고 사진만으로 빨리 진행하려 한다.
3. **기대:** 품질 위협이나 불이익 안내 없이 다음으로 이동할 것으로 예상한다.
4. **조작:** `건너뛰기`를 한 번 탭한다.
5. **즉각적 피드백:** 선택을 즉시 수용하고 다음 단계로 전환한다.
6. **성공 상태:** 동영상 없음이 정상 선택으로 저장된다.
7. **실패 / 오류 상태:** 별도 업로드가 없으므로 전환 실패만 재시도하며 사진은 보존한다.
8. **취소 / 되돌리기 / 수정:** 뒤로 돌아와 동영상을 추가할 수 있다.
9. **재조작:** 처리 중 중복 전환을 만들지 않는다.
10. **다음 상태:** 생활 문답.
11. **존재 필요성:** 추천 구조처럼 동영상을 사진 단계 안에 합치면 별도 건너뛰기는 제거하고 `다음`이 동영상 없음도 수용한다.

## 4.4 생활 문답의 선택지와 이동

각 질문에서 아래에 적은 선택지는 모두 서로 독립적인 탭 대상이다. 빈도 선택에는 정답·실패·건강 판정이 없으며, 어떤 답도 미접속·급식·청소 패널티로 이어지지 않는다.

### 4.4.1 문답 1 — 좋아하는 쓰다듬기 부위의 각 선택지

선택지: `머리`, `배`, `엉덩이`, `등`

1. **인지:** 네 부위가 각각 선택 가능함을 알고, 복수 선택이라면 여러 개를 고를 수 있다는 사실을 선택 전에 인지한다.
2. **사용 동기:** 실제로 좋아했던 접촉 부위를 이후 쓰다듬기 반응에 반영하려 한다.
3. **기대:** 선택한 각 부위를 문질렀을 때 다른 부위보다 하트와 긍정 반응이 분명해질 것으로 예상한다.
4. **조작:** 원하는 부위를 탭한다. 단일 선택이면 하나를 교체하고, 복수 선택이면 `머리`·`배`·`엉덩이`·`등`을 각각 켜고 끈다. 복수 선택 여부는 미확정이다.
5. **즉각적 피드백:** 탭한 각 부위의 현재 선택 상태를 즉시 보여준다.
6. **성공 상태:** 선택한 각 부위가 선호 영역으로 저장되어 Home 쓰다듬기 반응 조건에 연결된다.
7. **실패 / 오류 상태:** 저장 실패 시 화면 선택을 유지하고 재시도한다. 필수인데 미선택이면 다음 이동 시 이 질문 안에서 안내한다.
8. **취소 / 되돌리기 / 수정:** 단일 선택은 다른 부위로 교체하고, 복수 선택은 재탭으로 개별 해제한다. 이전으로 돌아와도 값을 유지한다.
9. **재조작:** 단일 선택의 동일 항목 재탭은 유지, 복수 선택에서는 해제로 동작한다.
10. **다음 상태:** 활동량 질문.
11. **존재 필요성:** 핵심 쓰다듬기 개인화와 직접 연결되므로 필요하다. 단일·복수 정책은 사용자 결정이 필요하다.

### 4.4.2 문답 2 — 활동량의 각 선택지

선택지: `매우 적음`, `적음`, `보통`, `많음`, `매우 많음`

1. **인지:** 다섯 선택지가 왼쪽에서 오른쪽으로 증가하는 하나의 정도임을 안다.
2. **사용 동기:** 실제 반려동물의 활발함을 이동·놀이·휴식 경향에 반영하려 한다.
3. **기대:** 선택 수준에 따라 상대적인 생활 행동 경향이 달라질 것으로 예상한다.
4. **조작:** 기억에 가장 가까운 하나를 탭한다.
5. **즉각적 피드백:** 현재 선택한 표현을 즉시 확인한다.
6. **성공 상태:** `매우 적음`부터 `매우 많음`까지 각각 최저·낮음·중간·높음·최고 활동 성향으로 저장되며 숫자 상태값은 사용자에게 노출하지 않는다.
7. **실패 / 오류 상태:** 저장 실패 시 선택을 보존하고, 미선택이면 이 질문에서 해결한다.
8. **취소 / 되돌리기 / 수정:** 다른 단계를 탭해 현재 답을 교체하거나 나중에 이전으로 돌아와 바꾼다.
9. **재조작:** 같은 단계는 유지, 다른 단계는 마지막 선택 하나만 남긴다.
10. **다음 상태:** 식사 주기 질문.
11. **존재 필요성:** 자율 활동 차이를 만드는 P0 정보라 필요하며 정밀 시간표보다 현재 5단계가 첫 등록에 적합하다.

### 4.4.3 문답 3 — 식사 주기의 각 선택지

선택지: `하루 1회 미만`, `1회`, `2회`, `3회`, `수시로`

1. **인지:** 하루 기준 식사 빈도를 고르는 다섯 개의 단일 선택임을 안다.
2. **사용 동기:** 실제 식사 습관을 자율 식사 리듬에 반영하려 한다.
3. **기대:** 선택이 상대적 식사 경향에 쓰이되 앱을 열지 않았다고 굶거나 해로운 결과가 생기지 않을 것으로 기대한다.
4. **조작:** `하루 1회 미만`, `1회`, `2회`, `3회`, `수시로` 중 하나를 탭한다.
5. **즉각적 피드백:** 선택한 빈도가 현재 답으로 표시된다.
6. **성공 상태:** 각 횟수는 해당 하루 빈도로, `수시로`는 고정 횟수보다 잦은 성향으로 저장된다. 정확한 시각 입력으로 취급하지 않는다.
7. **실패 / 오류 상태:** 저장 실패 시 답을 유지하고 미선택이면 이 질문 안에서 안내한다.
8. **취소 / 되돌리기 / 수정:** 다른 선택지로 교체하거나 이전으로 돌아와 수정한다.
9. **재조작:** 같은 항목은 유지하고 다른 항목은 기존 답을 대체한다.
10. **다음 상태:** 강아지의 짖음 또는 고양이의 울음 질문.
11. **존재 필요성:** 자율 식사 행동에 필요하다. 정확한 시간·양 입력은 관리 의무감과 이탈을 늘리므로 첫 등록에 추가하지 않는다.

### 4.4.4 문답 4 — 짖는 정도 / 우는 정도의 각 선택지

선택지: `거의 없음`, `드물게`, `보통`, `자주`, `매우 자주`

1. **인지:** 기본 정보의 종에 따라 강아지는 `짖는 정도`, 고양이는 `우는 정도`를 묻고 다섯 단계가 증가함을 안다.
2. **사용 동기:** 실제 소리 내는 성향을 종에 맞는 생활 행동에 반영하려 한다.
3. **기대:** 선택에 따라 발성 경향이 달라지며 낮거나 높은 값이 문제로 평가되지 않을 것으로 예상한다.
4. **조작:** 다섯 선택지 중 하나를 탭한다.
5. **즉각적 피드백:** 선택 빈도와 종에 맞는 질문 문구를 즉시 확인한다.
6. **성공 상태:** `거의 없음`부터 `매우 자주`까지 각각 최저·낮음·중간·높음·최고 발성 경향으로 저장된다. 실제 반려동물 본인의 발화 설정과는 구분된다.
7. **실패 / 오류 상태:** 종과 질문이 맞지 않으면 진행 전에 고치고, 저장 실패 시 선택을 보존한다.
8. **취소 / 되돌리기 / 수정:** 다른 빈도로 바꾼다. 종 변경 시 자동 변환하지 않고 이 답을 다시 확인하는 것을 추천한다.
9. **재조작:** 같은 값은 유지, 다른 값은 기존 답을 대체한다.
10. **다음 상태:** 배변 주기 질문.
11. **존재 필요성:** 종별 생활감 개인화에 필요하며 강아지·고양이를 별도 화면으로 만들 필요는 없다.

### 4.4.5 문답 5 — 배변 주기의 각 선택지

선택지: `하루 1회 미만`, `1회`, `2회`, `3회`, `4회 이상`

1. **인지:** 하루 기준 배변 빈도를 고르는 단일 선택임을 안다.
2. **사용 동기:** 실제 생활 습관과 Home 생활 흔적의 상대적 발생 경향을 비슷하게 만들려 한다.
3. **기대:** 선택이 흔적 빈도에 반영되지만 미청소가 질병·죽음·행복 저하로 이어지지 않을 것으로 예상한다.
4. **조작:** 다섯 선택지 중 하나를 탭한다.
5. **즉각적 피드백:** 현재 선택 빈도를 즉시 보여준다.
6. **성공 상태:** 각 횟수는 해당 빈도로, `4회 이상`은 상한 범주로 저장되며 추가 정밀 입력을 요구하지 않는다.
7. **실패 / 오류 상태:** 저장 실패 시 답을 보존하고 미선택이면 이 질문에서 안내한다.
8. **취소 / 되돌리기 / 수정:** 다른 빈도로 교체하거나 이전으로 돌아와 수정한다.
9. **재조작:** 동일 항목은 유지, 다른 항목은 대체한다.
10. **다음 상태:** 수면양 질문.
11. **존재 필요성:** Home 생활 흔적 개인화에 필요하며 배변 시각·종류 같은 추가 입력은 첫 만남을 불필요하게 늦춘다.

### 4.4.6 문답 6 — 수면양의 각 선택지

선택지: `매우 적음`, `적음`, `보통`, `많음`, `매우 많음`

1. **인지:** 다섯 선택지가 상대적 수면양이며 왼쪽에서 오른쪽으로 증가함을 안다.
2. **사용 동기:** 쉬고 자는 생활 리듬을 실제 반려동물과 비슷하게 만들려 한다.
3. **기대:** 선택한 수면양이 자율 휴식·수면 경향에 반영될 것으로 예상한다.
4. **조작:** 기억에 가장 가까운 하나를 탭한다.
5. **즉각적 피드백:** 현재 선택 단계를 즉시 보여준다.
6. **성공 상태:** `매우 적음`부터 `매우 많음`까지 최저·낮음·중간·높음·최고 수면 경향으로 저장하며 건강 이상으로 평가하지 않는다.
7. **실패 / 오류 상태:** 저장 실패 시 답을 보존하고 미선택이면 완료 전에 안내한다.
8. **취소 / 되돌리기 / 수정:** 다른 단계로 교체하며 이전 질문을 다녀와도 선택을 유지한다.
9. **재조작:** 같은 값은 유지, 다른 값은 기존 답을 대체한다.
10. **다음 상태:** 생성 결과 준비 상태 또는 후보 화면.
11. **존재 필요성:** 자율 수면 패턴에 필요하며 시간 단위 수면표보다 현재 5단계가 첫 등록에 적합하다.

### 4.4.7 문답 이전

1. **인지:** 앱 전체 이탈이 아니라 바로 전 질문으로 가는 조작임을 안다.
2. **사용 동기:** 직전 답을 확인하거나 수정하려 한다.
3. **기대:** 현재까지의 다른 답이 사라지지 않을 것으로 예상한다.
4. **조작:** `이전` 또는 문답 내 뒤로가기를 한 번 탭한다.
5. **즉각적 피드백:** 이전 질문과 저장된 답을 바로 보여준다.
6. **성공 상태:** 질문 위치가 하나 줄고 선택값이 복원된다. 첫 질문에서 이전하면 자료 단계로 간다.
7. **실패 / 오류 상태:** 이동 실패 시 현재 질문과 답을 유지하며 기기 뒤로가기와 데이터 보존 규칙을 일치시킨다.
8. **취소 / 되돌리기 / 수정:** 이전 질문에서 수정하거나 다시 다음으로 돌아온다.
9. **재조작:** 빠른 연속 탭이 질문을 건너뛰지 않게 한 단계씩 처리한다.
10. **다음 상태:** 이전 질문 또는 자료 단계.
11. **존재 필요성:** 기억 기반 답변을 안전하게 수정하려면 필요하며 발견성이 낮은 스와이프만으로 대체하지 않는다.

### 4.4.8 문답 다음

1. **인지:** 현재 답을 저장하고 다음 질문으로 가는 주요 행동임을 안다.
2. **사용 동기:** 답변을 마치고 후보에 가까워지려 한다.
3. **기대:** 현재 답이 보존되고 다음 질문이 나타나며 마지막에는 결과 준비로 갈 것으로 예상한다.
4. **조작:** 선택 뒤 `다음`을 탭한다. 마지막 CTA는 결과 준비가 이어짐을 예고한다.
5. **즉각적 피드백:** 답 저장과 질문 위치 변경을 보여주며 미선택이면 이동하지 않고 안내한다.
6. **성공 상태:** 1~5번은 다음 질문, 6번은 생성 결과 준비 상태로 간다.
7. **실패 / 오류 상태:** 저장 실패 시 선택을 잃지 않으며 마지막 제출 실패도 여섯 답 재입력을 요구하지 않는다.
8. **취소 / 되돌리기 / 수정:** 다음 질문의 이전 동작으로 돌아와 수정한다. 생성 뒤 수정은 후보 복구 Flow로 연결한다.
9. **재조작:** 중복 질문 이동·중복 생성 요청을 막는다.
10. **다음 상태:** 다음 질문, 생성 진행 또는 준비된 후보.
11. **존재 필요성:** 오선택 복구와 첫 질문의 복수 선택 가능성 때문에 자동 진행보다 명시적 다음을 추천한다.

## 4.5 캐릭터 생성과 후보 복구

### 4.5.1 캐릭터 생성 진행 / 재시도

1. **인지:** 생성 요청이 접수되어 시스템이 처리 중인 상태임을 안다.
2. **사용 동기:** 자신의 입력으로 만들어진 후보를 보고 싶다.
3. **기대:** 추가 입력 없이 후보 2~3개가 준비되고 이미 입력한 자료는 보존될 것으로 예상한다.
4. **조작:** 정상 처리 중에는 없음. 실패했을 때 `다시 시도`를 탭한다.
5. **즉각적 피드백:** 요청 접수·처리 중·완료·실패를 구분하고 확정 근거 없는 남은 시간을 약속하지 않는다.
6. **성공 상태:** 후보 2~3개를 비교할 수 있는 상태가 된다.
7. **실패 / 오류 상태:** 생성 요청만 실패로 처리하고 사진·문답을 유지한다. 반복 실패 시 사진 수정 경로를 제공한다.
8. **취소 / 되돌리기 / 수정:** 화면을 떠나도 요청을 유지할지 취소할지는 기술 결정이 필요하나, 입력과 이전 후보는 삭제하지 않는다.
9. **재조작:** 처리 중 재시도는 중복 생성을 만들지 않고 실패 뒤 재조작만 새 요청이 된다.
10. **다음 상태:** 후보 카드 또는 입력 수정.
11. **존재 필요성:** 비동기 처리에는 필요하지만 문답 중 결과가 준비되면 별도 대기 화면을 생략할 수 있다.

### 4.5.2 캐릭터 후보 카드

1. **인지:** 2~3개 후보가 서로 비교·선택 가능한 하나의 묶음이며 카드 전체가 탭 대상임을 안다.
2. **사용 동기:** 기억하는 모습에 가장 가까운 후보를 기준으로 고르려 한다.
3. **기대:** 탭은 선택만 하고 즉시 최종 확정하거나 다음 단계로 넘어가지 않을 것으로 예상한다.
4. **조작:** 후보 카드 하나를 탭한다. 세부 확인용 확대 제공 여부는 사용자 결정이 필요하다.
5. **즉각적 피드백:** 현재 선택 후보를 즉시 구분하고 그 후보에 적용되는 확정·보정 행동을 사용할 수 있게 한다.
6. **성공 상태:** 선택이 유지되고 확정, 보정, 다른 후보 선택, 불만족 복구 중 하나를 고를 수 있다.
7. **실패 / 오류 상태:** 특정 후보만 로드 실패면 그 후보만 재시도하고 나머지는 보존한다. 전체 실패는 생성 재시도로 간다.
8. **취소 / 되돌리기 / 수정:** 다른 카드를 탭해 바꾸며 뒤로가도 생성 결과를 파괴하지 않는다.
9. **재조작:** 선택 카드 재탭은 중복 확정으로 처리하지 않는다. 확대를 지원한다면 별도 동작 의미가 필요하다.
10. **다음 상태:** 후보 확정, 보정 진입, 다시 만들기 또는 입력 수정.
11. **존재 필요성:** AI 결과에 사용자 선택권을 주므로 필수다. 후보 간 차이가 의미 있는지는 결과 품질 테스트가 필요하다.

### 4.5.3 후보 확정

1. **인지:** `이 모습으로 할게요`가 카드 선택과 다른 최종 진행 행동임을 안다.
2. **사용 동기:** 가장 가까운 후보를 기준 캐릭터로 정하고 계속 진행하려 한다.
3. **기대:** 현재 외형이 저장되고 공간 설정으로 이어질 것으로 예상한다.
4. **조작:** 선택 후보가 있는 상태에서 CTA를 한 번 탭한다.
5. **즉각적 피드백:** 선택 외형의 저장 처리와 중복 탭 방지를 알린다.
6. **성공 상태:** 미보정 후보가 최종 외형으로 저장된다.
7. **실패 / 오류 상태:** 후보 선택을 유지한 채 저장만 재시도한다.
8. **취소 / 되돌리기 / 수정:** 탭 전에는 자유롭게 후보를 바꾼다. 공간 단계에서 외형 수정으로 돌아갈 때의 영향 범위는 미확정이다.
9. **재조작:** 처리 중 하나의 저장 요청만 유지하고 중복 캐릭터를 만들지 않는다.
10. **다음 상태:** 공간 사진.
11. **존재 필요성:** 카드 탭만으로 자동 확정하면 비교 중 실수 위험이 커서 명시적 확정이 필요하다.

### 4.5.4 다시 만들기

1. **인지:** 후보 확정과 구분된 보조 행동이며 “현재 입력으로 다른 후보를 만든다”는 결과를 조작 전에 안다.
2. **사용 동기:** 입력 자료는 맞지만 모든 후보가 전반적으로 닮지 않았다고 느낀다.
3. **기대:** 현재 사진·답변을 유지한 채 새 후보 세트가 생기고 기존 후보는 새 결과 성공 전까지 남을 것으로 예상한다.
4. **조작:** `다시 만들기`를 탭하고, 필요하면 `같은 입력으로 새 후보`, `사진 수정`, `이전 정보 수정` 중 문제에 맞는 경로를 고른다. 이유 응답은 강제하지 않는다.
5. **즉각적 피드백:** 어떤 입력으로 새 생성이 시작됐는지 알리고 기존 후보를 안전 상태로 보존한다.
6. **성공 상태:** 새 후보 2~3개를 비교할 수 있다. 직전 세트까지 장기 보존할지는 정책 결정이 필요하다.
7. **실패 / 오류 상태:** 새 생성 실패 시 기존 후보를 복원하고 재시도를 제공한다. 기술 실패를 재생성 허용 횟수로 세지 않는 것을 추천한다.
8. **취소 / 되돌리기 / 수정:** 생성 취소가 가능하면 기존 후보로 돌아간다. 사진·정보 수정은 해당 단계로 직접 가고 무관한 입력은 유지한다.
9. **재조작:** 생성 중 중복 요청을 막는다. 횟수·비용·대기 제한이 있다면 실행 전에 알려야 하며 현재는 미확정이다.
10. **다음 상태:** 새 후보 선택 또는 선택한 입력 수정 단계.
11. **존재 필요성:** 필요하다. 별도의 `후보 재생성`과 의미가 같으므로 하나로 통합하고, 모호한 전체 초기화 행동으로 사용하지 않는다.

### 4.5.5 캐릭터 보정 진입

1. **인지:** 선택 후보에 적용되는 `조금 다듬기` 의미의 행동이며 후보가 없으면 사용할 수 없음을 안다.
2. **사용 동기:** 전체 인상은 가깝지만 귀·털·체형·눈·색·무늬 일부만 다를 때 수정하려 한다.
3. **기대:** 선택 후보를 기준으로 일부 특징만 바뀌고 원본 후보와 사진은 보존될 것으로 예상한다.
4. **조작:** 후보 선택 뒤 보정 진입을 탭한다.
5. **즉각적 피드백:** 기준 후보와 현재값을 유지한 편집 상태가 열린다.
6. **성공 상태:** 기준 후보와 보정 초안이 구분된 상태에서 필요한 항목만 수정할 수 있다.
7. **실패 / 오류 상태:** 편집 리소스 로드 실패 시 선택 후보를 유지하고 후보 화면으로 안전하게 돌아가 재시도한다.
8. **취소 / 되돌리기 / 수정:** 뒤로가면 후보 화면으로 돌아간다. 같은 후보의 초안 보존 기간은 사용자 결정이 필요하다.
9. **재조작:** 다시 진입하면 중복 편집 세션을 만들지 않고 보존 정책에 따른 초안을 연다.
10. **다음 상태:** 보정값 변경, 되돌리기 또는 보정 확정.
11. **존재 필요성:** 작은 차이 때문에 전체 재생성을 반복하지 않도록 필요하다.

### 4.5.6 보정값 변경

1. **인지:** 귀·털·체형·눈·색·무늬가 수정 가능한 항목이고 현재값이 무엇인지 안다.
2. **사용 동기:** 실제 모습과 다른 특정 특징만 더 가깝게 만들려 한다.
3. **기대:** 조작한 항목이 예측 가능한 범위에서 바뀌며 무관한 특징·생활 답은 변하지 않을 것으로 예상한다.
4. **조작:** 항목을 선택하고 제공된 값을 탭하거나, 기술적으로 필요한 경우 제한된 범위에서 조절한다. 정확한 조작 형식은 미확정이다.
5. **즉각적 피드백:** 현재값과 미리보기에 반영 중·완료·실패를 해당 항목 단위로 보여준다.
6. **성공 상태:** 변경이 보정 초안에 저장되고 원본과 비교할 수 있다.
7. **실패 / 오류 상태:** 실패한 변경만 이전값으로 복구하고 다른 성공 변경은 보존한다.
8. **취소 / 되돌리기 / 수정:** 직전 변경을 되돌리고 후보 화면으로 나가더라도 확정 전 초안임을 분명히 한다.
9. **재조작:** 같은 항목을 다시 바꾸면 현재값을 대체하며 의도치 않은 누적 왜곡을 만들지 않는다.
10. **다음 상태:** 다른 보정값, 되돌리기 또는 확정.
11. **존재 필요성:** 간단 보정에 필요하지만 여섯 항목을 모두 만지게 강제하면 안 된다.

### 4.5.7 보정값 되돌리기

1. **인지:** 변경 이력이 있을 때 직전 변경을 취소하는 행동임을 안다.
2. **사용 동기:** 방금 수정한 결과가 덜 닮았거나 실수했다고 느낀다.
3. **기대:** 직전 변경 한 단계만 취소되고 다른 입력과 기준 후보는 유지될 것으로 예상한다.
4. **조작:** `되돌리기`를 한 번 탭한다.
5. **즉각적 피드백:** 미리보기와 현재값이 직전 정상 상태로 돌아간다.
6. **성공 상태:** 마지막 보정 이력 하나가 제거된다.
7. **실패 / 오류 상태:** 이력이 없으면 동작하지 않게 하고 렌더링 실패 시 데이터상 마지막 정상 상태를 유지한다.
8. **취소 / 되돌리기 / 수정:** 되돌린 값을 다시 선택해 재적용할 수 있다. 별도 다시 실행은 사용자 결정이 필요하다.
9. **재조작:** 반복하면 기준 후보까지 한 단계씩 돌아가며 기준에서는 더 동작하지 않는다.
10. **다음 상태:** 추가 보정 또는 현재 상태 확정.
11. **존재 필요성:** 안전하게 비교·실험하기 위해 필요하며 전체 초기화만으로 대체하기 어렵다.

### 4.5.8 보정 확정

1. **인지:** 모든 항목을 수정하지 않아도 사용할 수 있는 최종 저장 행동임을 안다.
2. **사용 동기:** 현재 보정 결과에 만족해 공간 설정으로 계속 가려 한다.
3. **기대:** 기준 후보와 보정값이 최종 외형으로 저장될 것으로 예상한다.
4. **조작:** 확정 CTA를 한 번 탭한다.
5. **즉각적 피드백:** 현재 미리보기를 고정하고 저장 상태를 보여준다.
6. **성공 상태:** 보정 외형이 최종 저장되고 후보 화면의 이중 확정 없이 공간 사진으로 간다.
7. **실패 / 오류 상태:** 보정 초안을 모두 보존한 채 저장만 재시도한다.
8. **취소 / 되돌리기 / 수정:** 확정 전에는 후보로 돌아가 비교한다. 확정 뒤 되돌아갈 때 재생성 영향은 미확정이다.
9. **재조작:** 중복 저장·중복 캐릭터 생성을 막는다.
10. **다음 상태:** 공간 사진.
11. **존재 필요성:** 필요하다. `보정 완료 → 후보 화면 → 다시 확정`의 이중 확인은 제거한다.

## 4.6 공간 사진과 이동 가능 영역

### 4.6.1 공간 사진 업로드

1. **인지:** 캐릭터가 생활할 실제 공간 사진 한 장을 선택하는 행동임을 안다.
2. **사용 동기:** 함께 지냈던 공간 또는 의미 있는 실제 공간에서 캐릭터를 만나려 한다.
3. **기대:** 사진이 Home 배경이 되고 다음에 이동할 바닥을 직접 정할 것으로 예상한다.
4. **조작:** 공간 사진 업로드를 탭하고 기기에서 한 장을 선택한다. 직접 촬영 지원은 미확정이다.
5. **즉각적 피드백:** 미리보기, 업로드 진행, 완료 시 `업로드 완료`를 보여준다.
6. **성공 상태:** 공간 사진이 저장되어 영역 편집에 사용할 수 있다.
7. **실패 / 오류 상태:** 권한, 형식, 손상, 해상도, 네트워크 문제를 구분하며 캐릭터 결과를 보존한다.
8. **취소 / 되돌리기 / 수정:** 선택 취소 시 현재 단계에 남는다. 사진 교체 전에는 기존 이동 영역이 무효화될 수 있음을 알리고, 새 업로드 실패 시 기존 사진을 유지한다.
9. **재조작:** 업로드 뒤 재탭은 교체로 작동한다.
10. **다음 상태:** 이동 가능 영역 편집.
11. **존재 필요성:** 실제 공간에서 생활한다는 핵심 가치에 필수다. 공간 분류나 여러 방 업로드를 추가하지 않는다.

### 4.6.2 이동 가능 영역 Brush

1. **인지:** 기본 활성화된 `칠하기`와 “칠한 바닥 안에서 캐릭터가 움직인다”는 짧은 최초 안내로 조작 가능함을 안다.
2. **사용 동기:** 캐릭터가 벽·가구 위가 아니라 실제로 다닐 수 있는 바닥에서 움직이게 하려 한다.
3. **기대:** 손가락으로 채운 영역이 이동 범위가 되고 완료 전 수정·미리보기가 가능할 것으로 예상한다.
4. **조작:** 한 손가락으로 바닥을 문질러 채운다. 사진 확대·이동은 Brush와 충돌하지 않는 별도 제스처 규칙이 필요하다.
5. **즉각적 피드백:** 손가락 경로를 따라 영역이 지연 없이 추가되고 현재 활성 도구를 계속 알린다.
6. **성공 상태:** 캐릭터가 움직일 수 있는 유효한 면적이 생긴다.
7. **실패 / 오류 상태:** 빈 영역, 너무 작은 영역, 지원하지 않는 분리 영역은 미리보기·완료 전에 구체적으로 알려준다. 기준은 미확정이다.
8. **취소 / 되돌리기 / 수정:** 지우기, 실행 취소, 초기화로 복구하고 뒤로가도 초안을 보존한다.
9. **재조작:** 반복 칠하기는 영역을 누적하며 이미 채운 부분에는 중복 효과가 없다.
10. **다음 상태:** 지우기, 초기화, 미리보기 또는 완료.
11. **존재 필요성:** 현재 직접 지정 정책에서는 필요하다. 정밀 모델링이 아니라 근사 영역으로 성공할 수 있어야 한다.

### 4.6.3 지우기

1. **인지:** 사진이 아니라 칠한 영역 일부를 제거하는 편집 도구임을 안다.
2. **사용 동기:** 가구·벽까지 잘못 칠했거나 범위를 좁히려 한다.
3. **기대:** 문지른 부분의 영역만 사라지고 사진과 나머지 영역은 유지될 것으로 예상한다.
4. **조작:** 지우기를 선택하고 잘못된 부분을 한 손가락으로 문지른다.
5. **즉각적 피드백:** 손가락 경로에서 영역이 즉시 사라지고 지우기 활성 상태를 유지한다.
6. **성공 상태:** 필요한 부분만 제거된다.
7. **실패 / 오류 상태:** 지울 곳이 없으면 다른 데이터에 변화가 없고, 결과가 무효 영역이면 완료 전에 안내한다.
8. **취소 / 되돌리기 / 수정:** 과하게 지웠으면 Brush 또는 실행 취소로 복구한다.
9. **재조작:** 계속 문지르면 추가 영역을 지우며 빈 부분에 반복해도 영향이 없다.
10. **다음 상태:** Brush, 초기화, 미리보기 또는 완료.
11. **존재 필요성:** 작은 실수 복구에 필수이며 전체 초기화로 대체하면 비용이 너무 크다.

### 4.6.4 실행 취소 / 다시 실행 `추천 추가 Element`

1. **인지:** 마지막 편집 획을 되돌리거나 다시 적용하는 행동임을 안다.
2. **사용 동기:** Brush·지우기에서 방금 한 실수를 즉시 복구하려 한다.
3. **기대:** 마지막 획만 바뀌고 전체 영역과 사진은 유지될 것으로 예상한다.
4. **조작:** 실행 취소 또는 다시 실행을 탭한다.
5. **즉각적 피드백:** 마지막 획의 결과와 이력 가능 상태가 즉시 바뀐다.
6. **성공 상태:** 편집 이력이 한 단계 이동한다.
7. **실패 / 오류 상태:** 해당 이력이 없으면 동작하지 않고 데이터 변화가 없다.
8. **취소 / 되돌리기 / 수정:** 실행 취소를 다시 실행으로 복원하고 반대 방향도 동일하게 처리한다.
9. **재조작:** 이력 범위 안에서 한 단계씩 이동하며 빠른 반복 입력이 순서를 건너뛰지 않는다.
10. **다음 상태:** 계속 편집, 미리보기 또는 완료.
11. **존재 필요성:** 현재 문서에 확정된 Element는 아니지만 Brush 편집의 복구 비용을 크게 낮추므로 Low-fi에서 필요성을 검증할 것을 추천한다.

### 4.6.5 초기화

1. **인지:** 공간 사진이 아니라 **이동 영역 전체**를 지우는 행동임을 안다.
2. **사용 동기:** 편집을 잘못 이해했거나 처음부터 다시 하는 편이 빠르다고 판단한다.
3. **기대:** 칠한 영역만 모두 사라지고 사진은 유지될 것으로 예상한다.
4. **조작:** 초기화를 탭하고 영역이 있으면 결과를 확인한다.
5. **즉각적 피드백:** 무엇이 지워지는지 알린 뒤 확인하면 빈 영역과 Brush 상태로 돌아간다.
6. **성공 상태:** 공간 사진을 보존한 빈 편집 상태가 된다.
7. **실패 / 오류 상태:** 로컬 초안을 우선 보존하며 상태 저장 실패가 다른 설정을 지우지 않는다.
8. **취소 / 되돌리기 / 수정:** 확인 전 취소한다. 확인 직후 전체 복구를 제공할지는 사용자 결정이 필요하다.
9. **재조작:** 이미 빈 상태에서는 추가 변화나 반복 확인을 만들지 않는다.
10. **다음 상태:** Brush로 다시 편집한다.
11. **존재 필요성:** 전체 오해를 빠르게 복구하기 위해 유지한다.

### 4.6.6 미리보기

1. **인지:** 칠한 영역에서 캐릭터가 어떻게 움직일지 확인하는 행동임을 안다.
2. **사용 동기:** 영역 표시만으로는 실제 이동 결과를 예측하기 어렵다.
3. **기대:** 편집값을 바꾸지 않고 캐릭터 또는 대체 이동 표시가 실제 규칙에 맞춰 움직일 것으로 예상한다.
4. **조작:** 미리보기를 탭하고 확인 후 편집으로 돌아간다.
5. **즉각적 피드백:** 편집 입력을 잠시 멈추고 대표 위치·경로를 보여준다.
6. **성공 상태:** 가구 침범, 이동 폭, 분리 영역의 영향을 확인한다.
7. **실패 / 오류 상태:** 영역이 없거나 너무 작으면 이유와 수정 행동을 알려준다. 캐릭터 렌더링 실패 시 대체 표시 지원 여부는 기술 검토가 필요하다.
8. **취소 / 되돌리기 / 수정:** 언제든 편집으로 돌아가며 기존 영역을 그대로 유지한다.
9. **재조작:** 같은 규칙으로 다시 확인할 수 있고 비교 가능한 대표 경로를 유지한다.
10. **다음 상태:** 영역 수정 또는 완료.
11. **존재 필요성:** 완료 전 결과 예측에 매우 중요하며 단순 설명으로 대체하기 어렵다.

### 4.6.7 이동 영역 완료

1. **인지:** 유효한 영역을 저장하고 편집을 끝내는 CTA임을 안다.
2. **사용 동기:** 이동 범위가 충분하다고 판단해 첫 만남으로 진행하려 한다.
3. **기대:** 영역만 저장되고 사진과 캐릭터 외형은 유지될 것으로 예상한다.
4. **조작:** 완료를 한 번 탭한다.
5. **즉각적 피드백:** 영역 유효성 검사와 저장 상태를 보여준다.
6. **성공 상태:** 이동 영역이 저장된다.
7. **실패 / 오류 상태:** 빈 영역·크기·연결성 문제와 고치는 방법을 알려주고 편집에 남긴다. 저장 실패 시 마스크를 보존한다.
8. **취소 / 되돌리기 / 수정:** 저장 전 뒤로가도 초안을 유지하고, Home 이후 수정 진입점은 추후 결정한다.
9. **재조작:** 저장 중 중복 요청을 만들지 않는다.
10. **다음 상태:** 추천안에서는 첫 만남, 현재 Flow에서는 기본 오브젝트 배치.
11. **존재 필요성:** 사용자가 결과를 검토하고 명시적으로 끝내기 위해 필요하다.

## 4.7 기본 오브젝트 배치와 첫 만남

다음 세 배치는 추천안에서 첫 만남 뒤 Home의 생활 준비 맥락으로 이동한다. 첫 만남 전 임시 오브젝트가 필요한지, 배치를 건너뛸 수 있는지는 사용자 결정이 필요하다.

### 4.7.1 밥그릇 배치

1. **인지:** 생활 물건 배치 상태에서 밥그릇이 이동 가능한 현재 대상임을 안다.
2. **사용 동기:** 이후 직접 급식할 위치를 정하려 한다.
3. **기대:** 배치 후 일반 Home에서 탭하면 밥 주기가 작동할 것으로 예상한다.
4. **조작:** 밥그릇을 선택해 원하는 위치로 드래그하고 놓는다.
5. **즉각적 피드백:** 이동 중 유효 여부를 알리고 유효 위치에는 고정, 무효 위치에서는 마지막 유효 위치로 돌아간다.
6. **성공 상태:** 캐릭터가 접근할 수 있는 위치가 저장된다.
7. **실패 / 오류 상태:** 이동영역 밖·접근 불가·경계 밖·지원하지 않는 겹침은 저장하지 않고 이유를 알려준다. 저장 실패 시 마지막 유효 상태를 보존한다.
8. **취소 / 되돌리기 / 수정:** 놓기 전 취소, 배치 직후 재이동, 이후 꾸미기에서 수정한다.
9. **재조작:** 배치 상태의 탭·드래그는 재배치, 일반 Home의 탭은 급식으로 동작한다.
10. **다음 상태:** 잠자리 배치 또는 Home.
11. **존재 필요성:** 밥 상호작용을 위해 오브젝트는 필요하지만 사용자가 첫 만남 전에 수동 배치할 필요는 없다.

### 4.7.2 잠자리 배치

1. **인지:** 캐릭터가 쉬고 잘 기본 오브젝트이며 현재 배치 대상임을 안다.
2. **사용 동기:** 자율 휴식·수면 장면이 일어날 위치를 정하려 한다.
3. **기대:** 놓은 위치가 휴식 장소로 사용되고 실제 공간 사진은 유지될 것으로 예상한다.
4. **조작:** 잠자리를 원하는 위치로 드래그하고 놓는다.
5. **즉각적 피드백:** 접근 가능한 위치인지 즉시 알리고 유효한 위치에 고정한다.
6. **성공 상태:** 잠자리 위치가 저장되어 휴식 행동과 연결될 준비가 된다.
7. **실패 / 오류 상태:** 이동영역 단절, 화면 밖, 지원하지 않는 겹침을 알려주며 다른 배치는 보존한다.
8. **취소 / 되돌리기 / 수정:** 현재 배치를 취소하거나 재이동하고 이후 꾸미기에서 수정한다.
9. **재조작:** 배치 상태에서는 재배치한다. 일반 Home에서 잠자리 탭이 별도 행동을 일으킬지는 확정되지 않았다.
10. **다음 상태:** 장난감 배치 또는 Home.
11. **존재 필요성:** 자율 수면의 장소성을 강화하지만 첫 만남 전 필수 조작일 필요는 없다.

### 4.7.3 장난감 배치

1. **인지:** 직접 놀이와 연결되는 현재 배치 대상임을 안다.
2. **사용 동기:** 캐릭터와 놀 수 있는 위치를 정하려 한다.
3. **기대:** 일반 Home에서 놓은 장난감을 탭하면 연결 행동이 시작될 것으로 예상한다.
4. **조작:** 장난감을 원하는 위치로 드래그하고 놓는다.
5. **즉각적 피드백:** 위치 유효 여부를 알리고 유효한 곳에 고정한다.
6. **성공 상태:** 장난감 위치가 저장되어 놀이가 가능해진다.
7. **실패 / 오류 상태:** 접근 불가·경계 밖·겹침 규칙 위반은 저장하지 않으며 앞선 배치를 되돌리지 않는다.
8. **취소 / 되돌리기 / 수정:** 취소·재배치가 가능하고 이후 꾸미기에서 수정한다.
9. **재조작:** 배치 상태에서는 재배치, 일반 Home에서는 놀이 시작으로 동작한다.
10. **다음 상태:** 별도 완료 페이지 없이 Home 생활.
11. **존재 필요성:** 직접 놀이에 필요하지만 첫 만남 전 필수 배치에서는 제거할 수 있다.

### 4.7.4 첫 만남 진행

1. **인지:** 이동 영역 저장 뒤 같은 공간에서 캐릭터가 등장하면서 첫 만남이 시작됐음을 자연스럽게 안다.
2. **사용 동기:** 지금까지의 입력이 자신의 공간 안에서 생활하는 캐릭터로 연결되는 결과를 보고 싶다.
3. **기대:** 선택 캐릭터가 실제 공간에 나타나며 부활·본인 발화나 과도한 감정 연출 없이 Home으로 이어질 것으로 예상한다.
4. **조작:** 필수 조작 없이 5~10초 자동 진행하는 것을 추천한다. 건너뛰기·가속은 사용자 결정이 필요하다.
5. **즉각적 피드백:** 공간과 캐릭터의 연속된 등장, 시스템 문구 `{이름}가 우리 집으로 찾아왔어요.`를 보여준다.
6. **성공 상태:** 같은 캐릭터·공간의 Home 자율 생활 상태로 전환되며 완료 페이지가 없다.
7. **실패 / 오류 상태:** 캐릭터 또는 애니메이션 로드 실패 시 설정 전체가 아닌 첫 만남만 재시도하고, 반복 실패 시 공간·캐릭터·확정 문구로 안전하게 Home에 진입한다.
8. **취소 / 되돌리기 / 수정:** 장면 중 뒤로가기로 설정을 깨지 않는다. 앱 종료 시 미완료면 안전하게 이어가고 완료 후에는 일반 Home으로 간다.
9. **재조작:** 일반 Home 진입 때마다 반복하지 않는다. 수동 다시보기는 현재 범위에 추가하지 않는다.
10. **다음 상태:** Home 첫 도착과 캐릭터 발견.
11. **존재 필요성:** 생성 과정의 가장 중요한 감정적 보상이므로 반드시 유지하고 추가 과제로 희석하지 않는다.

## 4.8 Home의 직접 교감

### 4.8.1 Home의 캐릭터

1. **인지:** 움직이는 핵심 대상 자체와 첫 진입의 한 번성 안내로 직접 누를 수 있음을 안다.
2. **사용 동기:** 가까이 보고 반응을 확인하거나 쓰다듬고 싶다.
3. **기대:** 캐릭터가 입력을 알아차리고 가까운 교감 상태로 전환될 것으로 예상한다.
4. **조작:** 캐릭터를 한 번 탭한다.
5. **즉각적 피드백:** 시선·작은 몸짓으로 탭을 인지한 뒤 확대를 시작한다.
6. **성공 상태:** 쓰다듬을 수 있는 확대 상태가 된다.
7. **실패 / 오류 상태:** 이동 중에도 누르기 쉬운 판정 범위를 제공하고 로드 실패 시 Home 상태를 보존해 재시도한다.
8. **취소 / 되돌리기 / 수정:** 전환 중 뒤로가면 기본 시점을 유지하며 생활 상태는 변하지 않는다.
9. **재조작:** 전환 중 중복 확대를 만들지 않고 확대 뒤 탭은 교감 입력 맥락으로 처리한다.
10. **다음 상태:** 캐릭터 확대와 쓰다듬기.
11. **존재 필요성:** 핵심 상호작용이라 필수이며 별도 `쓰다듬기` 메뉴보다 직접 터치가 자연스럽다.

### 4.8.2 밥그릇

1. **인지:** 캐릭터가 바라보거나 접근하는 행동과 최초 관련 상황의 한 번성 안내로 직접 터치 가능함을 안다.
2. **사용 동기:** 밥을 주고 먹는 생활 모습을 보고 싶다.
3. **기대:** 그릇에 먹이가 생기고 캐릭터가 필요할 때 먹을 것으로 예상한다.
4. **조작:** 밥그릇을 한 번 탭한다.
5. **즉각적 피드백:** 그릇 상태가 즉시 바뀌고 캐릭터가 가능한 범위에서 이를 인지한다.
6. **성공 상태:** 필요 상태면 이동해 먹고, 아니면 먹이가 남아 이후 자연스럽게 이용된다.
7. **실패 / 오류 상태:** 경로 계산 실패에도 급식 상태는 보존하고 이후 재접근하게 한다. 저장 실패는 재시도하며 거짓 성공을 표시하지 않는다.
8. **취소 / 되돌리기 / 수정:** 실수 급식은 해로운 결과가 없어 별도 되돌리기가 필수는 아니다. 위치는 꾸미기에서 수정한다.
9. **재조작:** 이미 채워진 상태에서는 중복 누적하지 않고 입력 인지 피드백만 준다.
10. **다음 상태:** 먹기 또는 자율 생활 지속.
11. **존재 필요성:** 핵심 생활 교감에 필요하며 별도 급식 메뉴로 대체하지 않는다.

### 4.8.3 장난감

1. **인지:** 캐릭터의 접근·관심 행동과 첫 놀이 상황의 한 번성 안내로 누를 수 있음을 안다.
2. **사용 동기:** 함께 놀고 장난감에 따른 반응을 보고 싶다.
3. **기대:** 해당 장난감에 연결된 놀이 행동이 시작될 것으로 예상한다.
4. **조작:** 장난감을 탭한다.
5. **즉각적 피드백:** 장난감 또는 캐릭터가 즉시 입력을 인지한다.
6. **성공 상태:** 캐릭터가 접근해 놀거나 현재의 짧은 행동 뒤 자연스럽게 놀이를 시작한다.
7. **실패 / 오류 상태:** 자거나 다른 행동 중인 것은 오류가 아니다. 인지 반응을 주고 이후 이용 가능 상태를 유지한다.
8. **취소 / 되돌리기 / 수정:** 추가 입력을 멈추면 놀이가 자연스럽게 끝나며 위치는 꾸미기에서 바꾼다.
9. **재조작:** 놀이 중 반복 탭은 처음부터 재시작하지 않고 현재 놀이의 추가 반응으로 처리한다.
10. **다음 상태:** 놀이 후 자율 생활.
11. **존재 필요성:** 행동 연동 장난감은 필요하며 모든 장식물을 상호작용 대상으로 만들 필요는 없다.

### 4.8.4 배변 흔적

1. **인지:** 이전에 없던 생활 흔적이며 최초 등장 때 한 번만 직접 눌러 치울 수 있음을 안다.
2. **사용 동기:** 공간을 정리하거나 가벼운 돌봄 행동을 하고 싶다.
3. **기대:** 한 번 누르면 흔적만 제거될 것으로 예상한다.
4. **조작:** 배변 흔적을 한 번 탭한다.
5. **즉각적 피드백:** 청소가 인식됐음을 보이며 흔적이 제거된다.
6. **성공 상태:** 공간이 정리되고 점수·의무 보상 없이 생활이 이어진다.
7. **실패 / 오류 상태:** 작은 흔적도 누르기 쉽게 처리하고 저장 실패 시 사용자를 탓하지 않으며 재시도한다.
8. **취소 / 되돌리기 / 수정:** 해로운 결과가 없는 단순 제거라 지속적인 되돌리기는 필요하지 않다.
9. **재조작:** 제거한 위치를 다시 눌러도 중복 동작·보상이 없다.
10. **다음 상태:** Home 자율 생활.
11. **존재 필요성:** 생활 흔적과 직접 돌봄 가설 검증에 필요하되 미청소 패널티·재촉은 금지한다.

### 4.8.5 캐릭터 확대

1. **인지:** 캐릭터 직접 탭과 전환 반응으로 가까이 볼 수 있음을 배운다.
2. **사용 동기:** 표정과 모습을 자세히 보고 쓰다듬고 싶다.
3. **기대:** 캐릭터 중심 시점으로 전환되고 종료 방법도 찾을 수 있을 것으로 예상한다.
4. **조작:** Home 캐릭터를 탭한다.
5. **즉각적 피드백:** 캐릭터가 입력을 인지하고 확대 전환을 시작한다.
6. **성공 상태:** 머리·배·엉덩이·등을 직접 문지를 수 있는 상태가 된다.
7. **실패 / 오류 상태:** 확대 위치 계산 실패 시 안전한 기본 확대 상태를 사용하며 캐릭터 데이터를 초기화하지 않는다.
8. **취소 / 되돌리기 / 수정:** 명시적 종료, 시스템 뒤로가기, 배경 탭으로 기본 시점에 돌아간다.
9. **재조작:** 확대 상태의 캐릭터 재탭을 종료로 오해하지 않게 하고 교감 입력과 구분한다.
10. **다음 상태:** 쓰다듬기 또는 기본 시점 복귀.
11. **존재 필요성:** 쓰다듬기 정확도와 몰입에 필요하지만 별도 확대 버튼은 불필요하다.

### 4.8.6 쓰다듬기

1. **인지:** 첫 확대 때 한 번만 손가락으로 문지르는 방법을 알려 조작 가능함을 안다.
2. **사용 동기:** 직접 교감하고 기억한 선호가 반영됐는지 확인하려 한다.
3. **기대:** 문지른 부위에 즉시 반응하고 선호 부위에서는 더 분명한 긍정 반응이 나올 것으로 예상한다.
4. **조작:** 머리·배·엉덩이·등 중 원하는 부위를 손가락으로 문지른다.
5. **즉각적 피드백:** 모든 유효한 문지르기에 작은 수용 반응을 주고 선호 부위에는 하트와 명확한 긍정 행동을 더한다.
6. **성공 상태:** 사용자는 입력이 인식됐고 문답 개인화가 실제 반응에 적용됐음을 느낀다.
7. **실패 / 오류 상태:** 짧은 탭이 문지르기로 인식되지 않으면 실패 표시 없이 동작 안내를 한 번 다시 제공한다.
8. **취소 / 되돌리기 / 수정:** 손가락을 떼면 현재 문지르기만 끝나고 확대는 유지된다.
9. **재조작:** 반복 가능하지만 점수·친밀도 수치·효과 누적 경쟁을 만들지 않고 반응 과잉을 제한한다.
10. **다음 상태:** 계속 교감하거나 기본 시점으로 돌아간다.
11. **존재 필요성:** StayPet의 핵심 개인화 체감이므로 필수이며 메뉴 버튼으로 대체하지 않는다.

### 4.8.7 쓰다듬기 종료 / 기본 시점 복귀

1. **인지:** 확대 상태에서 항상 찾을 수 있는 명시적 종료 방법이 있어 숨은 제스처를 추측하지 않아도 된다.
2. **사용 동기:** Home 관찰로 돌아가거나 다른 오브젝트와 상호작용하려 한다.
3. **기대:** 생활·교감 상태를 잃지 않고 원래 시점으로 돌아갈 것으로 예상한다.
4. **조작:** 명시적 종료, 시스템 뒤로가기 또는 캐릭터 밖 배경 탭을 사용한다. 쓰다듬기와 충돌하는 아래 스와이프를 주 종료로 사용하지 않는다.
5. **즉각적 피드백:** 확대가 끝나고 기본 Home 시점으로 연속 전환된다.
6. **성공 상태:** 캐릭터가 자연스럽게 자율 생활로 돌아간다.
7. **실패 / 오류 상태:** 한 종료 수단이 실패해도 시스템 뒤로가기가 안전한 대체 경로가 된다.
8. **취소 / 되돌리기 / 수정:** 캐릭터를 다시 탭하면 확대 상태로 돌아갈 수 있다.
9. **재조작:** 전환 중 반복 종료 입력은 한 번만 처리한다.
10. **다음 상태:** Home 기본 시점.
11. **존재 필요성:** 반드시 필요하나 별도 `쓰다듬기 완료` 제출은 불필요하다.

### 4.8.8 상태 말풍선

1. **인지:** 캐릭터의 현재 행동에 연결된 짧은 상태 정보로 인지한다.
2. **사용 동기:** 기본적으로 읽기 위해 본다. 탭한다면 화면에서 닫으려는 의도일 가능성이 높다.
3. **기대:** 현재 상태를 설명할 뿐 의무·경고·점수나 간접 메뉴를 열지 않을 것으로 예상한다.
4. **조작:** 기본은 읽기이며, 탭 상호작용을 준다면 조기 닫기로만 제한하는 것을 추천한다.
5. **즉각적 피드백:** 탭 시 말풍선만 사라지고 캐릭터 행동은 계속된다.
6. **성공 상태:** 숫자 게이지 없이 현재 상태를 이해한다.
7. **실패 / 오류 상태:** 행동과 맞지 않는 오래된 말풍선은 상태 변경 시 제거하며 빈 상태도 정상으로 처리한다.
8. **취소 / 되돌리기 / 수정:** 닫은 말풍선을 되돌릴 필요는 없고 같은 상태가 다시 생기면 자연스럽게 나타날 수 있다.
9. **재조작:** 닫힌 뒤 반복 탭은 변화를 만들지 않는다.
10. **다음 상태:** 직접 오브젝트를 탭하거나 관찰을 계속한다.
11. **존재 필요성:** 상태 전달에는 필요하지만 상호작용 CTA일 필요는 없다. `배고파요`를 눌러 메뉴를 여는 대신 밥그릇 직접 터치를 유지한다.

## 4.9 Home의 보조 기능 진입

최종 navigation pattern과 Home 메뉴 위치는 미확정이다. 따라서 아래는 진입 후 동작과 우선순위만 정의하며 위치·모양은 제안하지 않는다.

### 4.9.1 꾸미기 진입

1. **인지:** Home의 보조 탐색에서 명시적인 `꾸미기` 기능임을 안다.
2. **사용 동기:** 생활 오브젝트를 배치·이동하거나 실제 공간에 작은 변화를 주려 한다.
3. **기대:** 현재 Home을 잃지 않고 편집 상태로 들어가며 기존 배치가 유지될 것으로 예상한다.
4. **조작:** 꾸미기 진입을 탭한다.
5. **즉각적 피드백:** 현재 배치를 기준으로 편집 가능한 상태가 열린다.
6. **성공 상태:** 사용자가 보유한 오브젝트를 선택·배치·이동·회전할 수 있다.
7. **실패 / 오류 상태:** 편집 데이터 로드 실패 시 Home을 유지하고 재시도한다.
8. **취소 / 되돌리기 / 수정:** 변경 전 상태로 취소하거나 저장 뒤 Home으로 돌아간다.
9. **재조작:** 다시 들어오면 마지막 저장 배치를 불러온다.
10. **다음 상태:** 꾸미기 편집 또는 Home.
11. **존재 필요성:** 공간 꾸미기는 P0이지만 첫 Home의 주요 행동일 필요는 없고 첫 교감 뒤 보조 경로로 두는 것이 적절하다.

### 4.9.2 꾸미기 편집 — 선택 / 이동 / 회전 / 저장

1. **인지:** 편집 상태에서 어떤 오브젝트가 선택됐고 이동·회전·저장할 수 있는지 안다.
2. **사용 동기:** 실제 공간의 정체성을 유지하면서 생활 물건과 소규모 장식을 원하는 위치에 두려 한다.
3. **기대:** 유효한 변경만 저장되고 캐릭터가 행동 연동 오브젝트에 접근할 수 있을 것으로 예상한다.
4. **조작:** 보유 오브젝트 선택 → 드래그 이동 → 필요 시 회전 → 저장.
5. **즉각적 피드백:** 현재 선택, 유효·무효 위치, 회전 결과, 저장 처리 상태를 각각 즉시 알려준다.
6. **성공 상태:** 저장된 배치가 Home과 연결 행동에 반영된다.
7. **실패 / 오류 상태:** 무효 위치는 마지막 유효 위치로 돌리고 저장 실패 시 편집 초안을 보존한다.
8. **취소 / 되돌리기 / 수정:** 개별 이동을 되돌리며, 저장하지 않고 나갈 때 변경이 있으면 폐기 여부를 확인한다.
9. **재조작:** 같은 오브젝트를 다시 선택해 수정하고 저장 중 중복 요청을 막는다.
10. **다음 상태:** 편집 계속 또는 Home.
11. **존재 필요성:** P0 꾸미기에 필요하지만 첫 Low-fi에서는 기본 오브젝트 한두 개의 핵심 조작만 검증하고 전체 카탈로그로 확장하지 않는다.

### 4.9.3 앨범 진입

1. **인지:** 보조 탐색에서 저장된 자료를 보는 앨범임을 안다.
2. **사용 동기:** 기존 추억 자료나 새로 촬영한 Home 장면을 다시 보고 싶다.
3. **기대:** 저장 자료 목록과 상세 보기가 열릴 것으로 예상한다.
4. **조작:** 앨범 진입을 탭한다.
5. **즉각적 피드백:** 자료 목록 또는 오류가 아닌 빈 상태를 보여준다.
6. **성공 상태:** 항목을 선택해 상세 내용을 볼 수 있다.
7. **실패 / 오류 상태:** 로드 실패를 삭제된 것처럼 보이지 않게 하고 재시도한다. 자료 없음은 정상 빈 상태다.
8. **취소 / 되돌리기 / 수정:** 뒤로가기로 Home에 돌아간다. 자료 삭제·복구 정책은 별도 결정이 필요하다.
9. **재조작:** 재진입 시 최신 저장 상태를 불러온다.
10. **다음 상태:** 상세 보기, 향후 추억 사진 확인 또는 Home.
11. **존재 필요성:** P1이며 첫 Low-fi 핵심 Flow에는 필수가 아니다. 추억 사진과 하나의 후속 검증 시나리오로 묶는다.

### 4.9.4 추억 사진 촬영

1. **인지:** 현재 Home 장면을 저장하는 보조 촬영 행동임을 안다. 첫 교감 전에 기능 설명을 강제하지 않는다.
2. **사용 동기:** 지금의 생활 장면을 새 기억으로 남기고 싶다.
3. **기대:** Home 장면이 방해 정보 없이 저장되고 SNS 공유를 강요받지 않을 것으로 예상한다.
4. **조작:** 촬영 상태에 진입해 원하는 순간 촬영한다.
5. **즉각적 피드백:** 촬영 처리를 알리고 성공 시 `저장 완료`를 보여준다.
6. **성공 상태:** 결과가 정해진 저장 위치에 남고 앨범에서 다시 볼 수 있다.
7. **실패 / 오류 상태:** 장면을 유지한 채 재시도·취소하며 실패를 성공으로 표시하지 않는다.
8. **취소 / 되돌리기 / 수정:** 촬영 전 취소하면 Home으로 돌아간다. 저장 후 삭제·되돌리기는 저장 정책과 함께 정한다.
9. **재조작:** 반복 촬영은 별도 결과로 저장하되 빠른 중복 입력은 한 번만 처리한다.
10. **다음 상태:** 기본은 Home, 이후 앨범에서 확인.
11. **존재 필요성:** P1이며 첫 생활 가설에 필수는 아니지만 “새 기억을 남기고 싶은가”를 후속 검증할 때 P1 중 우선순위가 높다.

### 4.9.5 상점 진입

1. **인지:** 새로운 생활 오브젝트를 얻는 경로임을 안다. 추천은 독립 Home 주 메뉴보다 꾸미기 맥락에서 발견하게 하는 것이다.
2. **사용 동기:** 특별 가구·장난감·새 행동 장면을 추가하고 싶다.
3. **기대:** 아이템 기능과 필요한 재화를 확인하되 기본 교감은 결제에 막히지 않을 것으로 예상한다.
4. **조작:** 꾸미기 안의 상점 연결 또는 향후 보조 상점 진입을 탭한다.
5. **즉각적 피드백:** 아이템 목록과 현재 선택 맥락을 연다.
6. **성공 상태:** 구매 완료 시 보유 상태가 되고 꾸미기에서 배치할 수 있다.
7. **실패 / 오류 상태:** 재화 부족, 네트워크·구매 실패를 구분하고 중복 결제를 막는다. 가격·결제·환불 정책은 이 문서에서 정하지 않는다.
8. **취소 / 되돌리기 / 수정:** 구매 확정 전 꾸미기로 돌아간다. 실제 결제 취소는 정책 결정 전 임의 설계하지 않는다.
9. **재조작:** 보유 아이템 재탭은 중복 구매가 아니라 배치 경로로 이어지는 것을 추천한다.
10. **다음 상태:** 꾸미기에서 배치 또는 Home.
11. **존재 필요성:** P1 비즈니스 기능이라 Low-fi 1차에서 제외하며 Home의 핵심 교감과 같은 우선순위로 노출하지 않는다.

### 4.9.6 알림 옵트인 `P1 후속 Element`

1. **인지:** 생활 알림을 받을지 사용자가 직접 선택하는 요청임을 안다.
2. **사용 동기:** 앱 밖에서도 낮은 빈도의 현재 생활 소식을 받고 싶다.
3. **기대:** 거절해도 기능·관계에 불이익이 없고 나중에 바꿀 수 있을 것으로 예상한다.
4. **조작:** 생활 알림을 원할 때 옵트인을 선택한 뒤 필요한 OS 권한 요청에 응답한다.
5. **즉각적 피드백:** 앱 내 선택과 OS 권한 결과를 구분해 알려준다.
6. **성공 상태:** 허용된 경우 낮은 빈도의 생활 소식을 받을 수 있는 상태가 된다.
7. **실패 / 오류 상태:** OS 거부·제한은 등록 실패가 아니며 설정에서 바꿀 수 있는 방법만 중립적으로 안내한다.
8. **취소 / 되돌리기 / 수정:** 지금은 선택하지 않거나 나중에 설정에서 끌 수 있다. 재촉하지 않는다.
9. **재조작:** 이미 결정한 사용자를 반복해서 묻지 않고 사용자가 직접 설정을 바꿀 때만 갱신한다.
10. **다음 상태:** 현재 Home을 유지한다.
11. **존재 필요성:** P1 재방문 보조 기능이나 첫 만남 Flow와 Low-fi 1차에는 필요 없다. 허용 시점·빈도는 별도 사용자 결정이 필요하다.

# 5. 오류 / 복구 / 뒤로가기 Flow

## 5.1 전역 원칙

1. **실패 범위만 재시도한다.** 사진 한 장 실패는 그 사진만, 후보 생성 실패는 생성만, 저장 실패는 저장만 다시 수행한다.
2. **성공한 입력을 기본적으로 보존한다.** 인증 방식 변경, 네트워크 단절, 앱 종료가 사진·문답·후보를 초기화하지 않는다.
3. **뒤로가기는 삭제가 아니다.** 이전 단계로 가는 것과 전체 등록 포기를 분리한다.
4. **파괴적 변경 전에 영향 범위를 알린다.** 공간 사진 교체로 이동 영역이 무효화되거나 사진 수정으로 새 후보가 필요할 때만 확인한다.
5. **새 결과가 성공하기 전 기존 결과를 보존한다.** 사진 교체, 후보 재생성, 보정 렌더링 실패가 마지막 정상 결과를 없애면 안 된다.
6. **오류 메시지는 원인과 다음 행동을 함께 제공한다.** `실패했어요`만 보여주지 않고 재시도·파일 교체·권한 변경 중 가능한 행동을 구분한다.
7. **선택 사항의 실패가 핵심 경로를 막지 않는다.** 동영상·앨범·촬영·알림·상점 오류는 첫 만남과 기본 교감을 차단하지 않는다.
8. **죄책감과 책임 전가를 금지한다.** 업로드·배치·청소 실패를 사용자의 돌봄 부족처럼 표현하지 않는다.

## 5.2 단계별 뒤로가기와 취소

| 현재 단계 | 뒤로가기 결과 | 보존할 것 | 확인이 필요한 경우 |
|---|---|---|---|
| 외부 로그인 | StayPet 로그인 선택으로 복귀 | 앱 내부 기존 설정 | 외부 공급자가 별도 확인을 요구하는 경우만 따름 |
| 기본 정보 | 로그인으로 복귀 | 종·이름·성별 초안 | 계정 자체 전환 시 저장 대상이 달라지는 경우 |
| 사진·동영상 | 기본 정보로 복귀 | 성공 업로드와 실패 파일 상태 | 없음 |
| 문답 2~6 | 직전 질문 | 모든 답과 업로드 | 없음 |

## 5.4 이전 정보 수정이 뒤 단계에 미치는 영향

- **이름 변경:** 첫 만남과 상태 문구의 이름을 갱신한다. 생성 자체에 이름이 사용되는지 여부는 기술 결정이 필요하다.
- **종 변경:** 짖음/울음 답을 다시 확인하고, 외형·종별 행동에 영향을 주므로 후보 재생성 가능성을 안내해야 한다.
- **성별 변경:** 실제 생성·호칭에 쓰이는 범위가 확정돼야 재생성 필요 여부도 결정할 수 있다.
- **사진 추가·교체:** 새 후보가 필요할 가능성이 높다. 새 생성 성공 전 기존 후보를 보존한다.
- **생활 문답 변경:** 앞으로의 행동과 쓰다듬기 반응에 갱신한다. 외형 생성에도 입력되는지 여부에 따라 후보 재생성 여부가 달라지므로 기술 확인이 필요하다.
- **후보·보정 변경:** 공간 사진과 이동 영역은 보존할 수 있지만 캐릭터 크기·동작 영역에 영향이 있는지는 기술 검증이 필요하다.
- **공간 사진 교체:** 기존 이동 영역과 오브젝트 위치가 새 사진에 그대로 맞지 않으므로 교체 전 무효화 범위를 알린다.
- **이동 영역 수정:** 기존 오브젝트가 새 범위에서 접근 불가능해질 수 있으므로 완료 전에 문제 오브젝트만 다시 배치하게 한다.

## 5.5 중단 후 재개 지점 `추천`

- 인증 완료
- 기본 정보 완료
- 각 사진·동영상 업로드 완료
- 각 문답 답변 완료
- 생성 요청 접수 및 결과 완료
- 후보 또는 보정 외형 확정
- 공간 사진 업로드 완료
- 이동 영역 편집 초안 및 완료
- 각 기본 오브젝트 배치 완료
- 첫 만남 완료

재개 시 사용자를 무조건 다음 단계로 보내지 않는다. 완료된 단계의 마지막 확정값을 보여 주고, 미완료 작업이 있으면 그 작업에서 이어간다. 등록을 중단했다는 이유로 죄책감이나 손실 경고를 주지 않는다.

# 6. 첫 만남까지의 이탈 위험

## 6.1 가능성이 높은 다섯 지점

| 순위 | 이탈 지점 | 사용자가 느끼는 문제 | 추천 완화 |
|---|---|---|---|
| 1 | 사진 선택·권한·업로드 | 사적인 자료 제공 부담, 적절한 사진을 다시 보는 정서적 부담, 기술 실패 | 파일별 상태·복구, 초안 저장, 성공 자료 보존, 요구 조건의 맥락 안내 |
| 2 | 모든 후보가 닮지 않음 | 긴 입력과 대기 뒤 핵심 약속이 실패했다고 느낌 | 기존 후보 보존, 보정·다시 만들기·사진 수정의 명확한 분리 |
| 3 | 이동 영역 지정과 오브젝트 배치 | 낯선 편집 과제와 정밀 작업이 감정적 보상 직전에 누적 | 최초 한 번 안내, 실행 취소·미리보기, 근사치 허용, 수동 오브젝트 배치를 첫 만남 뒤로 이동 |
| 4 | 사진 → 동영상 → 6개 문답 | 입력 작업이 연속되고 끝을 알 수 없음 | 동영상 독립 단계 제거, 1/6 진행 맥락, 답 저장, 가능하면 생성과 문답 병렬 처리 |
| 5 | 로그인 | 가치를 보기 전에 계정·동의를 요구하고 일반 가입 의미가 불명확 | 소셜 인증 복귀 안정성, 일반 로그인 의미 결정, 중단 등록 재개 |

## 6.2 가장 감정적으로 중요한 순간

감정적 중요도는 하나의 장면보다 다음 세 순간의 연결에서 생긴다.

1. 후보 중 처음으로 “우리 아이와 닮았다”고 느끼는 순간
2. 그 캐릭터가 사용자의 실제 공간에 등장하는 첫 만남
3. 입력한 선호 부위를 문질렀을 때 하트와 긍정 행동으로 개인화가 확인되는 첫 쓰다듬기

그중 가장 큰 정점은 **선택한 캐릭터가 실제 공간에 처음 등장하는 순간**이다. 첫 만남 직전과 직후에는 오브젝트 배치, 상점, 전체 기능 설명을 끼워 넣지 않는 것이 중요하다.

## 6.3 가장 지루해질 위험이 높은 순간

- 사진·선택 동영상·6개 문답이 직렬로 이어지는 구간
- 문답을 마친 뒤 시작되는 AI 생성 대기
- 이미 후보를 본 뒤 이동 영역을 정밀하게 칠하고 기본 오브젝트까지 모두 배치하는 구간

가장 큰 단일 위험은 **이동 영역 편집 뒤 다시 오브젝트 세 개를 배치해야 첫 만남이 오는 구조**다. 생성은 처리 특성상 대기가 필요할 수 있지만, 문답과 겹칠 수 있다. 반면 오브젝트 수동 배치는 순서 변경만으로 첫 가치 경험 뒤로 옮길 수 있다.

## 6.4 Low-fi에서 관찰할 이탈 신호

- 사진 단계에서 권한 요청 전에 멈추거나 파일 선택을 반복하는가
- 동영상이 선택 사항임을 묻거나 건너뛰기를 찾는가
- 문답 중 남은 질문 수를 확인하려 하는가
- 후보 불만족 시 `다시 만들기`와 사진 수정을 구분하는가
- 이동 영역에서 테두리만 그리거나 사진 이동과 칠하기를 혼동하는가
- 오브젝트 배치 중 첫 만남이 언제인지 묻는가
- Home 진입 후 캐릭터와 오브젝트를 스스로 눌러 보는가

# 7. Home Interaction Discovery

## 7.1 추천 첫 방문 발견 순서

1. 첫 만남이 끝나도 별도 튜토리얼 화면으로 전환하지 않는다.
2. 짧게 관찰할 시간을 주고 캐릭터가 사용자를 바라보거나 다가오는 현재 행동으로 관심을 모은다.
3. 사용자가 망설일 때만 캐릭터 직접 탭을 알리는 **한 가지** 비차단 안내를 제공한다.
4. 캐릭터 탭 성공 후 확대 상태에서 손가락으로 문지르는 방법 하나만 알린다.
5. 첫 쓰다듬기가 인식되면 안내를 종료하고 사용자가 스스로 종료·복귀하게 한다.
6. 기본 시점으로 돌아온 뒤 현재 맥락에 맞는 밥그릇 또는 장난감 중 하나만 다음 발견 대상으로 삼는다.
7. 배변 흔적은 실제로 처음 나타났을 때만 한 번 안내한다.
8. 꾸미기·앨범·추억 사진·상점·알림은 첫 Home 튜토리얼에서 설명하지 않는다.

## 7.2 버튼 없이 조작 가능성을 알리는 원칙

- **캐릭터:** 사용자를 알아차리는 행동과 최초 한 번의 직접 탭 안내.
- **밥그릇:** 캐릭터가 바라보거나 접근하는 행동, 현재 상태와 연결된 최초 안내.
- **장난감:** 캐릭터의 관심 행동 또는 첫 놀이 상황에서만 안내.
- **배변 흔적:** 새로 생긴 흔적 자체와 최초 한 번의 청소 안내.
- **모든 유효 탭:** 시선, 몸짓, 이동, 오브젝트 상태 변화 중 적어도 하나로 즉시 응답.
- **효과 없는 탭:** 화면 전체에 버튼 표식을 늘리기보다 상호작용 대상의 판정과 피드백을 일관되게 한다.

안내는 성공 즉시 사라지고 무시할 수 있어야 한다. 사용자가 일정 시간 아무 행동도 하지 않을 때 한 차례 재안내하는 것은 검토할 수 있지만 반복 재촉은 금지한다.

## 7.3 캐릭터 확대 → 쓰다듬기 → 종료

- 캐릭터 탭과 확대는 하나의 연속 동작으로 만든다.
- 확대된 직후에는 캐릭터 몸 위의 문지르기와 화면 종료가 충돌하지 않아야 한다.
- 종료는 명시적 종료 수단, 시스템 뒤로가기, 배경 탭을 제공하는 것을 추천한다.
- 아래로 스와이프는 쓰다듬기 동작과 혼동되므로 주 종료 방식으로 추천하지 않는다.
- 손가락을 뗐다는 이유만으로 바로 기본 시점으로 돌아가지 않는다. 잠시 멈추거나 다른 부위를 이어서 만질 수 있어야 한다.
- 별도 `완료` 제출 없이 종료하면 자연스럽게 기본 Home으로 복귀한다.

## 7.4 선호 부위가 개인화로 느껴지는 조건

1. 하트는 단순 탭이 아니라 유효한 문지르기와 부위 판정 뒤에 나타난다.
2. 선호 부위에서는 하트뿐 아니라 캐릭터의 편안한 몸짓이나 반응 지속으로 차이를 만든다.
3. 모든 부위에서 같은 하트를 보여 주지 않는다.
4. 하트에 점수·콤보·친밀도 상승 같은 게임 규칙을 연결하지 않는다.
5. 첫 긍정 반응 직후 설문 결과를 설명하는 팝업을 띄우지 않는다. 사용자가 반응 자체로 연결을 깨닫게 한다.

## 7.5 비선호 부위의 자연스러운 차이

- 비선호는 `싫어하는 부위`나 오답으로 취급하지 않는다.
- 터치를 무시하지 않고 시선, 깜박임, 작은 몸 움직임 같은 중립적 수용 반응을 준다.
- 하트와 강한 긍정 행동은 생략해 선호 부위와 자연스럽게 대비한다.
- 화내기, 밀어내기, 도망가기, 실패 문구, 친밀도 감소는 사용하지 않는다.
- 캐릭터가 몸을 편하게 돌려 다른 부위를 내어 주는 행동은 가능한 후보지만 채택 여부는 사용자 결정이 필요하다.

## 7.6 활동 보고서 없는 재방문 발견

과거를 설명하는 대신 **현재 장면에 생활의 결과를 남긴다.**

- 경과시간에 맞는 현재 위치와 행동으로 진입한다.
- 밥그릇 상태, 장난감 위치, 잠자리 사용, 배변 흔적 중 상황에 맞는 한두 가지가 현재 장면과 일치한다.
- 캐릭터가 매번 사용자를 기다리는 자세가 아니라 자거나 놀거나 이동하는 자기 생활 중에 등장한다.
- 사용자를 알아차리면 가끔 바라보거나 다가오되 `기다렸어요`, `왜 이제 왔어요` 같은 표현은 금지한다.
- 말풍선은 현재 상태만 설명하고 과거 이벤트 목록을 만들지 않는다.
- 테스트에서 연속성을 이해하지 못한다면 두 번째 방문에 한해 “앱을 닫아도 생활은 이어진다”는 중립적 원리 안내를 검토할 수 있다. 최종 카피와 채택 여부는 미확정이다.

# 8. Low-fi 1차 검증 범위

이 절은 향후 Low-fi 범위를 제안할 뿐 현재 Low-fi를 제작하는 것이 아니다.

## 8.1 반드시 검증할 P0 핵심

- 세 로그인 경로의 성공·취소·실패 후 분기
- 종·이름·성별 통합 단계와 수정
- 사진 추가·삭제·교체·일부 실패
- 생활 문답 6개, 진행 맥락, 이전·다음
- 생성 진행·실패·재시도
- 후보 선택·확정·불만족 복구
- 보정 진입·변경·되돌리기·확정
- 공간 사진 업로드·교체
- 이동 영역 Brush·지우기·실행 취소 후보·초기화·미리보기·완료
- 이동 영역 뒤 첫 만남으로 바로 가는 추천 순서
- 첫 만남에서 Home으로 이어지는 상태
- Home 캐릭터 발견, 확대, 쓰다듬기, 선호·비선호 반응, 종료
- 밥그릇·장난감·배변 흔적 직접 터치
- 첫 만남 뒤 기본 오브젝트 배치 또는 임시 배치 대안
- 꾸미기에서 기본 오브젝트 이동·저장 정도의 최소 편집
- 활동 보고서 없이 달라진 현재 장면으로 들어오는 재방문 상태

## 8.2 P1 기능별 1차 포함 판단

| P1 기능 | 1차 Low-fi 추천 | 판단 이유 |
|---|---|---|
| 선택적 동영상 | 원칙적으로 제외. 필요하면 사진 단계 안의 선택 Element만 비교안으로 테스트 | P1이며 독립 단계가 온보딩 피로에 미치는 영향이 더 큰 쟁점이다 |
| 추억 앨범 | 제외 | 첫 핵심 생활과 별도 가치이며 촬영 콘텐츠 없이는 빈 구조만 테스트하게 된다 |
| 추억 사진 | 제외, 후속 P1 중 우선 검증 | 핵심 교감 뒤 “새 장면을 남기고 싶은가”를 별도 시나리오로 확인할 가치가 있다 |
| 옵트인 알림 | 제외 | 실제 재방문·권한·빈도 맥락이 필요하고 첫 만남 Flow와 무관하다 |
| 상점·재화 | 제외 | 가격·재화가 미확정이고 핵심 무료 경험 검증을 흐린다 |
| 함께한 날 | 제외 | 누적 방문을 전제로 하므로 단회 신규 사용자 테스트에서 검증하기 어렵다 |

**결론:** P1 중 1차 Low-fi 핵심 시나리오에 반드시 포함해야 하는 기능은 없다. 여력이 있다면 핵심 테스트와 분리해 `Home 장면 촬영 → 저장 완료 → 앨범 확인`만 두 번째 시나리오로 검증한다.

## 8.3 1차에서 의도적으로 제외할 것

- 전체 상점·재화·결제 Flow
- 전체 앨범 관리와 알림 설정
- 함께한 날과 오브젝트 해금
- 다양한 장식 카탈로그와 정교한 꾸미기
- 최종 종별 대표 행동 전체
- 최종 navigation pattern과 Home 메뉴 위치
- 시각 디자인 시스템과 High-fi 표현
- AI 생성 기술 설명과 실제 구현 상세

# 9. 현재 Flow에서 유지할 것

1. **별도 서비스 소개 화면 없음:** 첫 화면에서 바로 인증 방법을 선택한다.
2. **확정된 세 로그인 경로:** 일반, Kakao, Google.
3. **강아지·고양이 지원과 이름·성별 입력:** 화면 수는 재검토하되 정보 범위는 현재 P0를 유지한다.
4. **사진 최소 한 장과 추가 사진 선택:** 금지된 `사진 1장만으로도 시작할 수 있어요` 카피는 사용하지 않고 성공 시 `업로드 완료`처럼 짧게 피드백한다.
5. **생활 문답 여섯 개:** 쓰다듬기 선호, 활동량, 식사, 짖음/울음, 배변, 수면을 유지한다.
6. **문답 한 번에 한 질문:** 여러 항목을 빽빽하게 묶지 않는다. 다만 하나의 연속된 문답 단계라는 맥락을 강화한다.
7. **AI 후보 2~3개와 간단 보정:** 하나의 결과를 강요하지 않고 사용자가 선택·수정한다.
8. **실제 공간 사진 한 장과 직접 이동 영역 지정:** 공간 분류나 여러 공간을 임의로 추가하지 않는다.
9. **첫 만남 5~10초와 확정 문구:** `{이름}가 우리 집으로 찾아왔어요.`를 시스템 문구로 유지한다.
10. **완료 페이지 없이 Home 연결:** 첫 만남과 생활을 끊지 않는다.
11. **Home의 실제 공간·캐릭터 중심 구조와 최소 UI:** 숫자 상태판·복잡한 HUD를 추가하지 않는다.
12. **캐릭터·밥그릇·장난감·배변 흔적 직접 터치:** 메뉴를 거치는 간접 조작으로 바꾸지 않는다.
13. **캐릭터 확대와 직접 문지르기:** 선호 부위의 하트·긍정 반응을 유지한다.
14. **비선호 부위의 실패·부정 패널티 없음:** 반응 차이는 중립적 수용과 긍정 강도의 차이로 만든다.
15. **경과시간 기반 오프라인 생활과 활동 보고서 없음:** 현재 장면의 행동·흔적으로 연속성을 전달한다.
16. **미접속·급식·청소의 해로운 패널티 없음:** 질병·죽음·죄책감·연속 출석 압박을 만들지 않는다.
17. **기본 교감과 기본 생활 오브젝트 무료:** 상점이 핵심 경험을 막지 않는다.

# 10. 합칠 것

## 10.1 하나의 화면 또는 상태로 합치기 추천

- **종 + 이름 + 성별 → 반려동물 기본 정보:** 같은 사용자 목표에 속하고 개별 화면의 정보량이 적다.
- **필수 사진 + 추가 사진 + 선택적 동영상 → 자료 준비:** 동영상을 유지할 경우에도 별도 필수 관문으로 만들지 않는다.
- **여섯 질문 화면 → 하나의 문답 단계:** 화면에는 한 질문만 두되 진행 맥락·이전·다음을 공유한다.
- **후보 선택 + 보정 진입 + 직접 확정 → 후보 단계:** 후보를 고른 곳에서 바로 확정하거나 선택적으로 보정에 들어간다.
- **보정 완료 + 최종 외형 확정 → 한 번의 보정 확정:** 저장 확인을 두 번 요구하지 않는다.
- **첫 만남 + Home 진입:** 같은 공간과 캐릭터가 중간 완료 페이지 없이 생활로 이어진다.
- **캐릭터 탭 + 캐릭터 확대:** 하나의 원자적 직접 상호작용으로 연결한다.
- **쓰다듬기 종료 + 기본 시점 복귀:** 별도 제출 없이 하나의 종료 Flow로 처리한다.
- **기본 오브젝트 배치 + 초기 꾸미기:** 첫 만남 뒤 Home 맥락에서 같은 배치 규칙을 학습한다.
- **상점 + 꾸미기 맥락:** 상점은 독립 Home 주 행동보다 필요한 오브젝트를 찾는 과정에 연결하는 안을 추천한다.
- **추억 사진 + 앨범:** `촬영 → 저장 → 다시 보기`라는 하나의 후속 P1 검증 시나리오로 묶는다.
- **첫 사용자 튜토리얼 + 실제 Home 상황:** 별도 투어 대신 첫 캐릭터·첫 쓰다듬기·첫 생활 흔적 순간에 각각 한 번 안내한다.

## 10.2 합치지 말아야 할 것

- 여섯 질문을 한 화면에 모두 배치하지 않는다.
- 후보 비교와 세부 보정 편집을 동시에 전부 노출하지 않는다.
- 공간 사진 선택과 Brush 편집을 같은 조작 상태로 섞지 않는다.
- Home 일반 상태와 오브젝트 배치 상태에서 같은 탭·드래그가 모호하게 두 의미를 갖지 않게 한다.
- 상태 말풍선 탭을 밥·놀이의 간접 CTA로 합치지 않는다.

# 11. 제거할 것

아래는 기능 자체를 제품 범위에서 삭제한다는 확정이 아니라, **추천 Flow 또는 Low-fi 1차의 필수 경로에서 제거할 항목**이다.

1. 별도의 `추가 사진이 있나요?` 확인 화면
2. 선택적 동영상만을 위한 독립 필수 단계와, 그 화면이 사라질 때의 별도 `건너뛰기`
3. 종·이름·성별 각각의 독립 화면
4. 모든 질문을 마친 뒤 답을 다시 제출하는 별도 검토·완료 화면
5. 사진 수정·정보 수정·새 후보 생성을 구분하지 않는 모호한 전체 초기화형 `다시 만들기`
6. `보정 완료 → 후보 화면 → 후보 재확정`의 이중 확정
7. 첫 만남 전 밥그릇·잠자리·장난감 **전부**의 의무적 수동 배치
8. 첫 만남 뒤 별도 완료 페이지
9. 첫 Home에서 모든 기능을 설명하는 전체 투어
10. 쓰다듬기 `완료` 버튼, 점수, 친밀도 수치, 콤보 같은 불필요한 제출·게임화
11. 상태 말풍선을 행동 메뉴로 사용하는 간접 조작
12. Low-fi 1차 핵심 시나리오의 상점·재화·함께한 날·알림·전체 앨범
13. 재방문 진입의 활동 보고서·놓친 보상·미접속 시간 요약

# 12. 순서를 바꿀 것

## 12.1 현재 대비 추천 변경

| 현재 순서 | 추천 순서 | 이유 |
|---|---|---|
| 종 선택 → 이름/성별 | 종·이름·성별 한 단계 | 같은 목표의 화면 전환 감소 |
| 사진 → 추가 사진 분기 → 동영상 분기 | 사진 단계 안에서 추가 자료 관리 | 선택 자료가 필수처럼 느껴지는 문제 감소 |
| 문답 완료 → AI 생성 시작 | 유효 사진 뒤 생성 시작 → 문답 중 처리 `조건부` | 체감 대기 감소. 기술 가능성 확인 필요 |
| 후보 확정 → 별도 보정 판단 | 후보 선택 단계에서 확정 또는 보정 진입 | 선택·수정 관계를 명확하게 함 |
| 이동 영역 → 기본 오브젝트 배치 → 첫 만남 | 이동 영역 → 첫 만남 → Home 첫 교감 → 기본 오브젝트 배치 | 감정적 보상을 앞당기고 설정 피로를 생활 준비 맥락으로 전환 |
| 첫 사용자 튜토리얼을 한 번에 제공할 가능성 | 캐릭터 → 쓰다듬기 → 실제 생활 오브젝트 순으로 상황별 안내 | Home 몰입과 기억 가능성 개선 |
| Home에서 P1 기능을 함께 소개 | 핵심 교감 후 사용자가 필요할 때 발견 | 첫 경험의 초점 유지 |

## 12.2 추천 최종 순서

`앱 실행·세션 확인 → 로그인 → 반려동물 기본 정보 → 사진 준비 → 생성 처리 시작(가능한 경우) → 생활 문답 1~6 → 생성 완료 확인 → 후보 선택 → 필요 시 보정 → 외형 확정 → 공간 사진 → 이동 영역 편집·미리보기 → 첫 만남 → Home 첫 관찰 → 캐릭터 확대·쓰다듬기 → 기본 오브젝트 배치·조정 → 상황별 밥·놀이·배변 발견`

# 13. 아직 사용자 결정이 필요한 것

## 13.1 로그인과 계정

- 일반 로그인 상세 인증 방식
- `로그인하기`가 신규 일반 가입도 포함하는지
- 일반·Kakao·Google 사이 중복 계정 연결·병합 정책
- 인증 뒤 중단 등록을 어느 저장 지점에서 재개할지

## 13.2 기본 정보와 문답

- 성별 선택지, 필수 여부, 외형·호칭·행동에 실제로 미치는 영향
- 이름 허용 문자·최대 길이
- 쓰다듬기 선호 부위 단일 선택 또는 복수 선택
- 여섯 문답을 모두 필수로 할지, `잘 모르겠어요` 같은 중립 선택을 허용할지
- 종 변경 시 짖음/울음 외 어떤 입력을 다시 확인할지

## 13.3 사진·동영상

- 사진·동영상의 허용 개수, 형식, 용량, 동영상 길이
- 기기 촬영을 함께 제공할지
- 중복 파일 처리와 사진 품질 기준
- 선택적 동영상을 신규 Flow에 노출할지, 추후 자료 보강으로 옮길지
- 사진 검증 직후 외형 생성을 시작할 수 있는지

## 13.4 생성·후보·보정

- 생성 처리 중 앱 이탈·취소·완료 통지 방식
- 후보 세부 확대가 필요한지
- `다시 만들기`의 횟수·대기·비용 정책과 직전 후보 보존 범위
- 기술 실패가 재생성 제한에 포함되는지
- 보정값의 실제 선택 범위와 미리보기 처리 방식
- 확정 뒤 외형·문답을 수정할 때 재생성이 필요한 범위

## 13.5 공간과 이동 영역

- 공간 사진 촬영 지원과 권장 조건
- Brush와 사진 확대·이동의 정확한 제스처 규칙
- Brush 크기 변경 필요 여부
- 실행 취소·다시 실행을 확정 Element로 넣을지
- 최소 이동 면적, 분리 영역 허용, 연결성, 원근·가림 처리
- 실제 캐릭터 미리보기와 대체 경로 표시 중 가능한 방식
- Home 이후 공간 사진·이동 영역 수정 진입점

## 13.6 기본 오브젝트와 첫 만남

- 첫 만남에 기본 오브젝트가 기술적으로 필요한지
- 첫 만남 전 임시 자동 배치를 사용할지
- 첫 만남 뒤 배치를 필수로 할지, 나중에 하기를 허용할지
- 밥그릇·잠자리·장난감의 고정 배치 순서 또는 자유 순서
- 미배치 상태에서 관련 자율 행동을 어떻게 중립적으로 처리할지
- 오브젝트 유효 위치·겹침·접근 가능 판정 규칙
- 첫 만남 건너뛰기·가속·중단 후 재개·다시보기 정책

## 13.7 Home

- 캐릭터가 다른 행동 중일 때 탭하면 즉시 확대할지 짧은 행동 뒤 확대할지
- 확대 종료를 명시적 종료·배경 탭·시스템 뒤로가기 모두 지원할지
- 상태 말풍선을 완전한 읽기 요소로 둘지 탭으로 닫을 수 있게 할지
- 비선호 부위에서 선호 부위 쪽으로 자세를 돌리는 중립 행동을 사용할지
- 두 번째 방문에서 오프라인 생활 원리를 한 번 안내할지
- 최종 navigation pattern과 꾸미기·앨범·상점의 진입 관계
- 온보딩 사진·영상을 앨범에 자동 포함할지
- 추억 사진의 앱 내부 저장·기기 저장 기본 정책
- 알림 옵트인 시점과 빈도

## 13.8 Low-fi 범위

- P1을 모두 제외한 추천 1차 범위를 승인할지
- 선택적 동영상의 존재만 비교안으로 포함할지
- 후속 P1 검증에서 추억 사진·앨범을 가장 먼저 다룰지
- 첫 만남 전 배치안과 첫 만남 후 배치안을 비교 테스트할지, 추천안 하나만 먼저 검증할지

# 14. Codex가 추천하는 최종 UX 구조와 그 이유

## 14.1 최종 추천 구조

### A. 빠른 진입

`앱 실행 → 로그인 → 종·이름·성별 통합 입력`

- 확정된 로그인 구조를 유지한다.
- 세 개의 짧고 연관된 기본 정보를 하나의 목표로 묶는다.

### B. 외형 자료와 생활 기억을 겹쳐 처리

`사진 준비 → 가능한 경우 생성 처리 시작 → 한 질문씩 6개 문답`

- 추가 사진과 동영상은 사진 단계 안의 선택 자료로 둔다.
- 문답은 여러 항목을 한 화면에 묶지 않고 하나의 6단계 흐름으로 유지한다.
- 기술적으로 가능하면 AI 처리와 문답을 병렬화한다.

### C. 결과 불만족을 안전하게 복구

`후보 2~3개 → 후보 선택 → 바로 확정 또는 간단 보정`

- `다시 만들기`는 같은 입력으로 새 후보를 만드는 의미로 한정한다.
- 작은 차이는 보정, 자료 부족은 사진 수정, 잘못된 정보는 해당 입력 수정으로 분리한다.
- 새 생성이 성공하기 전 기존 후보를 보존한다.

### D. 실제 공간의 최소 필수 설정

`공간 사진 → 이동 영역 Brush·지우기·실행 취소·미리보기 → 완료`

- 이동 영역은 제품의 핵심이므로 유지한다.
- 최초 한 번의 과업 안내와 강한 복구성을 제공한다.
- 정밀 모델링보다 충분한 근사 영역으로 성공하게 한다.

### E. 감정적 보상을 먼저 제공

`첫 만남 → Home → 캐릭터 탭 → 확대 → 첫 쓰다듬기`

- 수동 오브젝트 배치를 첫 만남 뒤로 옮긴다.
- 첫 만남과 Home 사이에 완료 페이지·전체 튜토리얼을 넣지 않는다.
- 선호 쓰다듬기 반응으로 문답의 개인화 가치를 즉시 확인한다.

### F. 생활 기능은 상황 속에서 발견

`첫 교감 → 기본 오브젝트 배치·조정 → 밥·놀이·배변의 상황별 발견 → 자율 생활`

- 한 번에 기능 하나만 알려 준다.
- Home에서 밥그릇·장난감·배변 흔적을 직접 누르는 원칙을 유지한다.
- P1 기능은 첫 핵심 교감과 분리한다.

## 14.2 이 구조를 추천하는 이유

1. **첫 만남까지의 필수 관문을 줄인다.** 기본 정보 통합, 독립 동영상 단계 제거, 수동 오브젝트 배치 후 이동으로 화면 전환과 선행 과제가 줄어든다.
2. **필요한 개인화는 버리지 않는다.** 여섯 문답과 이동 영역, 후보 선택·보정을 그대로 유지한다.
3. **체감 대기를 줄일 가능성이 있다.** 생성과 문답을 병렬 처리할 수 있다면 입력 뒤의 빈 대기를 숨길 수 있다.
4. **가장 큰 실패를 복구 가능하게 만든다.** 후보 불만족이 전체 재시작이 아니라 보정·재생성·사진 수정·정보 수정으로 나뉜다.
5. **감정 흐름을 보호한다.** 캐릭터와 공간이 준비된 뒤 기술적 배치 과제로 기대를 끊지 않고 먼저 만나게 한다.
6. **Home 몰입과 발견성을 함께 지킨다.** 항상 떠 있는 다수 버튼 대신 첫 행동과 실제 상황에 맞춘 한 번성 안내를 사용한다.
7. **StayPet의 제품 철학과 일치한다.** 관리 의무·죄책감·상태 점수보다 자율 생활 관찰과 직접 교감을 중심에 둔다.
8. **P0 검증을 선명하게 만든다.** 상점·함께한 날·알림 등 P1을 분리해 첫 테스트가 생성 완료, 유사도, 공간 생활, 직접 교감에 집중한다.

## 14.3 추천 강도

- **우선 채택을 추천:** 종·이름·성별 통합, 독립 추가 사진·동영상 화면 제거, 한 질문씩 6단계 문답, 후보 불만족 복구 분리, 첫 만남 전 수동 오브젝트 배치 제거, Home 상황별 튜토리얼.
- **기술 확인 후 채택 추천:** 사진 뒤 백그라운드 생성 시작, 실제 캐릭터 이동 미리보기, 첫 만남 전 임시 오브젝트 자동 배치.
- **사용자 결정 전 보류:** 성별의 필수성, 쓰다듬기 복수 선택, 재생성 제한·비용, 첫 만남 건너뛰기·재생, Home navigation, P1 첫 검증 범위.

이 제안의 핵심은 단순히 화면 수를 줄이는 것이 아니다. **사용자가 사진과 기억을 건넨 뒤 가능한 한 빨리 자신의 공간에서 캐릭터를 만나고, 그 직후 첫 쓰다듬기로 개인화를 확인하게 하는 것**이다. 나머지 생활 설정은 그 감정적 보상을 막지 않는 순서로 배치한다.
