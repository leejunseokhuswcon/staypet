# StayPet Low-fi Wireframe Spec v2

- 갱신일: 2026-08-17
- Source of truth: `docs/UX_FINAL.md` (보조: `docs/USER_FLOW.md` v1.2)
- 산출물: `lowfi/index.html`, `lowfi/styles.css`
- 단계: **Low-fi 1차 — 구조·흐름·상태 검증.** 시각 디자인·브랜딩·컬러는 이 단계의 대상이 아니다.

## v2에서 바뀐 것

v1은 45개 정적 프레임을 나열한 스토리보드였다. 검수 결과 **핵심 검증 대상이 정적 설명이나 잘못된 대체 조작으로 표현**돼 있어, 그대로 테스트하면 확정 UX가 아니라 "프레임 설명을 이해하는지"를 검증하게 된다는 문제가 확인됐다. v2는 **실제로 조작되는 단일 프로토타입 + 진행자 패널** 구조로 재작성했다.

| 문제 (v1) | 해결 (v2) |
|---|---|
| 쓰다듬기를 부위 버튼 4개로 표현 | **확대된 캐릭터를 직접 문지른다.** 부위는 보이지 않는 판정 영역 |
| Critical Path가 CTA 비활성으로 끊김 | 종·이름 입력, Q1 선택, 후보 선택이 **실제로 CTA를 활성화** |
| 검수 주석이 폰 화면 안에 노출 | **참가자 모드가 기본.** 주석·가설·진행자 도구 전부 숨김 |
| 상태를 바꾸지 않는 CTA 4개 | 전부 제거하거나 실제 동작으로 대체 |
| 이동 영역 유효성 검사 없음 | 최소 면적 미달 시 **완료 차단 + 인라인 복구** |
| 도달 예시가 숫자(`N칸`) | 선택 타일 안에 **발자국 표시** |
| Home 이후가 전부 정적 | Home이 **라이브 화면**. 탭·확대·문지르기·힌트·제안·배치·급식·청소가 실제 동작 |
| 보정이 정적 | 값 변경·전후 비교·undo·원본 복원·확정·실패 복구 실제 동작 |
| 후보 불만족 경로가 정적 | 다시 준비하기·그만 보기·재진입 실제 동작 |

**프레임 수를 목표로 삼지 않았다.** 상태가 실제 interaction 안에서 자연스럽게 표현될 수 있을 때만 합쳤고, 검증에 필요한 상태는 하나도 제거하지 않았다. v1의 45개 프레임에 있던 상태는 전부 v2에서 도달 가능하다(§4 대응표).

# 1. 참가자 모드 / 진행자 모드

**기본 상태는 참가자 모드다.** 파일을 열면 폰 화면만 보인다.

참가자 모드에서 **보이지 않는 것**: 검수 주석 · 검증 가설 · 프레임 설명 · 화면 ID · 시나리오 탐색 도구 · 진행자용 상황 발생 버튼 · 임시 파라미터 메모.

**진행자 모드 전환**: 키보드 `D` 또는 좌상단 모서리 3회 클릭. 화면에 버튼을 두지 않았다.

> 시나리오 필터와 화면 점프는 **테스트 진행자용 도구**이며 StayPet UI가 아니다. 참가자 화면에는 존재하지 않는다.

진행자 패널 구성 — 시나리오 5종 / 화면 직접 이동 / Home 상황 발생 / 기타 조작 / 현재 화면 메모와 가설 / 임시 파라미터 고지.

# 2. 실제로 조작 가능한 범위

## 2.1 주 경로 — 전 구간 실제 조작으로 연결

| 단계 | 실제 동작 |
|---|---|
| 로그인 | 3종 버튼 → 기본 정보 |
| 기본 정보 | 종·이름·성별 **셋 다 있어야 CTA 활성화**. 종은 미선택 상태로 시작 |
| 사진 자료 | 사진 추가 → 업로드 완료 + 적합성 결과 → **CTA 활성화** |
| 문답 Q1 | 부위 **복수 선택**(재탭 해제) → 확인 활성화. 선택값이 이후 하트 판정에 실제로 쓰인다 |
| 생성 대기 | 상단 ←로 **나갈 수 있고**, 돌아오면 상태 복원. 성공 전환은 **진행자 이벤트**로만 발생하며 참가자 화면에는 CTA가 없다 |
| 후보 | 카드 선택 → 확정·보정 활성화(**후보 선택 전에는 보정 진입 불가**) / 원본 보기 토글 / **다시 준비하기 · 그만 보기 · 재진입** |
| 보정 | 값 변경 · **전후 비교** · undo · 원본 복원 · 실패한 변경만 복구 |
| 공간 사진 | 빈 상태 → 선택 → 완료 → CTA 활성화 |
| 이동 영역 | 타일 탭 · 쓸기 · **재탭 제외** · 실행 취소 · 초기화 · **유효성 미달 시 완료 차단과 인라인 복구** |
| 첫 만남 | **자동 진행**(약 5초), 확정 문구 후 Home으로 연속. CTA 없음 |
| Home | 캐릭터 탭 → 확대 → **직접 문지르기** → 선호/비선호 반응 → 명시적 닫기 |

## 2.2 Home 라이브 상호작용

Home은 하나의 살아 있는 화면이다. 진행자가 생활 상황을 발생시키고, 참가자가 실제로 조작한다.

| 동작 | 구현 |
|---|---|
| 캐릭터 탭 → 확대 | 실제 |
| 쓰다듬기 | **clientX/clientY 좌표 변화 누적으로 탭/문지르기 판정**(`movementX/Y`는 합성·터치 입력에서 0이라 쓰지 않는다). 부위는 보이지 않는 판정 영역(머리·등·배·엉덩이) |
| 2계층 | 탭·반복 탭·이동 없는 길게 누르기 = 짧은 접촉(하트 없음) / **실제 문지르기(드래그)만 = 본 쓰다듬기** `사용자 결정 2026-08-18` |
| 부위 귀속 | **제스처가 처음 닿은 유효 부위로 고정**한다. 머리에서 시작해 등으로 흘러도 머리다. 부위 밖에서 시작하면 처음 진입한 부위로 고정하며, 한 번 정해지면 그 제스처 안에서 바뀌지 않는다 `2026-08-18` |
| 선호 부위 | **Q1에서 실제로 고른 부위에만** 하트. 참가자마다 달라진다 |
| 비선호 부위 | 중립 수용 반응, 실패·거부 없음 |
| 확대 종료 | 좌상단 명시적 닫기 하나(중복 제거) |
| 빈 영역 탭 | 세계를 바꾸지 않음. **유효 상호작용을 한 번도 못 한 상태에서 연속 2회**면 힌트 1회. 유효 탭 시 카운트 초기화. 무입력 시간은 트리거로 쓰지 않음 |
| 말풍선 | 비상호작용(`pointer-events:none`), 자동 소멸, 터치가 캐릭터로 통과 |
| 밥그릇 | 제안 → **위치 지정(탭)** → 잘못된 위치는 사유와 함께 거부 → 배치 → **탭하면 캐릭터가 반드시 인지** |
| 배변 | 흔적 등장 → 탭 → **청소 정상 완료** → 그 뒤에 Q5 제안 |
| 상황형 질문 | 제안 → 응답 → **행동 변화**(Q2 응답이 캐릭터 위치·활동에 반영) |

## 2.3 정적으로 남긴 것

해당 가설을 이번 시나리오에 넣을 때만 실제 동작시키면 되는 것들이다.
로그인 실패 · 사진 적합성 문제 · 사진 업로드 실패 · 생성 실패 복귀 · 첫 만남 중단 재개 · 기본 정보 수정 영향 · 잠자리/장난감 배치(밥그릇과 동일 메커니즘).

# 5. 테스트 시나리오

**45개를 순차 통과시키지 않는다.** 진행자 패널에서 시나리오를 선택한다.

## 5.1 주 경로 (필수)
`로그인 → 기본 정보 → 사진·적합성 → Q1 → 생성 시작 → (선택) 대기 이탈·복귀 → 후보 선택·확정 → (선택) 보정 → 공간 사진 → 이동 영역·완료 → 첫 만남 자동 → Home → 캐릭터 탭 → 직접 쓰다듬기 → 하트 → 아무 요구 없이 Home 관찰`

**첫 하트 이후 진행자는 개입하지 않고 멈춘다.** 참가자가 자발적으로 무엇을 하는지 관찰하는 구간이다.

## 5.2 점진적 개인화 (별도 세션)
관련 상황 발생 → 제안 → 선택적 응답 → **실제 행동 변화**. 미응답 상태로 두고 다른 상호작용이 가능한지 확인.

## 5.3 오브젝트 배치 (별도 세션)
정상 생활 → 맥락형 제안 → 위치 지정 → 잘못된 위치 복구 → 배치 → 사용.

## 5.4 복구 · 예외
로그인 실패 / 사진 부적합 / 업로드 실패 / 생성 실패 / 후보 불만족 / 이동 영역 미달 / 첫 만남 중단 / 기본 정보 수정 영향.

## 5.5 발견성
Home에서 헤매는 상황 → 무효 탭 2회 → 힌트 발생. 유효 탭 후 카운트 초기화 확인.

> **개인화와 오브젝트 배치를 한 세션에 연속으로 강제하지 않는다.** 그러면 "한 세션 새 제안 1개"와 "첫 교감 직후 비요구" 원칙을 검증할 수 없다.

### 시나리오 시작 시 상태 초기화

진행자가 시나리오 버튼을 누르면 **참가자 상태를 전부 지운 뒤 그 시나리오의 시작 조건만 세운다.** 이전 시나리오의 잔여 상태가 다음 결과를 오염시키지 않게 하기 위함이다.

- 초기화 범위: 종·이름·성별 · 사진/동영상/복구 화면 상태 · Q1 선택 · Q2~Q6 답변 · 미응답 질문 · 후보 선택과 숨김/재진입 · 보정 값과 이력 · 생성 상태 · Home 위치와 활동량 · 오브젝트와 배변 흔적 · 힌트와 유효/무효 탭 기록 · 확대 안내 노출 여부 · 말풍선과 임시 피드백 · **예약된 지연 콜백과 타이머**
- 시작 조건(fixture): `주 경로`·`복구`는 아무것도 미리 세우지 않는다. `개인화`·`오브젝트`·`발견성`은 Home에서 시작하므로 **등록 완료 상태**(종·이름·성별, Q1=머리·배)만 세운 뒤 시작한다
- 지연 콜백은 등록기를 거치므로, 청소 후 Q5 제안처럼 예약된 동작도 시나리오를 바꾸면 실행되지 않는다

# 6. 검증 가설

| ID | 가설 | 관찰 지표 |
|---|---|---|
| H0 | 소개 화면 없이 바로 인증해도 이탈하지 않는다 | 로그인 선택까지의 망설임, 실패 후 재시도 |
| H1 | Q1만 선행하는 경로가 이해되고 완주된다 | 첫 만남까지 완주율, 단계별 멈춤 |
| H2 | Q2~Q6이 없어도 등록이 끝났다고 이해한다 | "질문이 더 있나요?" 발화 |
| H3 | 사진 적합성을 업로드 직후 알리면 늦은 실패를 막는다 | 문제를 인지한 단계 |
| H4 | 후보 불만족 시 원인 진단 없이 진행할 수 있다 | 첫 클릭 대상, 경로 차이 이해, **재진입 시 강제 노출을 불편해하지 않는가** |
| H5 | 타일 토글이 첫 시도에 성공한다 | 첫 시도 성공률, 완료 시간, 수정 횟수 |

| H14 | **첫 하트 뒤 과제 없는 시간을 편안해한다** | 불안·"이제 뭘 하죠" 발화 |
| H15 | 상황형 제안이 누적 부담이 되지 않는다 | 방해로 인식하는 시점, **질문이 계속 떠 있는 것을 불편해하는가**, `건너뛰기`를 찾는가 |

| **H22** | **미응답 질문이 화면에 남아 있어도 관찰을 방해하지 않는다** | 질문이 떠 있는 채로 캐릭터를 만지는가, 답해야 한다는 압박을 느끼는가 |
